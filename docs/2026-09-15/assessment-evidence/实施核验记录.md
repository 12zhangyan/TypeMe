## 2. 先复现：改动前的缺陷

1. **全中立仍展示默认类型（用户反馈的核心）**：改动前 ResultView 用 `scoreQuestionnaire().typeCode` 取类型文案，`allBalanced` 只改提示不改正文；`shareImage` 用同一个 `typeCode` 画封面大字与文件名。全选 3 → 页面仍加载 ISFJ 的日常表现、优势与建议，分享图封面仍是大字 ISFJ。
2. **看不懂时没有合法出口**：只有五个数值档，「无法判断」不存在。
3. 本轮实施过程中**新发现并修复**的三个缺陷（都由测试先红后修）：
   - 「暂时无法判断」的原因下拉整体错位一位（选「两边都不适用」会存成 `unsure`）。根因是 `<option :value="index + 1">` 与 `UNKNOWN_REASONS[value]` 的 0 基下标不一致。
   - 越界作答（`{kind:'rating', value:9}`）被算成「已处理」，结果页判为 `incomplete` 并 `replace('/quiz')`，在结果页与答题页之间来回弹。修法：新增 `isCorruptResponse` 与 `corruptResponseIds`，结果页按**结构性错误**原地渲染错误态，答题页如实提示并允许重新选择修复（CR-1 口径）。
   - 分享图「结论提示」在两行高度内被省略号截断，「请结合两侧描述理解」这句被吃掉。改短四维全未定时的文案，并加回归断言（画出的提示正文不得含 `…`）。

### 4.1 打包产物的处理（如实记录，含一次人工恢复）

`mvn package` 在 Windows 上失败于「重命名被运行中的进程占用」。失败时 `jar:jar` 已经**覆盖写入**了那个 jar，于是 `target/typeme-backend-1.0.0.jar` 一度变成**没有依赖的普通 jar**（`java -jar` 起不来）。处理方式：

1. 不去停用户正在运行的 8080 进程（工程约定：不为方案工作停止未知进程）。
2. 临时给 `spring-boot-maven-plugin` 加 `<classifier>verify</classifier>`（`classifier` 参数没有 CLI 属性，`-Dspring-boot.repackage.classifier` 无效），让 repackage 写出 `typeme-backend-1.0.0-verify.jar` 而**不需要重命名**被占用的文件。
3. 把该 fat jar **复制**回标准文件名（实测：该文件对写入放行、对重命名不放行），删掉临时产物，并把 `pom.xml` 恢复原样（已核对：`pom.xml` 里不再出现 `classifier`，行数回到 95）。
4. 顺手清掉了 `target/classes/static/assets` 里**历史遗留的过期 bundle**（`copy-resources` 只覆盖不删除，之前每次打包都会累积；这是既有行为，不是本轮引入），最终 jar 里只剩当前这一份 `index-B1D5dVYq.js` + `index-BWB_iCBa.css`。
5. 用户随后要求杀掉并重启 8080/5173，重启后 jar 不再被占用；`mvn package` 已恢复正常（见 §5.1）。

### 5.1 标准地址的重启与复验（按用户要求）

用户要求把原有 8080/5173 进程杀掉重启。记录如下：

| 重启后端 | `D:\develop\jdk-21\bin\java.exe -jar target\run\typeme-backend-1.0.0.jar --server.address=127.0.0.1 --server.port=8080`（工作目录 `backend/`） |

**为什么后端改从 `target/run/` 的副本启动（一处刻意的偏离，请知悉）**：`java -jar target\typeme-backend-1.0.0.jar` 会一直占用该文件，于是

1. `mvn package` 会在 `repackage` 阶段失败（无法把 jar 重命名为 `.original`）；
2. 更糟的是，`jar:jar` 会**先把正在运行的 jar 覆盖成普通 jar**，运行中的服务随后就因为读不到 `BOOT-INF` 而崩掉——本次实际发生了两次（一次是用户原进程，一次是我重启后的进程）。

因此最终让 8080 从 `backend/target/run/typeme-backend-1.0.0.jar`（标准 jar 的副本）启动：URL、行为、接口完全一致，但 `mvn package` 不再互相破坏。刷新副本的命令：

```powershell
cd D:\develop\develop\code\TypeMe\backend
mvn.cmd package -DskipTests
Copy-Item target\typeme-backend-1.0.0.jar target\run\typeme-backend-1.0.0.jar -Force
# 然后重启 8080 服务
```

若更希望保持原来的单文件布局（`java -jar target\typeme-backend-1.0.0.jar`），那么打包前必须先停掉 8080 服务。

**恢复后的最终状态**（已验证）：`mvn package -DskipTests` 退出码 0，产出标准的一对文件 `typeme-backend-1.0.0.jar`（24.4 MB，可执行 fat jar）+ `typeme-backend-1.0.0.jar.original`（212 KB，普通 jar）；打包期间与打包之后，运行中的 5173 / 8080 均未受影响（v2 接口仍 200）。`pom.xml` 已确认还原（不再出现 `classifier`）。

### 7.2 本轮**发现并修掉**的真实缺陷（都属于「换成五维之后才暴露」的一类）

1. **本轮自己引入的回归：接口路径静默降级（最严重）**。为了让大五的单句贴切度格式能过契约，
   `domain/questionnaire.ts` 新增了 `format` / `responseAnchors` / `dimensionOrder` 三个可选字段的检查，
   写成了 `!== undefined`；而服务端（Jackson 默认 `Include.ALWAYS`）会把 YAML 里缺省的字段
   序列化成**显式 `null`**。于是 `responseAnchors: null`（OEJTS）/ `dimensionOrder: null`（两类包）
   被判成「声明了非法值」，**整包校验失败 → 页面静默用内置副本**：
   接口返回 200，服务端内容却一次都没被用上。这是本轮新增代码造成的，并被本轮浏览器验收
   （`packageSource` 断言）当场抓到。修法：可选字段一律 `!= null`（等价于「没这个字段」），
   并在 `domain/questionnaire.ts` 顶部写明原因。
   回归：`domain/assessmentPackage.spec.ts` 新增「接口形态（显式 null）与内置形态判定一致」，
   `stores/quiz.spec.ts` 新增「接口 200 + 显式 null → `packageSource === 'api'`」（含「返回别的包 ID 仍降级」）。
   验收：两个验收脚本改为**从 store 读 `packageSource`**，不再靠人工写标签；关于页的「服务端接口 / 服务端不可用」文案与实际路径一致性也被断言。
2. **导出图与结果页的两端记号是 OEJTS 专用的常量**：`utils/shareImage.ts`、`components/DimensionBar.vue`、
   `views/ResultView.vue` 直接查 `NEGATIVE_POLE` / `POSITIVE_POLE`（只有 EI/SN/TF/JP）。
   大五的 E/A/C/ES/O 查不到 → **导出图上被画成字面量 `undefined`**（页面里是空白，
   因为 Vue 把 `undefined` 渲染成空串，所以这个缺陷只有导出图会暴露成可见文字）。
   修法：一律改用报告行模型的 `lowToken` / `highToken`（内容包按量表给：字母 / 低高）。
   回归：`shareImage.spec.ts`「两侧记号画的是内容包的『低/高』，画布上不会出现字面量 undefined」、
   `views.spec.ts`「结果页两端记号是内容包的『低/高』」。
3. **写死的「四个维度」**：结果页标题、目录项、「继续认识自己」的提示、方法说明两条折叠项、
   分享图提示语、`shareImage` 的 clear 提示，全部按当前包写死四维。
   修法：新增 `utils/cnNumber.ts`（`chineseNumeral` / `dimensionCountPhrase`），
   首页与结果页共用；`ReportDimensionRow` 增加 `canJoinType`，让只拿到一行的组件也能说对
   「不写进完整类型 / 完整结论」。
4. **`clear` 的整体抬头自相矛盾**：五维都有方向时抬头写「本次偏好概览（没有明确方向）」，与标题
   「五个维度本次都有较明确的方向」直接打架。修法：`clear` 单独一支，写「（每个维度都有方向）」。
5. **自我观察在大五下无法使用**：`saveSelfReflection` 用 OEJTS 的 `DIMENSION_ORDER` 做门槛，
   大五维度被静默拒绝；`readSelfReflection` 只认 `EISNTFJP` 单字母且只遍历四维，
   于是**刷新后整片丢失**。修法：两者都以「本地快照里的内容包」为准（维度 = 包声明的顺序，
   记号 = 该维的 `low/high`）。回归：`quiz.spec.ts` 4 条（含「不是当前内容包的维度会被忽略」）。
6. **导出图页脚长署名被左右同时裁掉**：署名三行是硬画三行、不换行。
   OEJTS 的署名短，公有领域的 IPIP 署名长（`International Personality Item Pool (IPIP) — Goldberg's
   Big-Five Factor Markers`），导出图上真的出现了 `ational … Lewis R. Go` 这种断头文字。
   修法：页脚逐条按宽度换行，整体限制在 5 行内收尾，行距 32px。
   回归：`shareImage.spec.ts` 新增「拼回去等于源文本」「每一段都不超过画布可用宽度」两条
   （假 canvas 同时加了中英混排度量，避免等宽度量把小字号长行误判成放不下）。
7. **大五报告挂着 MBTI 免责声明**：结果页页脚无条件写「这不是 MBTI 官方测评，与 The Myers & Briggs
   Foundation 无任何关联」。修法：与首页一致，按 `hasTypeCode` 分档（大五不显示）。
8. **首页教学例子残留 OEJTS 说法**：默认入口是大五，首页却还在讲「两边都读完：左边是 1，右边是 5」。
   修法：`TEACHING_EXAMPLE` / `faqs` / `VALUES` 改为按作答格式生成（IPIP 讲「每题是一句自我描述：
   1 表示非常不贴切，5 表示非常贴切」）。回归：`instrumentCopy.spec.ts` 的格式对照用例。

> 说明：仓库**不在版本控制下**（没有 `.git`），所以个别缺陷的引入时间无法用 `git log` 佐证
> （第 1 条是本轮新增代码引入的，上文已写明）；其余各条都是「默认量表 = 五维大五」这条路径上
> 必然发生的写死假设，现在都有断言与截图证据。
