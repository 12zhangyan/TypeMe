# TypeMe 测评可信度调整：产品方案

版本：2.0 · 日期：2026-09-15 · 状态：可开始工程实施；中文题目修订为待试用草案，未完成心理测量验证。

配套：[开发方案](TypeMe-测评可信度调整-开发方案.md)、[32题审校与解释草案](TypeMe-32题审校与解释草案.md)、[本轮证据](assessment-evidence/核验记录.md)。

## 1. 本次要解决的真正问题

用户反馈：**结果不准、类型判断不合理；有些题目看不懂。**

本次不再以“页面变好看”为主要目标。要修正从题目理解、作答、分数解释到最终报告的整条链路：

> 看懂问题 → 能如实回答，包括无法判断 → 计算实际支持的维度 → 不足的维度保留未定 → 报告只说答案支持的内容。

### 1.1 本轮检查结论

**没有发现现有 OEJTS 公式在本轮样例中算术错误；已经发现类型解释和题目理解机制存在实质问题。**

| 层面 | 当前证据 | 判断 |
|---|---|---|
| 算术 | 当前领域测试 50/50 通过；独立探针 7/7 符合原公式 | 有工程正确性证据，不能由此证明测得准 |
| 类型切分 | 全部选 3 得 ISFJ；只将 Q3 从 3 改为 2 得 ESFJ | 这是阈值行为；一分变化不应触发整套人格叙事翻转 |
| 报告 | 实际浏览器全中立报告仍加载 ISFJ 日常表现、优势与建议 | 页面提示均衡与正文类型断言互相矛盾 |
| 分享 | 全中立报告生成的图片封面仍大字 ISFJ、“细节照顾者” | 提示在图片下方，无法消除主结论的误导 |
| 无法理解 | 现有答题只有五档；中间档明确说明“不代表没想好” | 用户看不懂时没有可表达真实状态的选项 |
| 题目 | Q6 机器人、Q17 保留可能、Q28 实证等表述；Q8/Q27/Q29 存在情境与价值导向风险 | 需要审校与用户试用，不能只加“凭第一感觉” |
| 量表效度 | 项目没有本版中文题目的实测信效度证据 | 不能宣称“中文更准确”“官方准确率” |

这些是本轮源码、合成答卷和本机浏览器的结论，不是对用户真实人格的判断，也不是对所有答卷都存在错误的推断。

### 1.2 对上一版方案的纠正

上一版方案过于强调兼容四字母与重做页面，保留了“即使均衡也输出默认类型”和“以完整类型作为文案入口”的基础。这会使开发者在表面增加提示后，依然给出不足以支持的报告。

本方案明确覆盖旧文档中以下决定，其余页面响应式、可访问性、本地隐私和工程边界继续有效：

- 不再要求每份报告都有完整四字母类型。
- “兼容码”仅留内部调试，不能出现在用户报告、分享图片、复制文字或文件名里。
- 允许“暂时无法判断”，与中立分值分开存储。
- 报告改为维度结果驱动；16型介绍降为独立的参考阅读。
- 允许有审校记录的中文题面/帮助文字修订，必须形成独立内容版本；不在同一个 quick 名称下静默替换。
- 为上述需求允许新增只读内容契约；不受旧文档“任何接口都不能变”的限制。

## 2. 产品路线：保留什么，改变什么

### 2.1 第一阶段的明确选择

继续做面向普通中文用户的**四维人格偏好探索工具**，在现有 32 题基础上修复可解释性与判型策略。保留用户熟悉的 E/I、S/N、T/F、J/P 语言，实际量表标识仍为 OEJTS。

这条路线能直接实施，避免将“结果不满意”草率处理为“再生成 60/100 道题”或“换个模型猜类型”。增加题数、改权重、接大模型都不自动增加有效性。

### 2.2 三种产品路线对比

| 路线 | 适用目标 | 本次决定 |
|---|---|---|
| OEJTS 中文探索工具 | 个人非商业使用，希望保留四维类型语言 | 采用；说明修订和验证状态 |
| 获得官方量表/服务授权 | 用户明确要求正式 MBTI 测评体系 | 另行确认资源、授权和交付方式；不冒充已有能力 |
| 基于明确来源的大五量表 | 希望以连续特质为主要产品，而非四字母类型 | 后续独立产品选择；不能简单映射大五为 MBTI |

OEJTS 本身说明其不是官方 MBTI，并未保证信度/准确性。16Personalities 也公开描述其 NERIS 为另一套框架，不能把两者的公式、题目和标签混用来“校准”本项目。[OEJTS原始说明](https://openpsychometrics.org/tests/OJTS/development/OEJTS1.2.pdf)、[16Personalities框架](https://www.16personalities.com/articles/our-theory)。

IPIP 的公有领域属性解决使用许可，不等于任何中文改编都有效，也不等于大五能直接转换为 MBTI。其官网明确区分原始资料与第三方实现质量。[IPIP许可](https://ipip.ori.org/newPermission.htm)、[第三方实现说明](https://ipip.ori.org/IPIPImplementationsAroundTheWeb.htm)。

## 3. 用户体验：让“不懂、不像、不确定”有合法出口

### 3.1 测试前说明

首页主文案：**了解你的偏好，也保留还不确定的部分。**

说明：`32 组日常描述。按通常情况下的真实感受选择，没有理想答案。不理解或缺少经历时可以标记“暂时无法判断”。`

首屏说明这版采用 OEJTS 中文修订草案/审校版（按实际状态），不能标“专业认证版”。取消“保证测出你的真实类型”式承诺。

开始前用一个**不计分的教学例子**解释操作即可，不额外收集个人资料：

- 两边都读完；左边是 1，右边是 5。
- 3 表示理解后觉得两侧差不多符合，不代表没看懂。
- 不确定该怎么理解、两边都不适用或没有相关经历，点“暂时无法判断”。
- 实际约束下的行为不必然等于偏好；不要为了选一个“好性格”而选答案。

不要要求用户只回想某一次考试、最近一场聚会，或只按工作角色回答全套题。情境例子用于释义，不重新限定整份量表的测量时间窗。

### 3.2 单题页面

保留两端手动“下一题”和新版响应式壳，增加三个必要元素：

1. 清楚的两端描述，标“左侧/右侧”，两边等权重；不露出所属人格字母暗示答案。
2. `这题是什么意思？`：在题卡内展开短释义，必要时同时解释两端。展开本身不改变答案。
3. `暂时无法判断`：独立于五档之外；可选原因“没理解/没有相关经历/两边都不适用/说不清”，原因可不填，不联网提交。

无法判断不是错误、不扣分，也不会被替换成 3。选后能继续，答题卡显示“待判断”。后续选择数字才替换该状态。

```text
第 6 / 32 题                      已处理 5/32
哪一侧更接近平常的你？
[左侧完整描述]                  [右侧完整描述]
[1 明显偏左] [2 偏左] [3 两侧相近] [4 偏右] [5 明显偏右]
这题是什么意思？ ▾
暂时无法判断
[上一题]                           [下一题]
```

手机的释义在题目下原位展开；长内容正常滚动。PC 也在题卡内，不要求用户在侧栏寻找帮助。不做悬浮提示作为唯一解释入口。

### 3.3 交卷前检查

区分三种数量：

- **已处理**：数字答案 + 无法判断。
- **已选择倾向**：有效 1–5 分值。
- **待判断**：用户明确标记无法判断；另列尚未作答。

所有题均已处理后，若存在待判断：显示 `有 3 题暂时无法判断，部分维度将暂不判型。`，提供 `回去看看` 与 `按现有答案查看报告`。

真正未访问/未处理的题不自动变成无法判断，先定位补充或主动选择无法判断。不要让用户为得到报告而被迫猜一个数字。

## 4. 新的判型产品规则

### 4.1 分开四个概念

| 概念 | 说明 | 面向用户 |
|---|---|---|
| 原始得分 | 严格执行所选版本量表公式 | 可展开查看 |
| 维度解释 | 完整性、两端偏移、待观察状态 | 报告主体 |
| 问卷参考组合 | 四个维度都满足本产品展示条件时生成 | 明确标“本次问卷参考组合” |
| 我的自我理解 | 用户阅读解释后独立记录的自我看法 | 单独展示，不覆盖问卷计算 |

MBTI 官方也区分问卷结果与解释反馈后的 best-fit type；本产品可借鉴“允许讨论和暂不决定”的原则，但本地自我观察模块不冒充官方认证反馈。[官方Best-Fit说明](https://www.myersbriggs.org/unique-features-of-myers-briggs/best-fit-type/)。

### 4.2 维度结论的四种状态

每个维度有 8 个数字作答时才执行该维度的原公式。存在无法判断/缺答时，不按比例补分、不均值填充、不缩短分母生成同一套量表结果。

| 条件 | 页面状态 | 字母处理 |
|---|---|---|
| 该维少于8个有效数字答案 | 信息不足 | 未定；不显示得分位置或 0分 |
| 8题齐全且原始分等于24 | 本次两侧相近 | 未定；没有“主导侧” |
| 8题齐全，距24为1–4分 | 本次略偏某侧，建议继续观察 | 保留偏向文字；不把字母写进完整类型 |
| 8题齐全，距24至少5分 | 本次回答偏向某侧 | 可用于问卷参考组合 |

**5分门槛是本产品暂定的保守展示策略，不是统计置信阈值，也没有证据证明它提升测量准确率。** 它接续旧版 C/D 的需要提醒范围，将提醒转为实际限制。必须版本化、可评估，不宣称是 OEJTS 或 MBTI 官方规则。

一个维度不足或待观察，完整类型就为空。页面可写 `I · S/N待观察 · F · P`，不能展示“INFP，准确率65%”。不要用 XXXX 当作第17种人格。

### 4.3 三个典型报告

**A：全中立。** 四维皆24；显示“本次回答没有显示明确的方向”。不输出 ISFJ、角色名、ISFJ优势或ISFJ分享卡。提供通用的观察建议。

**B：EI=12、SN=25、TF=16、JP=34。** 显示内向、S/N待观察、偏情感、偏灵活；完整类型为空。S/N 从25变24或23，不切换整套 INFP/ISFP 文案，只更新信息偏好部分。

**C：EI=12、SN=32、TF=16、JP=34。** 四维都满足展示条件，可以显示“本次问卷参考组合 INFP”。说明这是本版题目下的参考组合；报告仍以各维实际答案为主，而不是只调出一篇INFP文章。

### 4.4 同分不一定同一种作答情况

全选3与“各维两端贡献相互抵消”的合成答卷都可得24。报告可以客观区分：

- `这一维8题都选了“两侧相近”。`
- `这一维不同题目出现了两侧选择，合计接近中点。`

这不是“作答不认真”或“人格矛盾”的证据，不设惩罚、不输出质量百分比。只帮助用户回顾具体题目。

## 5. 报告从类型文章改成维度驱动

### 5.1 新版结构

1. **本次回答概览**：哪些维度有偏向、哪些待观察、哪些信息不足；能形成参考组合时才显示四字母。
2. **四个维度的说明**：双极含义、状态、作答覆盖情况、可展开的得分方法。
3. **为什么这样描述**：回看该维度相关题目和自己的选择。默认折叠，不把单题包装成因果证据或专业诊断。
4. **继续认识自己**：针对待观察维度给两个中性观察场景，选择“更偏左/更偏右/暂不确定”可作自我笔记，不计入量表分数。
5. **行动建议**：优先采用被支持的维度片段；不确定时给观察行为，不给某类型专属的优势判断。
6. **可选参考阅读**：只有四维足够时，显示相应类型文章，并标“类型参考介绍，非逐项测得的个人能力”；用户主动探索其他类型也标“阅读”，不写入测评结论。
7. **分享**：只导出当前报告真正成立的内容。

### 5.2 内容规则

- 一条 EI 解释只谈精力/互动偏好，不因另三维改变而顺带推断“总是照顾别人”。
- 不从 SN 推断智力，从 TF 推断道德，从 JP 推断勤奋，从 EI 推断社交能力。
- 不生成认知功能排序、荣格八维、A/T、职业匹配率、恋爱配对、类型稀有度。当前量表没有对应测量信息。
- 禁止用“你一定”“你天生”“你总是”。即便使用“可能”，没有测量支持的长篇个人断言也不能因此成立。
- 明显偏向不代表技能高、价值高，也不代表结果稳定。
- 同一维度的相同作答与状态应得到相同解释；某一维小改动不能改变其他三维解释。
- 数字默认收起，主页不再把 `距离/16×100` 叫“人格强度”主卖点。详情可写“本量表相对中点的偏移”，不用概率语言。

### 5.3 自我观察模块的边界

自我观察不是追加评分。不能把用户说“我觉得我偏N”加进SN分值，也不能把“用户更满意了”统计成算法更准。

针对 SN 的例子：`接触一个陌生任务时，你更自然地先找具体示例和事实，还是先形成可能的模式与方向？也可能两种都会用。` 只用于观察；不直接作为OEJTS新增题。

用户可保留未知；不能强制选四个字母才能完成流程。自我记录单独标“我的当前理解”，并可清除。

## 6. 题目可理解性与内容治理

### 6.1 全32题逐项审校

详见配套审校表，包含当前左右端、问题类型、候选写法、帮助文字与处理级别。不能只修改用户指出的一两题而遗漏同类问题。

内容修改分两类：

- **语言修订**：让句子更清楚，尽量保留原义、极向和题号；用新的中文内容版本，先试用再评价。
- **测量替换**：把“喊人声音”换成“主动社交”等看起来更像性格的问题，实质已换构念；不能套原题符号和证据。本次不直接进入正式评分包。

Q6/Q8/Q16/Q18/Q27/Q29 等优先人工审校：其中有些问题来自题项本身的两端不对称或情境影响，不能靠润色保证修好。

### 6.2 禁止在线临时释义

题干、帮助和例子都作为受版本管理的内容，客户端和服务端一致。不要让大模型在用户点击“看不懂”后随意生成不同解释；也不要把答案发送给模型来推断其真正类型。

### 6.3 中文试用与验证计划

先由两名能核对中英文含义的审校者检查极向与措辞，再安排两轮小规模认知访谈，每轮建议5–8名目标用户（设计建议，不是统计验证样本量）。参与者用自己的话复述题目，再说明选择理由；覆盖学生、职场等不同经验背景。

记录：题号、是否首次看懂、是否依赖帮助、误解类别、两边是否都不适用、候选文案版本。经明确同意再收集这些反馈；本次工程不自动上传真实答案。

可理解性试用门槛（产品验收，不是信效度结论）：

- 同一题若两名及以上试用者出现同类关键误读，必须修订并复测。
- 优先问题题目全部有复述结果和处理结论；未解决的题不能标“已验证易懂”。
- 帮助文字必须同时解释两端，不引导向社会认可的一侧。
- 新用户能够说清“中立”与“无法判断”的区别。

若要对外宣称更准确，需要另设心理测量研究：内容适配、项目分析、结构、信度/重测及合适的效度证据；样本和方法由研究目标确定，不能承诺“找200人，α>0.7就算准确”。改编测试应采集试用证据，这是ITC指南的基本方向。[ITC测试翻译与改编指南](https://www.intestcom.org/files/guideline_test_adaptation_2ed.pdf)。

## 7. 分阶段交付与度量

| 阶段 | 交付 | 可证明 | 不可声称 |
|---|---|---|---|
| R1 报告纠偏 | 可未定的类型、维度内容、统一分享、防默认类型泄漏 | 避免已证实的报告矛盾 | 测量准确率提升 |
| R2 可理解性 | 五档+无法判断、版本化帮助、中文修订试用包、复查页 | 用户能表达真实作答状态 | 改写题与原量表等效 |
| R3 用户验证 | 认知访谈与修订记录 | 在所覆盖用户中更易理解的证据 | 代表所有中文用户 |
| R4 测量研究 | 按方案取得的信效度数据 | 与具体样本/版本相符的结论 | 永久真实人格或绝对准确 |

R1和R2均在本次开发目标内。R3/R4需要真实参与者与相应资源，开发者完成可试用版本、材料和记录模板即可，不得编造参与者或验证结论。没有这些资源不阻塞本地实现，但须保留“待验证”状态。

产品度量分开看：任务完成率、看不懂原因分布、复查后修订率、对“未定”的理解率，都是体验指标；与用户自报类型一致率只可做探索，不能当作真实准确率。原型/本地试用阶段不为这些指标自动加埋点。

## 8. 交付验收

- 全中立：页面、分享、复制和文件名都不出现默认ISFJ或对应角色描述。
- 部分维度不确定：没有完整类型；其他维度仍有报告价值。
- 看不懂：可展开解释、可标无法判断、可继续到部分报告，不被迫猜答案。
- 边界改答：只更新对应维度，类型从可给出变待观察时正确撤销，旧分享失效。
- 同一维相同作答：解释不依赖另三维凑出来的类型。
- 公式与旧完整数字答卷兼容；新解释政策的不同明确版本化。
- 题面、解释、计分规则、报告片段来自同一锁定内容包。
- 页面仍满足上一版手机/PC、键盘、恢复及分享可靠性验收。
- 当前工程未做公开发布；本次方案生成未修改业务源码。

## 9. 给dsh的工作顺序

先读本产品方案 → 开发方案 → 32题审校表。先复现证据中的全中立问题，再改结果模型与报告，随后接入新作答状态和释义内容。最后把新版内容包、旧记录兼容、分享以及测试串起来。不要先换一批题再凭结果感觉调公式。

无需再让用户决定每个普通实现细节。只有新增测量构念、改评分公式、扩大收集/发布范围时再说明影响并请求决定。
