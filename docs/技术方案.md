## 0. 先说一个诚实的提醒

**如果只做静态内容站，纯前端 + 静态托管是最省事的选择——Java 后端会多出一台要维护的服务器。**

但我们仍然上 Java，理由站得住：

| 理由 | 说明 |
|---|---|
| **内容与代码解耦** | 题库、16 类型文案用 YAML 维护，改文案不用重新构建前端 |
| **启动期校验** | 32/44 题的题号连续性、维度归属、计分方向可在服务端启动时断言，防止内容错漏上线 |
| **版本化** | 题库/文案有版本号，结果页可标注"依据 v1.2 题库" |
| **架构留位** | 将来若要存匿名结果、做常模、做分享码，架构已就位 |
| **练手** | 这是个正当理由，不必回避 |

**代价**：要维护一台服务器、要管进程、要管日志。**这是明码标价的取舍，不是问题。**

## 1. 关键设计决策（ADR）

### ADR-1：计分放在前端，后端不参与计分

**决定**：32/44 题的计分、类型推断、清晰度分级全部在前端 TypeScript 完成，后端**不提供计分接口**。

**理由**：
1. **零网络请求**：答题过程完全本地状态，切换题目无延迟
2. **断网可用**：地铁、电梯里也能做完
3. **隐私**：**用户的答案从头到尾不离开浏览器**——这比任何隐私政策承诺都硬
4. **成本**：不需要为每次作答消耗服务器

**代价**：计分逻辑只有 TS 一份实现。将来若需要服务端计分，必须复制逻辑并保证两侧一致（届时用共享测试向量约束）。

> 这条是整套架构的核心，其他决策都围绕它。

### ADR-2：不建数据库，不存任何作答数据

**决定**：**不引入 MySQL/PostgreSQL，项目里没有任何持久化存储。**

**理由**：
- 已确认后端不存作答数据 → 没有要存的东西
- 不存数据 → **不触发《个人信息保护法》任何义务**（无告知同意、无删除权、无出境评估、无未成年人门槛）
- 省掉 DB 的安装、备份、连接池、迁移脚本

**代价**：
- 没有历史记录、没有重测对比
- 永远无法做人群常模（**这条我们本来就接受**，需求文档 4.2 已明确不给百分位）

**如果将来要存**：加 Spring Data JPA + PostgreSQL 即可，ADR-1 不受影响。但要同步补隐私政策与删除功能。

### ADR-3：内容用 YAML 维护，服务端启动时校验

**决定**：题库与类型文案放在 `backend/src/main/resources/content/`，用 YAML 声明；Spring Boot 启动时加载并**断言校验**，校验失败直接启动失败（快速失败）。

**校验项**：
- 每题 `id` 唯一、`dimension` 合法、`direction` 只能是 `+1 / -1`
- 每个版本的题号连续、每维度题数符合预期（快速版每维 8；标准版 I–E/F–T/J–P 各 12、S–N 8）
- 标准版必须包含快速版的全部 32 题（保证两版可比）
- 每条类型文案必须覆盖全部 16 个类型码

> **这条能防住最坑的失误**：题库手改错一个方向符号，结果会系统性出错，且很难靠肉眼发现。

### ADR-4：前端内置内容副本，后端挂了站点仍可用

**决定**：前端构建时**把同一份内容打包进产物**作为 fallback。启动时先请求 `/api/v1/...`，失败则用内置副本，并静默降级。

**理由**：个人站没有运维值班。**后端一挂就全站白屏是不可接受的。**

**实现**：内容源用同一份 YAML，前端通过构建脚本（Vite 插件或预构建 Node 脚本）把它转成 TS 常量。

### ADR-5：单端口部署，后端直接托管前端静态产物

**决定**：Vue 构建产物放进 Spring Boot 的 `static/` 目录，**由 Spring Boot 一个进程同时提供页面和 API**，监听 **8080**。

**理由**：
- 单进程、单端口，部署和排错都简单，不需要额外配 Nginx
- **用 IP + 非标准端口访问，规避域名与 ICP 备案**

**代价（重要，见第 6 章）**：**没有 HTTPS。**

## 5. API 契约

全部为 **GET**，无认证，无写接口（因为没有要写的东西）。

### 5.1 `GET /api/v1/meta`

```json
{
  "appVersion": "1.0.0",
  "contentVersion": "2026-09-01",
  "questionnaireVersions": ["quick", "standard"],
  "attribution": {
    "source": "Open Extended Jungian Type Scales (OEJTS) 1.2",
    "author": "Eric Jorgenson",
    "url": "https://openpsychometrics.org/tests/OEJTS/",
    "license": "CC BY-NC-SA 4.0",
    "licenseUrl": "https://creativecommons.org/licenses/by-nc-sa/4.0/"
  }
}
```

> ⚠️ **归属信息是 CC BY 的硬性义务，必须由接口下发并在前端展示**（落地页 + 关于页），不能只写死在某个页面里。

### 5.2 `GET /api/v1/questionnaires/{version}`

`version` ∈ `quick` | `standard`

```json
{
  "version": "quick",
  "title": "快速版",
  "questionCount": 32,
  "estimatedMinutes": 5,
  "questions": [
    {
      "id": 1,
      "textLeft": "喜欢列清单",
      "textRight": "凭记忆",
      "dimension": "JP",
      "direction": 1
    }
  ]
}
```

- `direction`：`+1` / `-1`，对应官方公式的符号
- **前端不硬编码题号与符号**，全部由接口驱动 → 题库调整不需要改前端

### 5.3 `GET /api/v1/types/{code}`

```json
{
  "code": "INFP",
  "nameCn": "调停者",
  "tagline": "……",
  "dimensions": { "EI": "……", "SN": "……", "TF": "……", "JP": "……" },
  "strengths": ["…", "…", "…"],
  "blindSpots": ["…", "…", "…"],
  "resonance": ["…", "…", "…"],
  "growth": ["…", "…"]
}
```

> `resonance` 就是需求文档 6.3 的「这说的就是我」条目——**3–5 条具体、可证伪的描述**，是反巴纳姆的关键。

### 5.4 `GET /api/v1/method`

方法说明页内容：题库来源与许可、计分方法、**为什么 S–N 测不准**、信效度数据、致谢。

### 5.5 关于分享码

**不做后端接口。** 结果可用纯前端的 URL 参数编码（如 `?r=ISFP&d=...`），零后端、不落库。若以后要做"朋友对比"，继续沿用这个方式。

## 6. 部署方案（含 HTTPS 缺失的后果）

### 6.1 方案

| 项 | 选择 |
|---|---|
| 服务器 | 国内云轻量应用服务器（阿里云/腾讯云），**2C2G 够用** |
| 访问方式 | **`http://<公网IP>:8080`** |
| 域名 | **不用** |
| ICP 备案 | **不做**（备案针对域名，IP + 非标准端口通常不触发） |
| 进程 | Spring Boot 打成 fat jar，`systemd` 守护（自启 + 崩溃重启） |
| 前端产物 | `mvn` 构建前先 `npm run build`，产物复制进 `backend/src/main/resources/static/` |
| 安全组 | 只放行 8080（和 22） |

> ⚠️ **【需确认】** 云厂商 ToS 对"IP 直接提供 Web 服务"的态度不完全一致，且规模变大后可能被要求备案。**这是"先用起来"的方案，不是长期方案。**

### 6.2 没有 HTTPS 会损失什么（必须知道）

| 影响 | 后果 | 对策 |
|---|---|---|
| **Web Share API（`navigator.share`）不可用** | 手机上无法唤起系统分享面板 | 降级为「下载图片 → 自行处理」；**这是必须实现的降级路径，不是可选** |
| `navigator.clipboard` 不可用 | 「复制链接」按钮失效（需 secure context） | 降级用 `document.execCommand('copy')` |
| **Service Worker / PWA 不可用** | 无法装到桌面、无离线缓存 | 可接受；离线能力靠 localStorage 进度 |
| 浏览器显示"不安全" | 观感差（PC 浏览器地址栏会明确标"不安全"） | 在落地页说明这是个人站 |
| 部分浏览器 API 受限 | 如 `getUserMedia`、通知 | 本项目不需要 |

**结论**：**核心功能（答题、计分、结果、canvas 生成与下载图片）在 HTTP 下都能工作。** 需要写降级代码的是 Web Share（手机分享）与剪贴板两处。

> ⚠️ **范围变更（去微信化）**：本项目**不再以微信内置浏览器为目标环境**，改为普通网页访问 + PC/手机响应式。因此原「微信 JS-SDK 不可用」一行已移除——该约束不再适用。

### 6.3 将来若要 HTTPS

必须**有域名**（自签证书微信内会被拦截）→ 就必须**ICP 备案**（约 1–3 周）。
届时加 Nginx + Let's Encrypt，Spring Boot 退到 127.0.0.1:8080。**架构不用改。**

## 7. 计分引擎（唯一的关键实现）

### 7.1 官方公式（**必须原样实现，不要"优化"**）

```
IE = 30 - Q3 - Q7 - Q11 + Q15 - Q19 + Q23 + Q27 - Q31
SN = 12 + Q4 + Q8 + Q12 + Q16 + Q20 - Q24 - Q28 + Q32
FT = 30 - Q2 + Q6 + Q10 - Q14 - Q18 + Q22 - Q26 - Q30
JP = 18 + Q1 + Q5 - Q9 + Q13 - Q17 + Q21 - Q25 + Q29
```

- 每维得分范围 **8–40**，中点 **24**
- 判定：`> 24` → 正极（E / N / T / P），否则负极（I / S / F / J）
- ⚠️ **是 `>` 不是 `>=`**，中点 24 归到 I / S / F / J

### 7.2 必须写的单元测试

用官方定义的三组极端输入验证，**这三条断言能挡住绝大多数实现错误**：

> ⚠️ **勘误（已验算确认）**：本节初版误写「全选 1 → 8 分 → ISFJ、全选 5 → 40 分 → ENTP」。**那是错的**——官方公式下每维符号和为 EI −2、SN +4、TF −2、JP +2，全选 1 只会得到 28/16/28/20。初版数值是照「原值直接相加」的错误算法倒推的，**恰好就是 `openjung` 的 bug**。

| 输入 | 期望 |
|---|---|
| 全部选 1 | EI 28 / SN 16 / TF 28 / JP 20 → **ESTJ** |
| 全部选 3 | 每维 = **24** → **ISFJ**（因 `>24` 才翻） |
| 全部选 5 | EI 20 / SN 32 / TF 20 / JP 28 → **INFP** |

**要测分数极值 8 / 40，需要专门的作答模式**：负号题选 5、正号题选 1 → 每维 8；反之为 40。**不要用"全选 1/全选 5"当作极值测试。**

⚠️ **额外加一组"防回归"测试**：随机生成 1000 份作答，断言每维得分恒在 8–40 区间，且 `intensity ∈ [0,100]`。

> **背景**：GitHub 上的 `openjung/core` 就是在这里出错的——它把 8 题原值直接相加判 `>24`，丢掉了符号和常数，导致同一份答卷给出不同字母。**照官方公式实现 + 写死这三组断言就不会踩。**

### 7.3 输出

```
原始分 s ∈ [8, 40]
偏向强度 = (s - 24) / 16          → [-1, +1]
显示强度 = |偏向强度| × 100       → 0–100
清晰度 d = |s - 24|：d≥9 明显 / 5–8 中等 / 2–4 轻微 / d≤1 压线（显示双字母）
```

**绝对不要输出"人群百分位"**——没有样本量，给了就是编造（需求文档 4.2）。

## 10. 待决策与风险

| # | 项 | 说明 |
|---|---|---|
| T1 | 内容 YAML 的 schema 细节 | 建议第一版就定死，后面改 schema 要动前后端 |
| T2 | 前端内容副本的生成方式 | Vite 插件 vs 独立 Node 脚本（建议后者，简单可控） |
| T3 | 是否上 Docker | 单机 systemd 足够；Docker 会多一层，但环境更干净 |
| T4 | 是否需要 `/api/v1/types` 一次返回全部 vs 按需 | 16 条文案总量小，建议**一次全量返回**并在前端缓存 |
| **R1** | **IP 访问的长期合规风险** | 云厂商可能要求备案；**规模变大这是第一个要解决的问题** |
| **R2** | **无 HTTPS 的观感** | 用户会看到"不安全"；建议落地页主动说明"个人站、无追踪" |
| **R3** | **内容校验漏网** | 靠 ADR-3 的启动断言 + 内容测试双保险 |
| R4 | 44 题标准版权重要自定 | 扩充题**没有官方验证权重**，且 24 分切分点失效；建议第一版**先只上 32 题** |

## 11. 建议的第一刀

不要一次做完。按这个顺序切：

1. **`questionnaire-quick.yml`（32 题）+ 计分引擎 + Vitest 断言** ← 先跑通这条最小链路
2. Spring Boot 骨架 + ContentService 校验 + 3 个 GET 接口
3. Vue 三个页面
4. 分享图
5. 16 类型文案（可与 2/3 并行，纯内容工作）
6. 部署

**第 1 步做完就能自己测一遍**，验证"32 题出来的结果像不像我"。这一步的反馈决定后面所有事——**在它之前不值得写任何页面。**
