## 执行卡片
- 改变：所有"跳到某一节"的滚动落点，在任何宽度和登录状态下都停在粘性顶栏的下沿之下，标题不会被盖住。
- 保持：hash 路由下仍用 JS 滚动，不改成 `<a href="#id">`（E-6）；跳转后焦点交给目标区块的现有行为不变；`prefers-reduced-motion` 仍关闭平滑滚动；顶栏外观和折行方式不变。
- 先核验：在 320 / 390 / 1440 宽实测 `.site-header` 高度（未登录、普通用户、管理员各一次）。如果所有组合都不超过 60/64px，说明问题已不存在，先停下报告。
- 首个切片：S-1，把 `--header-h` 改成运行时测量的值，报告页目录跳转在 320 宽落到顶栏之下。
- 完成判据：A-1…A-5 通过，现有 Vitest 与 typecheck 不回归。

## 方案

1. **测量**：App.vue 挂载后用 `ResizeObserver` 观察顶栏元素，每次尺寸变化把 `getBoundingClientRect().height` 取整后写成 `--header-h`（单位 px）；卸载时断开观察并移除这个内联变量。观察器不可用时不写，沿用 CSS 默认值。
2. **统一消费**：所有锚点偏移都改成 `calc(var(--header-h) + <留白>)`。删掉 E-4 里的 Tailwind `scroll-mt-*`，让这些区块交给 base 层的 `[id][data-anchor]` 规则处理（没有 `data-anchor` 的补上）；E-5 的目录标题改用同一个变量加上原来的视觉留白。
3. **成员页**（E-7）可以继续自己测量，也可以改读这个变量。执行 Agent 自行决定，但不能让 A153 的验收（`scripts/browser-verify-admin-members-errors.py`）回归。

## 兼容、风险与回滚
- 顶栏高度变化会让已滚动的页面产生一次重排，但 `scroll-margin-top` 只在跳转时生效，不会推动正在阅读的内容。
- 窄屏顶栏高达 153px 时，落点区间（A-2）会吃掉约 1/4 屏，这是顶栏本身的问题（A6 曾压缩过），不在本任务范围内。
- 回滚：撤掉 App.vue 里的观察器，变量自动回到 CSS 默认值；其他样式改动可以一起回退。
