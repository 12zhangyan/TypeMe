# 内容发布与研究准备（工程清单，不是效度结论）

## 当前事实与版本

2026-09-23 源码核对：新建十六型使用 `typeme-jung48-zh-v4`，大五使用 `typeme-bigfive50-zh-v1`（`JungPackageLoader.CURRENT_PACKAGE_ID`、`BigFivePackageLoader.CURRENT_PACKAGE_ID`）。v4 题面沿用 v3，阈值分母为 5；旧 v1/v2/v3 包、报告快照不得重写。大五新包由 `scripts/gen-platform-content.mjs` 读取 `backend/src/main/resources/assessment-packages/ipip50-zh1.yml` 派生；此源还服务旧 IPIP 流程，任何未来中文题面变化必须另建候选源与新包，不原地改写。

当前 `draft_review_pending` 是内容审校状态，不代表语言等值、重测稳定性、效度或常模已获验证。十六型是自我探索参考，不是官方 MBTI、诊断或选人依据；大五五维独立，不生成类型码、总分或人口百分位。现有测试验证实现一致性，不产生心理测量证据。

## 题目审校矩阵的现有基线

当前可复现的逐题工作表是 `06-当前题目审校矩阵.md`，由 `node scripts/gen-assessment-review.mjs` 从 v4、平台大五 v1 与旧 IPIP YAML 英文注释生成。`node scripts/gen-assessment-review.mjs --check` 只读核对当前工作表与内容快照，并检查 64/50 题、顺序、源题号、中文题面、维度和逐题方向一致。它不是人工审校；评审意见和访谈证据应单独保存，不能用重新生成覆盖人工记录。

- 十六型 64 题（48 主测、16 补充）的逐题矩阵已经在 `docs/2026-09-16/implementation/content/jung48-item-review.md`：ID、阶段、维度、两端措辞、极点、方向、疑义与修改意见。该文件记录的是 v1 初稿；v2 对 JP-02/JP-03 的修正见 `docs/2026-09-18-platform-plan/题目审校与版本决策.md`，v3/v4 不再换题面。**不能把旧矩阵的意见列误当成当前 v4 的盲审结论**。
- 大五 50 题的英文原句（每题 `# en:`）、中文题面、维度与 `direction` 在 `backend/src/main/resources/assessment-packages/ipip50-zh1.yml` 同位对照。平台新包在 `backend/src/main/resources/content/bigfive50-zh-v1.json`；逐题解释与来源追踪要同时核对旧源和派生版本。该同位对照不是独立翻译审校或语言等值证据。

对每一题的下一轮审校记录采用如下列，不先填写没有做过的访谈或评审结论：

| 记录字段 | 如何填写 |
| --- | --- |
| packageId、sha256、题号、版本来源 | 指向被冻结的内容包和对应源行，避免把 v1 与 v4 混用 |
| 英文原句／中文题面／帮助文字 | 大五核对 `# en:` 与 `text`；十六型记两端、场景与 help |
| 维度、方向／左右极点 | 双人先独立判语义，再与计分键比对；不为了提类型率改键 |
| 风险与候选修订 | 双重否定、文化情境、社会赞许、能力评价、维度混入、近义重复 |
| 审校人、日期、证据编号与结论 | 未完成保持“待审校”；分歧保留原始意见，不静默覆盖 |
| 访谈观察、试测分布与版本决定 | 只有实际收集并按同意范围分析后填写；改题必须发新包 |

优先核对十六型旧矩阵已提示的 JP-10、JP-11、EI-12、TF-10 等歧义，以及大五反向题和中文能力暗示。此处仅列已有风险，不宣称已解决。

## 发布检查单

1. 记录新包 ID、旧包 ID、内容与计分/报告版本、来源、差异、SHA-256、许可证及影响旧流程的路径；已有包和迁移历史保持原样。
2. 两位审校者分别检查题面含义和键值，保留分歧与证据；确认新增版本而不是覆盖已绑定内容。
3. 先对现有源跑六项 `--check` 留基线；修改候选源后生成、复查 diff、两端共享夹具与旧快照读取。不得把自动脚本通过称作真人审校通过。
4. 用合成答卷验证未作答、UNKNOWN、中档、覆盖不足、TIED/NEEDS_REVIEW、五维独立与历史报告不重算；检查导出、分享与可访问文案一致。
5. 发布默认版本、内容登记、执行迁移或使用真实数据库必须另获目标与操作授权；发布前拟定回滚与旧版本继续读取方案。
6. 只有认知访谈和试测按伦理/同意流程真实完成，才能更新相应研究状态；没有常模不得给出百分位。

## 研究执行模板（待开展）

认知访谈记录：使用随机参与者代号、同意版本、内容包与题号；逐题请参与者用自己的话复述、说明选择依据、标出不理解的词与“说不好”的原因。访谈者记录原话与观察分开，先不提示预期维度；招募、访谈与外发均需另外授权和合规审查。

试测数据字典最小字段：随机 `participantId`、`consentVersion`、`packageId`、`contentSha256`、题号、原始作答状态（未处理/UNKNOWN/数字 1–5 分开）、完成时间与题意反馈。不要默认导出用户名、昵称、邮箱、私人备注、恢复码或 AI 输入；单独定义保存期、撤回方式与最小权限。

分析预注册事项：按题与维度看缺答/UNKNOWN 分布、反向题理解与项目相关、内部一致性及区间、结构与重测稳定性；对十六型还要看边界稳定性，不用“出四字母比例”当效度。快速作答只作核查信号。样本量、纳排与判定标准须在真实研究开始前设计，不在代码里写一个“达标即有效”的开关。
