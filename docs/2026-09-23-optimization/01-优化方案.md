# TypeMe 前后端与双测评优化方案

日期：2026-09-23。性质：基于当前仓库的设计交付，尚未实施应用改造。

配套：[详细设计](02-详细设计.md) · [源码证据与本轮验证](03-现状核查与验证记录.md)。

## 1. 建议先做什么

建议按“作答与记录可靠 → 页面和按钮易用 → 报告易读 → 加载与查询效率 → 测评内容验证”的顺序推进。继续使用 Vue、Pinia、Spring Boot 和 JdbcTemplate，在现有模块上渐进改进。

第一批优先交付四件事：**十六型离页防丢失、大五新建草稿的重试幂等、草稿服务端筛选、历史报告分页**。这些都有当前代码位置支撑，能够直接改善用户结果。第二批再统一按钮和报告操作，随后依据测量结果优化前端包与后端查询。

“更容易得出四字母”“更少出现信息不足”不设为优化目标。测评质量的提升需要题目审校、认知访谈和试测，不能由界面美化或单元测试通过代替。

## 3. 问题与优先级

优先级定义：P1 为数据体验和主流程可靠性；P2 为主要体验、可解释性和维护；P3 为需要测量支撑的性能或后续扩展。本轮没有足够运行证据认定线上 P0 故障。

| 任务 | 优化项与事实依据 | 优先级 | 用户结果与验收核心 |
|---|---|---|---|
| S01 | 十六型缺少离页保存确认；两类新测均未见未保存答案的刷新关闭保护（F03） | P1 | 保存失败后点“暂时离开”有明确选择；不能把未同步记录说成已保存 |
| S02 | 大五选择页调用新建时未传幂等键（F04） | P1 | 服务端已创建但响应丢失，再试仍得到同一草稿 |
| S03 | 草稿取前 50 条后在浏览器过滤（F05） | P1 | 第 51 条及更早的未完成草稿仍可发现，失败态不误当无草稿 |
| S04 | 报告列表固定取第 0 页、50 条，没有翻页（F06） | P1 | 超过 50 份时能完整浏览，筛选和计数口径一致 |
| S05 | 新建资源与幂等完成分开，且 create 同类调用带事务注解的方法（F10） | P1 | 故障注入下资源与幂等结果一致；修正事务边界后回归真实并发 |
| S06 | 两套作答保存和冲突反馈存在实现差异（F02、F03、F07） | P1 | 同类错误得到同类提示，冲突保留待确认答案，不自动覆盖 |
| S07 | 大五离页弹窗手写，未复用已有焦点管理（F07） | P2 | 键盘焦点不逃出弹窗，关闭后回到触发位置 |
| S08 | 按钮样式已有基础，但业务加载、防重入、禁用原因分散（F13） | P2 | 每个按钮都能解释当前动作及不可用原因，异步结束不残留忙态 |
| S09 | 首页续答入口常驻，仍混有十六型专项内容与静态旧内容依赖（F12、F14） | P2 | 新访客清楚怎么选；已有草稿按实际量表续答；专题内容层级清楚 |
| S10 | 以大五接口的 409 分流十六型，页面随后重复加载（F08） | P2 | 使用中性元信息分流；正常流程不制造错误响应 |
| S11 | 新旧流程与管理页大量路由静态导入，App 也引用旧 store（F12） | P2 | 首页依赖收敛；进入旧流程时仍完整可用 |
| S12 | 大五报告缺少十六型已有的复制/图片导出，比较也只覆盖十六型（F11） | P2 | 两种报告有一致操作壳；比较保留量表和版本限制 |
| S13 | 报告层级和大五连续分数解释可进一步统一（F11、F16） | P2 | 先读结论与限制，再看细节；不会误读为人群排名 |
| S14 | 多个页面直接截取 UTC 字符串，时间呈现不统一（F17） | P2 | 同一记录在列表、详情、草稿显示相同的本地时间 |
| S15 | 大五存在未被调用的旧量程方法及误导注释（F16） | P2 | 消除后续误用入口；不把它报告为当前计分错误 |
| S16 | 当前报告列表读取完整 report_json 再提取摘要（F09） | P3 | 测量后减少列表 JSON 解析和传输；不重算历史报告 |
| S17 | 公开目录/图片映射可评估条件缓存；AI 当前固定周期轮询（F18） | P3 | 减少重复请求，同时准确刷新目录与任务状态 |
| S18 | 内容一致性已通过，心理测量证据仍待建立（F01、F19） | P2，研究线 | 从题目理解、翻译等值与试测数据发现问题，独立于代码正确性 |
| S19 | 版本信息、旧文档和当前事实存在局部出入（F15） | P2 | 更新事实索引和契约；保留历史记录，不抹掉原决策 |
| S20 | 缺少本轮运行性能基线 | P2，先测量 | 建立可复现指标后再决定索引、缓存、拆包规模 |

以上“缺少”只指本次查到的当前实现；源码路径和证据等级见核查记录。性能收益、真实丢失比例、冲突率与用户完成率均待测量。

## 4. 前端页面优化

### 4.1 信息架构

主导航使用“选择测评 / 我的测评 / 我的报告 / 账号”，管理入口仍按权限展示。答题时保留简化壳，突出题目、进度、保存状态和离开入口。

| 页面 | 主要内容 | 首要动作 | 次要动作 |
|---|---|---|---|
| 首页 | 两种测评差别、实际续答卡、结果示例、定位说明 | 选择测评；有可确认草稿时提供继续 | 查看方法 |
| 测评目录 | 题型、题量、预计时长、报告形式、内容状态说明 | 开始这一项 / 继续这一项 | 了解怎么测 |
| 测前说明 | 作答示例、中立与说不好的区别、服务端保存说明 | 我了解了，开始作答 | 返回目录 |
| 我的测评 | 服务端筛选的未完成记录、量表筛选、更新时间和进度 | 继续作答 | 明确“另开一次” |
| 答题页 | 一屏一题、题面、帮助、五档、说不好、同步状态 | 下一题 / 检查并提交 | 上一题、答题卡、暂时离开 |
| 补充题说明 | 为什么出现、实际题数、可跳过及结果影响 | 继续补充题 | 跳过补充题并提交 |
| 报告页 | 摘要、证据边界、维度解释、可观察行动 | 阅读报告 / 复制摘要 | 保存图片、查看方法、复测、可选 AI |
| 历史报告 | 筛选、分页、明确的结果状态 | 打开报告 | 同量表可比较记录、删除 |
| 登录/注册/恢复 | 字段反馈、邀请码、隐私定位说明和回跳 | 完成当前表单 | 切换登录/恢复 |
| 账号/管理 | 按资料、安全、数据、管理职责分区 | 当前分区的唯一提交 | 取消；危险动作独立放置 |

首页继续入口必须区分“未登录”“草稿查询中”“查不到服务”“确实无草稿”“有草稿”。查不到服务时显示重试，不以默认新建代替。预计时长保留“约”，后续用自愿试测数据校准，不能承诺固定分钟数。

### 4.2 视觉与移动端

延续暖白、森林绿、现有插画与阅读样式。优先整理内容层级和首屏信息量，不再整体更换视觉风格。插画避免抢占答题、表单和报告核心结论的可用空间。

- 中文正文建议 16px 左右、行高约 1.7；辅助说明不承载唯一的关键信息。
- 原按钮已有 44/48/52px 高度，保留基础。触控主要动作保持 44px 以上，题目选项沿用更大点击区。
- 320px 时保证选项完整可读；390px 检查单手操作；1440px 限制作答文本宽度并增加留白。
- 底部操作栏按实际高度预留空间，包含安全区；页面缩放后仍能滚动到最后一项。
- 焦点、选中、错误、保存失败同时提供文字或图标，不只靠颜色。
- 统一时间格式、错误通知、空态和重试入口。

详细按钮规格和布局见详细设计第 3–4 节。44px 是本站设计目标，不把它误写成 WCAG 2.2 AA 的统一最低尺寸；相关标准见 R01、R02。

## 5. 页面按钮优化

按钮优化包含“名称、层级、状态、动作结果和键盘语义”。每个主要按钮都需要一份动作契约。

| 情境 | 默认文案 | 执行中 | 失败后 | 禁用说明 |
|---|---|---|---|---|
| 创建草稿 | 开始十六型测评 / 开始大五测评 | 正在准备题目… | 重试开始，沿用本次操作标识 | 正在确认已有进度 |
| 继续草稿 | 继续作答 | 正在载入… | 重试载入 | 草稿不存在时给返回入口 |
| 单题推进 | 下一题 | 保持题目立即响应，状态区显示同步 | 保留本地回答和重试保存 | 未处理本题时提示“先选择一项或说不好” |
| 最终提交 | 检查并生成报告 | 正在保存… → 正在生成报告… | 重试提交；结果不确定先查已有报告 | 缺题、冲突、会话失效分别解释 |
| 保存失败 | 重试保存 | 正在保存… | 保留错误与未同步条数 | 登录失效时改为重新登录 |
| 冲突 | 查看两边的改动 | 正在读取最新进度… | 重试读取 | 不提供无提示覆盖按钮 |
| 复制摘要 | 复制报告摘要 | 正在复制… | 给可手动复制的文本 | 报告未加载完整时解释 |
| 保存图片 | 保存报告图片 | 正在生成图片… | 重试生成 | 生成中只锁住该动作 |
| AI | 查看 AI 分析选项 | 确认后生成；任务中显示状态 | 展示失败原因和可重试条件 | 额度、未开启、版本不支持、未同意分别解释 |
| 删除 | 删除这份报告 | 正在删除… | 对话框内显示失败 | 确认对象和影响，取消为安全默认 |

共享组件只处理视觉与交互语义；是否提交、如何幂等、如何解释业务失败仍由页面/store负责。避免一个万能按钮组件同时做网络请求、弹窗和跳转。

## 6. 答题与业务逻辑优化

### 6.1 保存与退出

建立共同的同步状态：未改动、待同步、保存中、已保存、保存失败、冲突、需重新登录。两套量表保留独立的轮次和计分规则，共用同步协调器或相同的契约测试。

每份草稿只允许一个 PATCH 在途；保存确认只覆盖本次发送的本地修订，不能清掉用户随后修改的答案。清除答案也是修改。切换草稿、退出账号和旧请求晚到时，必须按用户、attempt 和代次隔离。

页内离开先等待有限时长的保存；失败时选择留在当前页或明确放弃未同步部分。刷新关闭保护只作为最后提醒，不承诺浏览器一定会触发，不把异步请求或 sendBeacon 当成已持久化保证。默认不新增浏览器长期保存答案。

### 6.2 创建、续答与复测

“继续”“另开一次”“基于旧报告复测”三个动作分开。查询失败不自动新建；用户已经有草稿时默认继续，另开一次由明确动作触发。请求结果不确定的重试复用幂等键。

复测创建新 attempt 并记录来源，保留现有“不复制旧答案”的规则。若改的是已提交答案，必须进入新测评，旧报告保持原样。新测默认使用当前发布包；历史报告的“原规则”不能被新默认包替代。

### 6.3 提交与报告

十六型仍经过服务端覆盖检查、review 和提交；大五处理完 50 题即可生成 PROFILE，但数字回答不足的维度不给分数与方向。“说不好”可提交与“该维有充分作答”是两件事，提交检查页必须说明。

提交失败先分清“明确未成功”和“响应丢失、结果未知”。后者可只读查询 attempt 绑定报告后导航，避免引导用户反复新建。相同 attempt 的报告唯一约束必须保留。

## 7. 后端优化

继续采用模块化单体。前端可以共用页面壳，后端可以共用身份、版本、生命周期与查询能力，计分引擎保持分离。

| 方向 | 设计 |
|---|---|
| 中性分流 | 增加只读 attempt 元信息接口，返回已验证归属的 instrumentKind、版本、状态、reportId；不再把 409 当正常分流 |
| 筛选分页 | 草稿在 SQL 层按 open 状态过滤；报告分页并按量表筛选；稳定排序并在前端防止旧请求覆盖新筛选 |
| 事务幂等 | 复用仓库独立 writer bean 模式，让 attempt 写入与幂等完成在一个短事务中完成；故障注入验证 |
| 查询投影 | 先量测读取完整报告 JSON 的成本；必要时增加可重建摘要投影，历史 report_json 不动 |
| SQL 与索引 | 检查已有 user/time、user/status、唯一键及主键；依据 EXPLAIN 和数据量决策，不直接堆索引 |
| 公共缓存 | 目录和公开图片映射评估 ETag；私有草稿、报告和账号响应继续按私有数据策略处理 |
| AI | 保留独立任务、用户同意、配额、失败降级；只优化轮询和任务可观测性 |
| 可观测性 | 记录请求耗时、错误码、保存结果、队列等待等低敏指标；不采集密码、答案正文、报告正文或 AI 近况文本 |
| 安全 | 回归归属校验、CSRF、会话、限流、管理权限、删除与导出；前端禁用不能替代后端验证 |

默认暂不引入 Redis、消息队列、微服务或新 ORM。只有测量证明现有机制不够时再单独论证。框架升级属于独立兼容与依赖审计任务，不与本轮行为改动混在一起。

## 8. 十六型人格测评优化

### 8.1 产品呈现

- 对外保持“十六型人格参考测评”，明确非官方 MBTI。
- 报告先显示本次四维倾向与状态，再展示类型描述；TENTATIVE 明确写暂定参考，TIED 不拼完整四字母。
- 两侧都有合理的日常表现，不把 T/F 写成人品、EI 写成社交能力、JP 写成自律好坏。
- 候选 cost 保持规则距离解释；不换成匹配率。过程结构与建议同时展示“由字母推导、未额外测量”的说明。
- 补充题解释数量和触发原因；不诱导用户“补完一定更准确”或“必须选出一边”。

### 8.2 内容改进

为 64 题建立审校矩阵：维度、方面、正反方向、生活场景、语言复杂度、职业/学生适用性、社会赞许倾向、与其他维度混淆、帮助文本是否引导答案。优先评审双重问题、两端不对称、只适用于某类生活经历的题。

题面、帮助、顺序或解释改变都经过内容版本评审，先形成候选源文件，不覆盖已绑定包。保留 Java/TypeScript 同夹具、旧版本冻结、边界等号和全部结果状态测试。

### 8.3 规则改进边界

当前 v4 的阈值刚于 2026-09-22 完成调整。本方案不再提出随意调低或调高；先观察版本分布、补充题触发率、跳过率、边界稳定性和用户理解。指标只用于检验规则与体验，不把类型分布调均匀当成“准确”。

没有测量模型与校准数据前，不实施 IRT 自适应、动态加权、“AI 判型”或按用户期望补类型。

## 9. 大五人格测评优化

### 9.1 计分与呈现

保留 IPIP-50 的逐题方向和五维结构。每维 10 题，正向按 rating，反向按 6-rating；完整回答得到 10–50，数学中点 30。常量形式与反向计分等价，依据 R05、R06 及当前生成器核对。

报告以五条同向刻度呈现 E、A、C、ES、O，各自解释。ES 继续使用“情绪稳定性”方向，不在其他页面突然切成“神经质”而仍显示同一数值。O 的来源构念说明保留 IPIP 因子标记口径，不宣称等于完整 NEO 分面测量。

当前分档距中点 6、11 是产品展示策略。30 是量程中点，不是中国用户均值；40/50 不是 80% 人格水平；若提供 0–100 量程换算，必须叫“量程位置”，建议默认不显示以减少误读。

### 9.2 缺答与未知

一维需要 10 个数字回答才给分。某维含“说不好”时该维保留缺失结果，其他完整维度正常显示；不填 3、不缩短分母、不把 unknown 算成低分。

提交前说明：“你已处理 50 题，其中 X 题选择说不好；本次 Y 个方面可以解读，其他方面将标为信息不足。”提供回看，不要求用户编造数字回答。五维都不足时也明确保留“本次没有足够信息”的 PROFILE，是否改变此产品规则另行评审。

### 9.3 中文题目与报告

以原始题号、原文、当前中文、帮助、方向建立对照。由熟悉中英文和测量内容的审校者检查含义，再做受试者复述与认知访谈；只做回译不能证明等值。相关流程依据 ITC 适应性指导 R08。

不能从 10 题一个维度直接宣称可靠测出了 6 个分面或“30 项人格能力”。先完善连续维度报告、缺失解释、可观察行动与同版本比较，再考虑新量表产品。

## 10. 测评质量验证计划

工程验证和测量验证分别交付。工程测试证明公式和版本一致；研究数据用于评估理解、结构与稳定性。

| 阶段 | 工作 | 交付与进入下一阶段条件 |
|---|---|---|
| 内容审校 | 构念定义、题目映射、授权与来源、双极或反向含义核对 | 每题审校表、争议列表、候选包；无未处理的严重含义冲突 |
| 认知访谈 | 建议先按每量表 10–15 人编预算，覆盖不同学习/工作经历，按发现追加轮次 | 逐题理解问题与修订理由；这个人数是排期建议，不是效度充分性标准 |
| 可用性试测 | 可先以每量表 30–50 人估算流程预算，记录完成与误解，不做正式常模推断 | 时长、unknown 分布、补充题负担和报告理解问题 |
| 测量研究 | 专业人员依据模型、缺失率和精度要求制定样本量；研究计划先确定再收数 | 项目分析、适合有序作答的结构分析、内部一致性及区间、重测分析、必要的群体差异检查 |
| 发布评审 | 将代码验证、内容审校、测量证据、限制说明一起审阅 | 准确写明已验证与尚未验证范围，不因 alpha 较高就宣称测评准确 |

研究采集需要独立知情同意、去标识化、访问与保留规则。已有账号数据不因这份方案自动转作研究，也不自动向外部 AI 发送。正式常模需要明确的目标人群与适当样本，不能直接把便利样本的分位当“中国人百分位”。

## 11. 指标与验收目标

以下是建议目标，当前没有实测值的指标全部先建基线。测量事件只包含必要的技术状态；涉及新采集范围时另做数据用途说明。

| 类别 | 指标/验收 | 口径 |
|---|---|---|
| 数据可靠性 | 故障用例中未保存误报为已保存 = 0；单 attempt 重复报告 = 0 | 自动化断言，不用平均成功率掩盖单例丢失 |
| 记录可达性 | 51+ 记录全部可浏览，较旧草稿可发现 | 合成数据验证；包括筛选、删除后翻页 |
| 交互 | 快速改选、断网、409、登录失效、路由离开均有确定反馈 | 两类量表分别验证 |
| 无障碍 | 320/390/1440、键盘、200%缩放、弹窗焦点、无主要遮挡 | 真实浏览器；规范参考 R01/R02 |
| 加载性能 | 参考 p75 LCP ≤2.5s、INP ≤200ms、CLS ≤0.1 | 按移动/桌面分组；R04；实验室结果不冒充真实用户 p75 |
| API | 先记录固定负载下 p50/p95、SQL次数、响应字节和错误率 | 可先以 20 并发用户作场景预算，最终目标依部署资源确认 |
| 测评理解 | 用户能区分参考类型、边界、量程分数和排名 | 试读任务结果，不能以页面停留时长代替理解 |
| 测评质量 | 已审校题目、理解问题关闭率、版本化研究证据 | 不设“出类型率越高越好”的指标 |

## 12. 实施批次与工作量

以下是熟悉本仓库的一名开发者的工程人日粗估，包含定向测试与文档，不是交付承诺；数据库环境、评审等待、研究招募和真实 AI 费用均未计入。不同批次尽量独立发布和回退。

| 批次 | 范围 | 粗估 | 依赖与交付门槛 |
|---|---|---|---|
| A | S01–S04：离页保护、前端幂等、草稿筛选、报告分页 | 5–7 人日 | 定向契约/组件测试与三尺寸模拟接口浏览器验收 |
| B | S05–S08：事务一致性、同步契约、按钮和弹窗统一 | 6–9 人日 | H2 故障注入；真实 MySQL 并发验证需独立目标与授权 |
| C | S09–S15：首页分层、中性分流、拆包、报告操作、时间和死代码治理 | 7–10 人日 | 旧版兼容与导出一致性；测量拆包前后 |
| D | S16–S17、S20：性能基线、必要的查询投影和缓存 | 4–7 人日 | 先证实瓶颈；涉及 schema 时准备增量迁移并审批目标环境 |

工程合计约 **25–38 人日**，单人约 5–8 个工作周；研究不能压缩进这个工程数字。首批不等待新量表或 AI 功能。第二批事务修复也可优先于非关键视觉调整推进。

## 13. 发布与风险边界

- 先补充能够失败的回归用例，再改行为；不能通过降低断言消除问题。
- 后端新增字段/接口先上线，旧消费者继续可用；前端切换后观察，再考虑清理兼容路径。
- 量表内容、scoringVersion、reportContentVersion、哈希绑定保持完整；历史快照不原地重算。
- 若引入摘要投影，投影可重建，报告仍是权威；回退只停用投影读取，不删旧快照。
- 本轮设计不授权迁移、写现有数据库、真实 AI 调用、发布或部署。实施时在具体目标与操作范围内确认授权，普通代码编辑无需重复确认。

建议直接以批次 A 作为首个实施包。它的效果可以通过确定的故障场景验证，也为后续页面与报告改造提供可靠基础。
