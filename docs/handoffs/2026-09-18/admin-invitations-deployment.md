# 管理员、邀请注册与每日 AI 额度

## 已实现的使用方式

- 管理员登录后，从「账号与数据 → 管理后台 → 成员、报告与邀请码」进入 `/#/admin/members`。
- 管理员可查看全站成员的账号状态、注册时间、最近会话活动、测评进度和当时保存的测评报告。最近活动不等于实时在线。
- 报告支持十六型参考结果、倾向较轻、平分及大五五维结果；只读，不重新计算历史报告。普通用户的原有报告接口仍只允许本人读取。
- 注册必须使用邀请码。只有管理员能生成；一码一人，可选未来一年内的过期时间，也可撤销未使用的邀请码。邀请已使用时撤销返回冲突，不能撤销已经发生的注册。
- 完整邀请码仅在生成响应及当前页面内存出现，数据库只保存 SHA-256 校验值。列表不返回码或校验值。遗失后应撤销未使用的旧邀请并重新生成。
- 注册失败会回滚账号创建和邀请码消费；多人并发使用同一码只能成功一个。注销用户不会让已用邀请码恢复可用，注销邀请创建者会撤销其未用邀请并清除身份关联。
- 注册勾选说明和方法隐私页已说明管理员可以查看哪些数据。

## 默认管理员

| 部署环境变量 | 含义 |
| --- | --- |
| `TYPEME_ADMIN_BOOTSTRAP_USERNAME` | 默认 `typeme_admin`；4–32 位字母、数字或下划线 |
| `TYPEME_ADMIN_BOOTSTRAP_PASSWORD` | 由部署方通过安全环境注入，12–72 位可打印 ASCII；无内置默认密码 |

仅当系统没有未删除的管理员，且上述用户名、密码配置齐全时，启动流程会创建首个管理员。初始化不需要邀请码。配置为空不会创建账号；密码以现有密码编码器处理，不记录原文。

已有管理员时不创建第二个、不重设密码。若配置名称已被普通账号占用，则拒绝初始化并提示更换名称，**不会把同名普通账号提升为管理员**。当前配置的管理员名禁止普通注册；默认配置下 `typeme_admin` 为保留名。多实例初始化通过数据库锁串行处理。

部署后用该账号登录，可在账号页修改密码，并生成、保存恢复码。首次初始化完成后应从部署环境移除初始密码配置；保留用户名配置即可。已有账号继续用原密码登录。

## 每日 AI 次数

- 管理员给成员设置整数 `0–10000`；`0` 停止接受新的生成、重新生成及重试请求，不取消已经排队或执行的任务。
- 未单独分配的成员沿用系统默认每日额度；设置后按该成员的额度执行。当前页面提供分配固定额度，不提供恢复继承的操作。
- 额度按 UTC 日期计算，UTC 00:00 重置，即北京时间每日 08:00。生成中的任务也占额度；已用次数按预算预留口径显示。
- 修改额度不会清零当天已用次数；调低到已用次数以下时，剩余为 0。复用已有分析不重复扣次数，重新调用的重试需要再次占额度。
- 单独分配不会绕过全站 AI 开关、总调用/Token 预算、重试频率限制或用户的 AI 外发同意。

## 数据库与上线边界

新增迁移 `backend/src/main/resources/db/migration/V9__invitations_and_user_ai_limit.sql`：

1. `app_user.ai_daily_limit`：可空的每日额度，空值继承默认设置。
2. `registration_invitation`：邀请码校验值、创建者、到期时间、使用/撤销状态。
3. `admin_bootstrap_lock`：序列化初始化的单行锁。

**本轮只在一次性内存 H2 中执行了迁移，没有对现有数据库执行 DDL/DML，也没有创建真实管理员账号或部署服务。** 上线前仍需针对明确的数据库目标授权迁移和初始化写入。不能直接启动后端到现有数据库来绕过此限制。

获得授权后的部署步骤：备份目标数据库并验证恢复方式 → 在受控窗口执行 V9 → 通过部署环境注入初始密码 → 构建前端并打包后端 → 启动、登录管理员 → 验证邀请注册和成员权限 → 移除初始密码环境配置。前端与后端应一起升级，旧注册客户端因缺少邀请码将不能注册。

旧 `scripts/browser-verify-admin.py` 使用「先注册、重启后提权」的历史流程，不再适用本版本。当前浏览器验收脚本为 `scripts/browser-verify-admin-members.py`，只访问静态页面并拦截全部 API，不写数据库。

验证范围及截图见 [验收记录](../../optimization/verification/2026-09-18-admin/REPORT.md)。H2 结果不能替代真实 MySQL 方言、事务和锁验证；本轮未执行真实 AI 请求。
