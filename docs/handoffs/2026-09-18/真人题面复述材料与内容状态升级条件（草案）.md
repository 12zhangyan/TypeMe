## 0. 先分清三件事（否则记录会被误读）

| 事项 | 需要什么证据 | 本材料能提供吗 |
| --- | --- | --- |
| 题面**没有明显误读** | 若干独立被试的复述记录 + 判定 | ✅ 这是本材料的目标 |
| 题面**测量有效**（信度 / 效度 / 常模） | 独立研究：样本量、统计量、可复核数据 | ❌ 复述记录**永远不能**推出这一条 |
| 内容**可对外称已验证** | 上面两条 + 明确的对外口径 | ❌ 本材料只产出"记录"，不产出"声明" |

一句话口径：**复述只能发现"明显读不懂/读反了"，发现不了"测得准不准"。**
当前状态是：题目审校为单人非盲、无信度/效度/常模证据；`contentStatus` 是包**自我声明**的
字段，代码只会在加载时按 `draft_review_pending` 打一条 WARN，不做任何"已验证"背书。

## 1. 材料 A：题面复述脚本（单次会话，约 20–30 分钟）

### 1.1 被试与场次

- 3–5 人即可用来发现**明显**误读；人数再多也只是把同一结论重复几遍，不构成信度证据。
- 独立完成：同场次的人**不互相讨论**、不事后对答案。
- 每人只做一次；**不要**让同一个人做两遍来"确认稳定性"（那是重测信度的做法，需要正规设计）。
- 被试不需要任何心理学背景；相反，**越接近目标用户越好**。

### 1.2 逐字话术（照读，不要临场发挥）

> "接下来我给你看一些问卷题目。这些题我**不解释**，你也不需要回答'你会怎么做'。
> 我只需要你做一件事：读完每道题以后，用你自己的话告诉我**这道题在问什么、两边分别在说什么**。
> 如果你觉得说不清楚，就直接说'说不清楚'，这对我同样有用。
> 我不会告诉你答得对不对。"

关键约束：

- 不解释题意、不举例、不提示"左边是内向"这类方向信息。
- 被试说"我选左边"时，回一句："先不管选哪边 —— 这道题在问什么？"
- 被试问"这是不是 MBTI"时，答："和它同类，但这次的目的是看题面读不读得懂。"
- 不追问到被试说出"你想要的那个说法"为止；被试改口要记为**两次不同复述**。

### 1.3 抽题规则（避免只测好题）

- 十六型：每维 12 道主测题**全部**过一遍；补充题（每维 4 道）只在主测题里出现"含糊/读反"时补测。
- 大五：50 题**全部**过一遍（30 秒/题以内，总时长可控）。
- 顺序：按量表原始顺序，不按维度分组 —— 分组会让被试顺着上一题的读法猜下一题。
- 若时间不够：按"每维至少 6 道 + 随机抽"的方式减量，并在记录里写明**实际覆盖了哪些题号**，
  不能笼统写"抽测了一部分"。

### 1.4 判定分类（四类，互斥）

| 判定 | 含义 | 处置 |
| --- | --- | --- |
| `一致` | 复述出的两端含义与设计意图一致（用词不同没关系） | 记录即可 |
| `含糊` | 说不清两端差别，或被试自己也不确定 | 记录；同一题有 2 人以上判含糊 → 进入待改清单 |
| `读反` | 复述出的两端方向与设计意图相反 | 立即进入待改清单（最高优先） |
| `歧义` | 被试读出了第三种理解（题目本意之外的意思） | 进入待改清单，并写明"读成了什么" |

- **不要**把"被试觉得这题不好答/太抽象"直接判成 `含糊`；单独写在备注里，避免把"题目风格"
  和"题意读不懂"混成一类。
- 判定必须由记录人**当场**写下，不要事后凭记忆补记。
- 设计意图以内容源（YAML）里的 `leftPole` / `rightPole` 与维度定义为准；
  两份意图不一致时先提出来，别当场改题。

### 1.5 会话结束必做

1. 当场与被试确认："我记的是这些，你刚才的意思是这个吗？"（只确认记录准确性，不改判定）。
2. 填完记录表当天归档，写明日期、包版本、覆盖题号、在场人数。
3. 若同一题出现 `读反`：**不**当场改题；改题必须走内容版本流程（新 revision / 新 packageId），
   并重跑 `node scripts/convert-jung-content.mjs --check` 与 `node scripts/gen-jung-fixtures.mjs --check`。

## 2. 材料 B：匿名记录模板

### 2.1 场次头部（每次会话一份）

| 字段 | 填写要求 |
| --- | --- |
| 场次编号 | `S-2026MMDD-01`（自增，不含姓名） |
| 日期 | YYYY-MM-DD |
| 量表 / 版本 | 例如 `typeme-jung48-zh-v1`（**必须写 packageId**，不能只写"新测"） |
| 内容状态 | 记录当时的 `contentStatus`（当前为 `draft_review_pending`） |
| 覆盖题号 | 实际过了一遍的题号清单（或用区间 + 例外清单） |
| 在场人数 | 数字 |
| 记录人代号 | `R1` / `R2`（代号与真人的对应关系**不写进本文件**） |
| 话术偏差 | 是否照读；若有临场加话，写明加了什么 |

### 2.2 逐题记录（每题一行）

| 列 | 取值 |
| --- | --- |
| 场次编号 | 同 2.1 |
| 被试编号 | `P1` / `P2`（**仅编号**，见 2.4） |
| 题号 | 内容源里的题目 id（如 `EI-07` / `BF-E-03`） |
| 维度 | EI / SN / TF / JP 或大五维度 |
| 复述要点 | 被试的**原话要点**（≤60 字，允许口语） |
| 判定 | `一致` / `含糊` / `读反` / `歧义` |
| 歧义内容 | 判定为 `歧义` 时写"读成了什么" |
| 备注 | 迟疑时长、需要复读次数、是否反问 |
| 记录人代号 / 时间 | `R1` / `2026-09-18 15:40` |

### 2.3 汇总（每个包一份）

- 判定计数：`一致` / `含糊` / `读反` / `歧义` 各几题次。
- 待改清单：题号 + 判定 + 至少一个原始复述要点。
- 明确写出的**局限**：人数、是否盲、是否同场互相影响、是否只覆盖部分题。
  例：*"3 人非盲复述，覆盖 48/48 主测题；记录人同时是内容作者，未做交叉复核。"*

### 2.4 脱敏规则（硬性）

- 只保留 `P1` / `P2` 这样的编号；**不写**姓名、手机号、微信、邮箱、账号、IP、单位、城市。
- 不录音，或录音只用于当场转写且**当天删除**；归档文件里不放原始录音路径。
- 不把被试对某道题的**作答倾向**与他/她的身份关联记录（复述 ≠ 作答，更不做个人画像）。
- 记录文件放在本仓库 `docs/` 下的验证目录，文件名不得包含个人信息。

## 3. 材料 C：`contentStatus` 升级条件草案

### 3.1 现状（代码事实，不是判断）

- 枚举只有三档：`draft_review_pending` → `reviewed` → `field_tested`
  （`JungContentStatus`；大五包用的是同一组 token 的字符串字段）。
- 当前所有包都是 `draft_review_pending`；加载时按此状态打 WARN：
  "未做真人试读与试测，没有信度/效度证据，不得对外宣传为已验证"。
- 旧流程（OEJTS/IPIP 内容服务）另有"包声明状态不得高于包内最低证据状态"的一致性校验；
  新测的 `contentStatus` 目前主要是**声明 + 日志**，不是自动门禁 —— 所以升级必须靠人负责。

### 3.2 升级判据（建议，需用户确认后才执行）

| 目标状态 | 最低证据要求 | 谁签字 | 必须留下的凭证 |
| --- | --- | --- | --- |
| `reviewed` | ① 材料 B 的逐题记录，覆盖**该包的每一道题**；② `读反` 清零，`含糊`/`歧义` 均已处置或已改题；③ 记录人与内容作者**不是同一人**（至少一次交叉复核） | 内容负责人 | 场次头部 + 逐题记录 + 汇总；改过的题另附版本差异 |
| `field_tested` | 在 `reviewed` 基础上：④ 对真实目标用户做过**试测**（不是复述），有可复核的作答数据与最基本的分布描述（缺失率、各档使用率、明显天花板/地板项）；⑤ 明确写出**未做**信度/效度分析 | 内容负责人 + 项目负责人 | 试测方案、样本描述（脱敏的汇总口径）、数据文件校验和 |

### 3.3 明确**不能**作为升级依据的情形

- 没有记录，或记录只有开发者的自测感受。
- 只有 AI（模型）对题面做过"复核" —— 那是**生成/改写**证据，不是真人证据。
- 单人非盲复述（当前题目审校就是这种）**可以**支撑"进入待改清单"，不足以支撑 `reviewed`。
- 复述结果 "全部一致" 但样本是内容作者本人或同事。
- 任何把 `field_tested` 说成"已验证信效度"的说法 —— 试测 ≠ 信效度研究。

### 3.4 降级条件（反向也要写清）

出现下列任一情况，应把该包改回 `draft_review_pending` 并重新评估：

- 收到用户反馈指出某题"读反了"或"看不出在问什么"，且有可复核记录。
- 改了题面/极性问题（`leftPole`/`rightPole`）或增删题 —— 旧记录不再覆盖新内容。
- 发现原升级凭证不足（人数、覆盖、盲法任一项不实）。

### 3.5 与产品决定的关系

"是否投入真人验证、投入多少"是**待决事项**（决策清单 §2），本草案**不构成**已决。
在用户明确选择之前：不执行真人会话、不支付被试费用、不改 `contentStatus`。

## 4. 材料 D：最小执行清单（授权后照此做）

1. 选 3 人（非内容作者、非项目成员优先），预约 30 分钟。
2. 打印/打开材料 A §1.2 话术与材料 B 的记录表（空白）。
3. 逐题会话 → 当场填 2.2 → 当场与被试确认记录准确性。
4. 当天填完 2.1 与 2.3，归档到 `docs/optimization/verification/<日期>-jung-item-paraphrase/`。
5. 产出"待改清单"（若有）与一份**只描述过程与局限**的结论，不出现"已验证"字样。
6. 只有在 §3.2 条件全部满足且用户签字后，才**单独**提交一次内容版本变更。

## 5. 复核要点（给下一位读者）

- 本文件任何内容都不得被引用为"真人验证已完成"。
- 记录表里的判定是**记录人的主观判定**，不是测量结论；引用时必须带上人数、覆盖范围与盲法状态。
- 升级 `contentStatus` 是**内容版本变更**，需要绑定新 revision/packageId 与重新生成的哈希，
  不能手改 JSON 里那一个字段就发布。
