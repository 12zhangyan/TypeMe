## 二、Findings

### CR-1 ｜ 计分失败导致不可恢复的页面弹回，用户永远看不到结果

- **来源别名**：R4-1（CR）、R4-4（IM）、R1-5（MI）、R4-7（MI）——同一根因，影响边界不同，合并后取最高严重度
- **定位**：`frontend/src/stores/quiz.ts:104-110`（`isComplete`）、`frontend/src/views/ResultView.vue:41-49,104-112`、`frontend/src/api/client.ts:89-117`（`isValidQuestionnaire`）、`stores/quiz.ts` 恢复逻辑
- **证据**（R4 可复现）：
  - `isComplete` 只判 `typeof answers[q.id] === 'number'`，计分器要求值 ∈ 1..5
  - 手工写坏 localStorage（answers 全为 `9`）→ `isComplete=true` → `ScoringError: 题目 #3 的作答必须是 1–5 的整数，实际为 9` → `ResultView` 的 catch 返回 `null` 并 `router.replace('/quiz')` → 答题页显示 disabled 的「还差 1 题」→ **来回弹，永远看不到结果**
  - `isValidQuestionnaire` 只查 `scoring.constants` 是 object，`constants: {}` **通过校验** → 每个维度都抛错 → 同一弹回
  - `answers: {"1": "3"}`（字符串）被原样接受 → 该题**永久无法"答完"**
- **影响**：数据被写坏（存储篡改、旧版本残留、浏览器同步异常）时核心流程不可用，唯一出路是「重新测一次」
- **修复**：统一"有效作答"口径（值 ∈ 1..5）到 `isComplete`、client 校验、restore 三处；`isValidQuestionnaire` 补 constants 四键 + 有限数值 + 数量一致；`ResultView` 区分"未答完"（replace）与"结构性错误"（渲染错误态 + 重测入口）
- **验证**：补三条单测（越界值 / 坏 constants / 字符串作答），断言**能渲染结果或错误态且不发生 replace**

### IM-1 ｜ 前端内置副本与后端内容源整体分叉，且无任何守卫

- **来源别名**：R4-2（**CR**）、R2-1、R5-1、R5-2、R5-3、R1-4、R3-09
- **定位**：`backend/src/main/resources/content/{questionnaire-quick,types,method}.yml` ↔ `frontend/src/content/{fallback,typeProfiles}.ts`；`scripts/gen-fallback-content.mjs` **不存在**
- **证据**：
  - 题库：逐字相同仅 2–3 题，**30/32 题措辞不同**；`dimension`/`direction` **32/32 一致**（故分数一致）
  - **16 型文案：`nameCn` 相同 0/16、`tagline` 相同 0/16，全部字段不同**（我独立复核）
  - 方法页：后端 4 节 vs fallback 6 节，标题集合不同；`references` **只有 fallback 有**
  - `contentVersion`：后端 `2026-09-01` vs fallback `builtin-2026-01`
  - 守卫为空：无生成脚本、无跨源断言；`fallback.spec.ts` 的关键词表是自指的；后端用 SHA-256 锁死 YAML 但 fallback **无绑定**
- **影响**：用户看到的题目、类型名、人格解读、合规声明**取决于后端当时是否可达**；下一次改内容只能改一边，且没有测试会红
- **修复**：落地 `scripts/gen-fallback-content.mjs`，从后端内容**单向生成**三份前端副本并纳入 build；加跨源一致性测试（逐字段含文本）
- **验证**：故意改后端一处 → 测试必须红
- **严重度分歧记录（不静默换号）**：R4 判 **CR**（用户可见且用户无法自行修复）；R2/R5 判 **IM**（计分语义零差异、不会算错分）；R1/R3 判 **MI**。**本聚合采纳 IM** —— 按 Critical 定义（数据错误 / 核心流程不可用）不成立：分数与类型均正确。**若你更认可 R4 的判断，可提升为 CR-2。**

### IM-2 ｜ 分享/下载失败时静默无反馈（**已因范围变更降级为 MI**）

> ⚠️ **范围变更后的重新定级**：原判 IM，前提是"微信内 H5 无法唤起朋友圈分享，保存图片是唯一裂变主路径"。
> **现已去微信化**（改为普通网页访问 + PC/手机响应式），该前提不再成立，**降级为 MI**。
> 但**"失败静默无反馈"本身仍是真实缺陷**，修复要求保留。

- **来源别名**：R4-3
- **定位**：`frontend/src/views/ResultView.vue:128-138`、`frontend/src/utils/shareImage.ts:307-317`
- **证据**：`saveToAlbum` 只在 `downloadShareCard` **抛错**时才打开降级预览；而 `<a download>` 的常见失败方式是**静默无效**（不抛错）→ R4 mock 后断言预览**未**打开、页面无任何"失败/重试"字样
- **影响**：用户点「保存图片」后页面毫无反应，会以为坏了
- **修复（按新范围调整）**：下载后**无条件**给出可见结果；手机优先 `navigator.share`（Web Share API），**不可用时降级为打开图片供长按保存**；canvas 失败要有提示
- **验证**：mock 静默失败后断言出现可见反馈

### IM-6 ｜ PC 桌面布局完全缺失（**范围变更后的一等需求**）

- **来源别名**：R6-1（**CR**）、R6-2（**CR**）、R6-7（MI，字号部分）
- **定位**：全部 `frontend/src/views/**`、`components/**`；`frontend/tailwind.config.js`
- **证据（headless Chromium 实测，非读码推断）**：
  - 静态 class token **947 个，带断点前缀仅 16 个（1.7%），且 100% 是 `sm:`**；无 `md`/`lg`/`xl`
  - 产物 CSS 中 `@media` 共 5 处 = 4×`min-width:640px` + 1×`prefers-reduced-motion`；**无任何 ≥768px 的断点**
  - 1280px 与 1920px 下 `main` **都是 608px**，字号与间距逐字节一致 → **≥640px 渲染完全相同**
  - `/quiz` @1920×1080：题卡 576px，占视口宽度 **30%**，**下方 620px 全空**（68% 宽 / 79% 面积留白）
- **影响**：直接违反已更新的 `需求文档.md` F-02「**PC 必须有独立的桌面布局**」
- **修复**：补 `md:`/`lg:` 断点；答题页 PC 改为居中卡片（限宽 + 上下留白收窄）或一屏多题；正文与辅助字号、CTA 尺寸随断点提升
- **验证**：在 1280 / 1920 两个视口断言题卡占视口宽度比例下限；补桌面断点断言（现有 `views.spec.ts` **无任何断点断言，只在 375 宽度语义下跑**）
- **严重度分歧记录**：R6 判 **CR**；本聚合采纳 **IM** —— 按 Critical 定义（数据错误 / 核心流程不可用 / 安全 / 生产事故），PC 上「答题→出结果」核心流程**可用**，属需求未满足。**降级只影响排期优先级，不影响"必须修"。**

### IM-7 ｜ 分享流程未按新 F-04 实现，且失败/成功均无反馈

- **来源别名**：R6-3（**CR**）、R4-3（已因范围变更降为 MI，其"无反馈"部分并入本条）
- **定位**：`frontend/src/utils/shareImage.ts`、`frontend/src/views/ResultView.vue`
- **证据**：① 全前端 `navigator.share` / `canShare` **grep 零命中** → 新 F-04「手机优先 navigator.share」**未实现**；② 实测点「下载这张图片」后 `textChanged:false`、无 toast → **成功时零可见反馈**；③ 结果页文案仍是微信专属（「微信内置浏览器里没法直接唤起…」），去微信化后**已过时且 PC 上语义不通**；④ 文案写死「保存图片到相册」，PC 上是 Downloads
- **影响**：分享是产品主要传播路径；用户无法确认是否成功，且 PC 用户读到错误的环境说明
- **修复**：实现 `navigator.share` 优先 + `canShare` 检测 + 降级；成功/失败都给可见反馈；文案按环境中性化（「下载 / 分享图片」），去掉微信专属表述
- **验证**：mock 成功与静默失败两种路径，断言均出现可见反馈

### IM-8 ｜ PC 键盘可用性与交互模型（交互仍为移动端推导）

- **来源别名**：R6-5（IM）、R6-4（IM）
- **定位**：`frontend/src/components/LikertScale.vue`、`frontend/src/views/QuizView.vue`
- **证据（实测键盘时间线）**：数字键 1–5 可用、有选中时 Enter 可用；但 **新题未作答时 Enter / ArrowRight 完全无反应且无任何反馈**；数字键选择后 **DOM 焦点始终在 BODY**，自动跳题后焦点丢失；容器是 `role=radiogroup` 却**无 roving tabindex、无组内 `@keydown`** → 违反 radiogroup 键盘约定。交互上「选中即 240ms 自动跳题」为移动端推导，桌面无确认/下一题优化
- **影响**：桌面用户（尤其键盘/无障碍用户）难以完成测评
- **修复**：补 roving tabindex + 组内方向键；未作答时给出反馈而非静默；PC 端提供显式「下一题」；焦点管理归还
- **验证**：补键盘路径用例（当前 `views.spec.ts` 无任何键盘断言）
- **注**：Tab 到选项后空格是否激活，Chrome 下按钮对纯 Space keyDown 不激活，**需真机确认**

### IM-3 ｜ 缺前端产物，SPA 回退在真实形态下 404

- **来源别名**：R3-01、R4（`GET /quiz` → 404）
- **定位**：缺 `backend/src/main/resources/static/`；`backend/pom.xml:34-59` 无搬运步骤
- **证据**：用**不含 test-classes** 的 classpath 启动真实上下文 → `/`、`/quiz`、`/result`、`/about`、`/assets/*.js` **全 404**，而 `/api/v1/meta` 200；测试全绿是因为 `src/test/resources/static/index.html` **夹具把问题盖住了**
- **影响**：ADR-5「一个进程同时提供页面和 API」目前**不成立**，IP:8080 直接访问得到 404。部署本不在本次范围，但这是 build 缺口而非部署步骤
- **修复**：maven 资源插件把 `frontend/dist` 复制进 `target/classes/static`；补一条**不带夹具**的集成测试断言 `/` 返回真实 index.html
- **验证**：去掉夹具后 `/` 仍 200 且返回真实产物

### IM-4 ｜ 计分归一化的「由题库推导」性质没有回归防线

### IM-5 ｜ 许可声明措辞不实，且与同一页面另一段自相矛盾
