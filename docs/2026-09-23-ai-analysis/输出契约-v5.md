# AI 引导分析输出契约

## 版本和输入

- 提示词：`typeme-ai-prompt-v5`；输出：`analysis-guided-v3`；发送范围仍为 `typeme-ai-scope-v3`。
- v3/v4 提示词继续使用 `analysis-readable-v2`；v1/v2 与其旧输出继续可读。旧文件未修改，旧任务创建、重试时仍绑定自己的提示词与报告 hash。
- 输入为所选固定报告维度摘要、结果状态、主题和最多 300 字主动自述；不增加原始答案、账户标识或其他报告。
- 新输入中的 `usableEvidenceIds` 从已有维度派生：大五要求 `hasResult=true`；十六型要求有有效作答数与数值摘要。平分仍可用于观察两种情境，不能据此选边。没有方向证据的维度仍随报告发送，以说明局限，不能支撑个人结论。

## 输出字段

所有对象禁止额外字段，长度按 Java/JavaScript 字符串长度校验。所有文本为纯文本，页面不把模型输出作为 HTML。

| 字段 | 约束 | 用途 |
| --- | --- | --- |
| schemaVersion | 固定 analysis-guided-v3 | 按任务版本检查，不接受模型自行降级 |
| referenceType | 与固定报告严格一致；大五和平分为 null | AI 无权改判 |
| summary | 1–240 字 | 回应主题/问题并交代边界 |
| observations | 0–3 条 | 只解释相关发现；通常两条已足够 |
| observation.title | 1–36 字 | 每条发现的独立标题 |
| observation.plainText | 1–220 字 | 报告证据与情境解释 |
| observation.example | 1–160 字 | 明确为假设的场景；不编造经历 |
| observation.checkQuestion | 1–100 字 | 邀请找出符合或相反的例子 |
| observation.evidenceIds | 1–8 个，不重复 | 必须在本次 usableEvidenceIds 内 |
| suggestedAction | 一个对象或 null | 无可用发现时不强行生成行动 |
| action.what / when | 各 1–120 字 | 具体做法、触发场景和低成本时长 |
| action.why / observe | 各 1–160 字 | 承接发现的理由、可见信号和停止条件 |
| action.evidenceIds | 1–8 个，不重复 | 必须被前文某条发现引用过 |
| limitations | 1–4 条，各 1–180 字 | 本次特定的不确定性，避免重复免责套话 |

结构真源：`backend/src/main/resources/ai/schemas/analysis-guided-v3.json`。后端拒绝缺字段、伪造/重复证据、无发现支撑的行动、改类型和截断结果；前端再次检查结构并把无法解析的问题显示给用户。

## 页面和任务语义

- 引用显示为本报告维度的中文名称，内部 ID 不进入普通界面。场景、核对问题、理由、做法、时机与观察分别呈现。
- 编辑主题或近况会撤销已勾选的发送确认；近况只保留在当前面板会话内。
- 相同报告、主题、近况与版本命中服务端去重。显式再次生成可重排原任务，并占一次额度；改主题或近况会另存任务。
- 重排期间保留旧成功正文并明确标记；成功后替换，失败后仍保留。AI 关闭或状态读取失败不遮住已经生成的分析。
- 请求状态绑定面板生命周期，离页、换报告、重新进入同一报告后拒绝旧请求回写；另一个标签页已重排时接上轮询。

## 上线和验证边界

前后端需要配套发布。配置明确固定 v4 的环境不会自动改成 v5；新建任务切换 v5 后生效，旧任务不会重新解释成新版。无需数据库迁移。

自动测试证明结构、版本、数据范围和状态语义。没有真实模型调用或真人审校，不能把格式通过等同于分析准确；提示词对“自述是背景、假设要明示”等语义的约束仍需真实样本审阅。
