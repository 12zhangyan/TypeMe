# AI 分析改造方案与验收

日期：2026-09-23。范围：两项登录测评的可选 AI 分析，包含提示词、输出校验、前端呈现和生成状态。

## 现状证据

- 当前默认 v4 输出 `analysis-readable-v2`，最多两条没有标题的观察。前端解析时丢弃 evidenceIds，把示例拼入正文、行动的做法/时机/观察混成编号列表，用户难以核对分析依据。
- 输入仅为所选报告的维度摘要、主题和最多 300 字自述。自述不是测量证据，不能据此改判类型。大五没有类型码，信息不足、平分和轻微倾向须区分。
- AiAnalysisPanel 提交后无论成功失败都会关闭表单；v3Ai.readJob 只解析 SUCCEEDED 的正文，重试失败或进行中时丢失服务端保留的上次结果；AI 关闭还会遮住历史分析。
- store 的状态请求没有失效检查，创建/重试仅检查 reportId，离开后回到同一报告会存在迟到响应写入的风险。
- 改前定向基线：前端 AI 三组测试 48/48 通过，说明以上路径尚缺回归覆盖。

## 实施设计

1. 新增 typeme-ai-prompt-v5 + analysis-guided-v3。保留 v1–v4 原文件、旧任务绑定与旧输出解析。新版最多三条发现，每条包含短标题、证据解释、假设场景、核对问题与证据引用；给一个行动，分清理由、做法、触发时机和观察信号。没有证据时允许空发现和空行动，不为填满页面编造。
2. 继续使用 typeme-ai-scope-v3，不新增外发的个人信息。根据固定报告标注可用于解释的维度，校验拒绝用大五无结果维度支持个人结论。对旧快照不重新计分；十六型平分保留 null，轻微倾向不包装成确定人格。
3. 生成表单增加主题对应的自述引导和字数反馈；分析正文展示真实引用的维度名称、独立场景和核对问题，行动按含义分组。历史结果在服务关闭、状态请求失败和重新生成期间仍可读。失败保留表单和已填内容，重试清楚说明额度与原请求范围。
4. 异步响应绑定面板生命周期，防止卸载、换报告及返回同一报告后串写状态；保留请求时的主题和内容，不在返回时读取变化中的表单。

## 边界与兼容

- 不改固定计分、题库、量表许可、报告快照、数据库 schema、认证归属、CSRF、额度或幂等规则。不自动重发 UNKNOWN 任务。
- 管理员/环境显式固定旧提示词版本时继续生效；默认配置升级不等于运行服务已升级。旧任务重试仍使用原输入与版本。
- 模型文本仍是待核对的解释。结构校验和模拟测试不能证明真实模型的心理学有效性、语义可靠性或真人体验。
- 不将补充问题写入日志或浏览器持久化。此次验收采用合成报告和 mock，不需要传输真实用户数据。

## 验证计划

- 纯逻辑/内存 H2：新旧版本、两量表、信息不足、平分、伪造证据、结构字段、类型改判、任务执行链与归属。
- 前端：结构解析、证据展示、失败保留正文与表单、额度/加载/禁用状态、迟到响应和重复操作。
- 类型检查、前端完整测试与构建；后端排除三类真实 MySQL 测试的子集。
- 真实 Chromium：320/390/1440 宽度，合成报告、网络接口模拟；覆盖键盘操作、滚动/溢出、确认、失败/重试、历史与关闭状态，保存脱敏截图。
