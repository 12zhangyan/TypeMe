# 验收标准与交付模板

日期：2026-09-23。用于后续前端实施；**本清单不是本轮方案交付已经通过的测试结果**。本轮实际证据见 [evidence/README.md](evidence/README.md)。

## 1. 必须分开的四类结果

1. 源码/单元测试：证明处理规则、组件与给定测试的行为。
2. 隔离浏览器：证明当前构建或源码在合成场景里的展示、操作和响应式表现。
3. 构建产物：证明本次前端可以编译，并核对生成资源；Maven 不会代构建前端。
4. 真实服务/数据库/AI：需要对应授权和单独证据；前三类通过不等于这一类通过。

文案减少、页面变漂亮也不等于测量效度提升或转化率提升。没有真实行为数据就不报百分比业务收益。

## 2. 视口、数据与对照方法

每个实际修改的页面至少用 **320×720、390×844、1440×900** 检查。补充一次 200% 浏览器缩放与纯键盘主流程检查；响应式模拟不等同于真机 Safari/微信内置浏览器测试。

前后对照必须使用同样的合成数据、状态、字体、默认展开状态与视口，记录 commit/未提交 diff 和服务地址。所有 API 请求必须在受控 mock 中闭合；未定义请求应显式失败，不透传到现有后端。默认禁止通过真实接口注册、生成草稿、保存答案、提交、生成 AI、删除。

需要的样例：匿名、模拟登录有/无草稿、草稿读取失败；十六型正常/略偏/平分；信息不足的返回流程；大五完整/部分无方向/旧范围异常；长中文；AI 关闭/等待/失败/结果未知/成功 mock。

首页题数/时长在合成样例中只能作为布局数据，不能当成真实产品数值来源。目录生产值应来自接口字段，不能抄本轮 fixture 的固定时长。

## 3. 页面与交互矩阵

每项记录 `PASS / FAIL / NOT RUN / N/A`、证据路径和简短说明。N/A 必须与本轮改动范围有关，不能用来躲避相关失败。

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | 首页首屏 | 390px 下看到产品用途、两项量表名称/差别与主行动；不以缩小字号或裁切达标 |
| A02 | 首页主要选择 | 完整选择区前置；动态题数/时长正确；无虚构人数/准确率 |

| A04 | 续答 | 真实模拟草稿进入原 attempt；未知/失败不当成无草稿，不多建空草稿 |
| A05 | 登录前了解 | 目录与方法可访问；开始时按当前规则进入登录，回跳保留量表选择 |
| A06 | 邀请注册 | 邀请码要求明显；输入/错误/提交态准确；不偷偷增加邮箱或匿名模式 |
| A07 | 恢复码 | 一次展示/一次使用/替换后果清楚；既有确认动作完整；证据不含真实码 |
| A08 | 双题型 | 十六型左右五档和大五符合五档各自正确，未知与中间档独立 |

| A13 | 补充/信息不足 | 十六型最多规定补充题；大五无补充；信息不足不显示有效报告 |
| A14 | 提交幂等 | 重复点击/响应丢失使用既有幂等语义，不出现重复报告 |

| A16 | 报告概览 | 去重复身份、短说明、少占高；同样例目标较基线缩短约 30%，不截结果 |

| A21 | 历史列表 | 原有筛选分页、打开与两类报告分流正确；空态/失败有清楚下一步 |

## 4. 文案专项验收

### 4.1 判断一段话是否该存在

逐段问：它改变用户当前的选择吗？不读它会有实际误操作吗？别处是否已经说过？能否用标签/按钮/状态直接表达？

如果四个问题的答案都不支持保留，直接删，不要求新增帮助弹窗。与用户无关的“服务端、快照同源、不可逆校验值”等技术叙述从普通操作区移除。

### 4.2 统计方式

- 用“说明性文字”作为统计对象，排除题干、固定结果、量表名称、动态数值和必须完整保留的许可文本；前后使用相同范围。
- 统一按去掉空白后的字符数计数，中文、字母、数字、标点都算字符；注明范围，别把一版计算按钮、另一版排除按钮。
- 分别报告：删除的重复文字、缩写减少、移到按需区的文字。**折叠不计作真正删除。**
- 首批综合目标为默认可见说明性字符减少约 30%–50%，不是每页强制减半。已经短的页面不必为了指标删必要信息。
- 每页至少给 3 处真实改前/改后或删除示例；字数减少但更难懂不算通过。

| 页面/状态 | 改前字符数 | 改后字符数 | 真删除/缩写 | 仅按需隐藏 | 必要提示是否保留 | 证据 |
|---|---:|---:|---|---|---|---|
| 首页正常 | 待实施记录 | 待实施记录 | 待填 | 待填 | 双量表区别 | 待填 |
| 登录正常 | 待实施记录 | 待实施记录 | 待填 | 待填 | 注册入口/回跳 | 待填 |
| 答题正常/失败分开 | 待实施记录 | 待实施记录 | 待填 | 待填 | 未保存/冲突 | 待填 |
| 报告外围三状态分开 | 待实施记录 | 待实施记录 | 待填 | 待填 | 不确定性/范围 | 待填 |
| 账号普通/危险状态分开 | 待实施记录 | 待实施记录 | 待填 | 待填 | 删除对象/后果 | 待填 |

禁止用空白值写“通过”，禁止把本表里的待填当作已经完成的成绩。

## 5. 命令与副作用

文档阶段只检查内容、路径、生成的证据文件及 diff，不必执行整套业务测试。

实施阶段先确认当前依赖环境和测试脚本，再按改动范围选命令。`npm test`/`build` 有旧内容生成前置脚本，应先留只读基线。以下均在仓库根或明确给出的目录执行，不暗中启动后端。

```powershell
# 仓库根：先保护已有工作并检查生成内容基线
git status --short
git diff --stat
node scripts/gen-fallback-content.mjs --check

# 如果涉及新测内容或共享夹具，再按 AGENTS.md 核对对应生成检查；
# 纯 UI 不应为了此次改版更改内容包。

# frontend 目录
npm.cmd run typecheck
# 可先运行实际相关的已有测试；以下只是入口示例：
npm.cmd test -- src/views/reportV3View.spec.ts src/components/aiAnalysisPanel.spec.ts
# 全套共享样式/主流程落地后运行完整前端测试与构建：
npm.cmd test
npm.cmd run build
```

只运行了相关测试，就只说相关子集通过。`npm.cmd run build:only` 不是 typecheck/test 的替代。构建生成无关文件变动时先比对来源，不使用 reset/checkout 丢弃用户工作。

后端没有改动无需运行 Maven。确实新增后端工作时先按项目要求确认范围和隔离，再用项目明确允许的测试子集；**默认不执行建库删库的 MySQL 测试**。

现有浏览器脚本的名字不能证明它安全：例如 `browser-verify-platform.py` 具有注册/答题流程；运行前必须阅读并确认 API 拦截与目标。不能直接对默认 8080 执行现成脚本来“快速验收”。

## 6. 性能与资源

本轮没有性能数值基线，不写“Lighthouse 100”或“加载快 X%”。实施者在同一模式、机器和网络下记录改前/改后，再判断有无新增负担。

- 不新增 UI/图表/动效依赖，不引入大字体或整套远端插画。
- 首屏只优先加载必要图片，非首屏遵循现有懒加载；检查尺寸预留和 fallback 是否引起布局跳动。
- 若修改图片加载或目录展开，应检查冷加载、图片失败和 reduced-motion。
- 记录构建资源差异与实际浏览器异常；没有测量就标未测，不凭视觉流畅断言性能提升。

## 7. 可选真人验证

页面技术验收之后，可以邀请小范围目标用户完成：辨别两项测评、恢复草稿、区分中间档与说不好、理解略偏/平分、找到自己的报告。观察需要解释多少次、在哪里犹豫；使用合成案例，不要求外发个人答案。

这是后续验证建议，当前没有真人结果，不用 5 个测试者之类的小样本宣称心理测量有效。

## 8. 实施交付模板

```markdown

日期 / 源码基准 / 本轮阶段：

- 修改了哪些页面/组件，解决哪个具体问题。

- 删除/缩写/按需三类的改前改后例子与字符统计。

## 浏览器
- 320 / 390 / 1440 对照图及对应状态。
- 布局数据、键盘/缩放/主要动作结果。
- 夹具缺失与真实未执行的场景。

## 自动验证
| 命令 | 退出码 | 结果 | 证据文件 |
|---|---:|---|---|

## 完成矩阵
- A01…A28：PASS / FAIL / NOT RUN / N/A + 理由。

## 文件与剩余事项
- 本轮文件列表；用户已有工作是否受到影响。
- 未覆盖风险；下一阶段可执行事项。

```
