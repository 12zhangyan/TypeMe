**推荐交接方式：**让有仓库访问能力的 AI 先读取本目录，复制提示词文件里的“整套实施总提示词”，按阶段 0 → 6 分步实现；每阶段留下 diff 和实际验证记录。上下文不足时，使用同文件的“续作提示词”。若只做第一批，优先完成阶段 0、1、2、4，并在阶段 6 中验收其影响范围。

这些提示词不是同时派出多位 AI 的指令。多个 AI 接力时，同一时间由一位负责共享文件，尤其是 `App.vue`、`style.css` 和 Tailwind 配置。后续 AI 从上次的交接记录继续，不从头重写页面。

## 最值得先做的事

1. **文案减重与纠错。**真正删除空泛、重复、实现层解释；必要提示一句话说明。修正账号页“单份报告不能删除”的过时说法，核对隐私措辞与权限事实。
2. **首页提前说明两种测评有什么不同。**当前主按钮已在手机首屏内，但 390px 视口下第一项测评标题约在页面纵向 1625px；增加靠前的精简选择区，缩短装饰段落和大图占位。
3. **报告先给容易理解的摘要。**当前十六型合成报告的概览在 390px 下约高 1263px。保留结果状态与必要解释，缩小类型码、移动人物插画，统一双报告的阅读与操作层级。
4. **保持保存、冲突、会话反馈真实且明显。**已有能力主要做呈现优化；不替换计分和保存逻辑，不为视觉统一抹平两个量表的差异。

这些尺寸来自[原始布局记录](evidence/layout-baseline.json)，仅反映本次合成数据、Windows 字体与 Chromium 环境，不能当作线上转化率或真实用户行为结论。

## 当前业务口径

以 `README.md` 顶部和当前源码为准：平台已有登录版十六型与登录版大五两条主流程；注册使用邀请码；公开量表目录和方法页可在登录前查看。旧的本地 IPIP/OEJTS 流程保留兼容。双量表区分必须贯穿首页、答题、报告、历史、分享与页脚。

本次实际查看 6 个竞品的公开页面；本地以当前源码、只读合成 API 查看首页与两种报告，并在 320 / 390 / 1440 宽度记录截图和布局。没有进入竞品付费报告，没有提交竞品问卷，没有运行 TypeMe 真实账号写入流程或真实 AI。文档里的新增设计是待实施建议，不是已经验收的成果。
