# TypeMe 前端优化方案

日期：2026-09-23。状态：待实施设计方案。结合竞品公开页面、当前源码与隔离浏览器基线，并纳入用户明确要求：**现有页面解释过多，需要真正精简，不必把所有事情都讲给用户。**

## 1. 本轮方向与边界

目标是让用户更快选到测评、顺畅作答、看懂结果。保留已有暖白、森林绿和原创插画，减少首屏装饰占高、重复身份信息、操作旁的长说明和遍布全站的同类声明。

优先级：**纠正错误文案 → 删除无用/重复文案 → 提前主要内容 → 改善交互与视觉一致性 → 验收。**简化不能只靠缩小字号、隐藏按钮或折叠所有段落。

本轮可以直接改页面标题、导航、按钮、引导、重复声明和说明性文字。题干、评分锚点、计分规则、固定报告快照与内容包结论不属于任意润色对象；涉及这部分应遵守版本契约，不因“更短”修改已绑定结果的含义。

默认只动前端展示、必要的组件交互与相应验证；维持 Vue 3 / TypeScript / Pinia / hash 路由。无新增量表、付费墙、社交匹配、匿名答题、数据库迁移或新的 AI 调用。本轮不改管理员业务和旧量表业务；共享样式变化需要对它们做回归观察。

## 2. 三条体验原则

1. **先给任务，再给说明。**页面先出现用户要选、要答、要读的内容。一个模块一个标题、一个主要行动，说明必须服务当前决定。
2. **只说一次，在需要的地方说。**普通报告边界集中说明；平分、未保存、删除不可恢复等当场提示。不要首页、卡片、结果、分享、页脚逐段复述同一套长话。
3. **主流程简洁，细节可以找。**“怎么计分”“内容依据”“数据处理”可在方法页查看；“revision、服务端重算、快照同源”等实现说明留在开发文档。不要为删除的废话再做更多帮助弹窗。

具体删改见[文案精简与逐页改写](03-文案精简与逐页改写.md)。它与本文件共同约束实施。

## 3. 信息架构

保留当前路由，不另外构建一套导航体系：

| 用户任务 | 现有位置 | 调整要点 |
|---|---|---|
| 了解并选择 | `/`、`/instruments` | 首页概览，目录完整选择；两项量表同等清楚 |
| 看方法 | `/instruments/:slug/method`、`/about` | 方法与边界集中承载，不在每张卡片重复 |
| 登录/邀请码注册 | `/login`、`/register`、`/recover` | 表单优先；解释短；保存既定回跳 |
| 继续/开始作答 | `/assess`、`/assess/:attemptId` | 优先续答；分别保留十六型与大五题型 |
| 读报告 | `/reports/:reportId`、`/reports/big-five/:reportId` | 共用阅读层级、不同结果模型 |
| 回访 | `/reports`、两种 compare 路由 | 保留筛选分页；只同量表比较 |
| 管理账号 | `/account` | 资料、安全、数据三组；纠正过时删除说明 |

顶栏建议“测评 / 我的报告 / 关于 / 账号”，Logo 返回首页；登录前显示登录入口。使用已有权限与会话判断，不新增后端菜单系统。窄屏可将低频操作收进可键盘操作的菜单，不能用极小字号挤入同一行；新菜单必须验收展开、关闭、焦点返回。

## 4. 视觉规格：延续现有风格，改善密度

### 4.1 颜色与排版

以 `frontend/tailwind.config.js` 的既有 token 为唯一来源。下表是已存在颜色及使用建议，不新增另一套相近颜色。

| 项目 | 建议 |
|---|---|
| 页面底色 | `paper`：`#F7F8F2`，不再给每一段包大色块 |
| 正文 | `ink`：`#20372F`；次级 `ink.soft`：`#43574A` |
| 主行动 | `primary.600`：`#2D6652`；每个主要视区一个填色主按钮 |
| 不确定/注意 | 既有 `accent`；用于略偏、冲突待处理等有具体含义的状态 |
| 错误/危险 | 既有 `danger`；不把普通参考声明渲染成警告 |
| 标题字体 | 沿用本地中文展示字体；宋体用于品牌/章节，大段正文和表单保持易读无衬线 |
| 正文字号 | 手机 16px 起，长文行高约 1.65–1.8；辅助文字通常 13–14px |
| 页面标题 | 手机 28–34px；普通桌面页 36–44px；首页展示标题约 48–64px，不沿用上百像素的占高 |
| 章节标题 | 手机 20–24px，桌面 24–28px；不在一张卡里连续放多个同等大标题 |
| 间距 | 优先使用现有 8/12/16/24/32/48px 档位；删除过量空白和重复容器内边距 |
| 控件 | 主要按钮高 48px 左右；主要触控目标至少 44 × 44px，选项清楚显示已选状态 |

这是项目设计目标；更大字号和系统缩放下仍应自然增长。不得使用固定高度裁切真实文本。

### 4.2 布局与图像

- 复用 `PageContainer.vue` 按首页、答题、结果、文章区分宽度。桌面首页不把内容横向铺满；报告正文目标约 680–760px，目录可保留侧栏。
- 手机左右边距通常 16px，320px 时结合现有容器校正；按钮可换行，不能靠缩到 11px 解决拥挤。
- 首页保留一幅主插画，手机建议约 160–220px 高，排在清楚的产品说明和主行动之后；不要先让用户滚过一整张海报才知道有哪些测评。
- 测评卡片先标题/差别/投入，插画降为辅助；首页人格图鉴下移，不让它比双量表选择更突出。
- 报告人物插画移至摘要之后的低优先位置，或桌面小幅辅助；报告不是人物海报。
- 沿用 `IllustrationFrame` 的远端/本地/兜底逻辑。不要绕过资源映射、热链竞品图片、安装图标库或引入在线字体。
- 只保留 120–200ms 的交互反馈；尊重 reduced-motion。不做滚动劫持、自动轮播和答题庆祝动效。

### 4.3 组件边界

优先调整现有 `PlatformIntro`、`InstrumentCard`、`PageContainer`、`DimensionMeter`、`FormErrorNotice`、`ConfirmDialog`、`AiAnalysisPanel`，不要先造“大而全设计系统”。

两处以上确有重复时再提取报告工具栏、简短状态行或问题导航组件；十六型和大五的数据准备仍在各自 view/store。公共 CSS 修改必须检查登录页、旧 `/quiz`、`/result` 与管理员页面，不新增全局通配覆盖。

## 5. 首页与测评选择：先告诉用户能做什么

### 5.1 首页推荐结构

```text
顶部：TypeMe                 测评 / 我的报告 / 账号

了解你的性格倾向
十六型看偏好，大五看五个方面。
[选择测评]  [继续上次测评，仅在确有草稿时]

十六型人格参考测评              大五人格倾向测评
四个方面的偏好                  五个方面的倾向
动态题数 / 时长                 动态题数 / 时长
[开始或登录后开始]              [开始或登录后开始]

报告长什么样（两种示例，明确“示例”）
可选浏览：十六型人物图鉴
页脚：方法与隐私 / 结果仅供自我探索参考
```

- 用一句直白标题替代层层情绪铺垫；现有手记气质由配色、版式与插画承载，不依赖多段“探索/向内/生长”。
- 删除同一屏重复的英文装饰标语、编号、宣言与介绍段。阅读路径压成一行或删除，因为按钮与页面已经表达流程。
- 在主按钮附近呈现两项测评名称及区别。可以是紧凑选择区，后面完整卡片无需再重复全部信息；若直接用紧凑卡片完成选择，就不再复制第二套大卡片。
- 卡片题数、时长来自目录字段，不写死本地样例的“10 分钟”。目录不可用时展示重试，不制造一个可开始的假目录。
- 未登录可看目录和方法；开始操作沿用当前守卫。邀请码要求在注册入口附近简短说明，无需首页放一大段注册规则。
- 草稿读取错误提示紧靠续答位置，短句 + 重试。不能把“暂时不知道有没有草稿”表现成“没有草稿”。

### 5.2 报告预览

首批可以用只展示布局的自家示例小图/示意组件，不新增路由和后台能力。每个预览有“报告示例”标识；选用合成夹具，不能展示真实用户数据或编造“很准”的推荐语。不要在首页先生成 AI 分析来吸引用户。

两类产出分别说明：十六型“参考类型与四维偏好”，大五“五维倾向”。大五预览不能借用人物类型码。

### 5.3 可验证目标

在默认字体、正常加载的基线样例下，390 × 844 首屏能看到产品用途、两项测评名称/差别和主按钮；完整卡片无需全部塞进首屏。第一张完整选择卡尽量在 Y ≤ 1000px 开始，1440 × 900 下选择区标题进入首屏或紧接首屏。320px 和放大文字时优先可读与可操作，不硬裁切以满足高度。

## 6. 登录、注册与恢复：只解释当前决定

- 登录页：标题“登录”，最多一句“登录后可保存进度和报告”，随后即表单；大插画缩小或移到桌面侧栏。
- 注册页：标题“创建账号”，一句“注册需要邀请码”；邀请码字段旁“向管理员领取”即可。格式规则在必要时提示，避免每个字段默认展示规则长文。
- 恢复码：保留只显示一次、每码一次、新码替换旧码等后果；删掉哈希和服务器保存方式。既有确认动作和防误离开保留。
- 错误：优先具体字段和可执行动作。用户名/密码错误的现有安全语义保持，不通过更详细文案暴露账户存在性。
- 认证成功回到原量表/草稿/报告，不改站内回跳校验。字段 label、autocomplete、错误关联和提交防重复均需保留。

## 7. 答题：让题目和选择成为主体

### 7.1 共同骨架

```text
测评名称             主测 12/48 · 已保存
[简洁进度条]

当前题目 / 场景
十六型：两端陈述 + 五档位置
大五：一句陈述 + 五档符合程度
[说不好，独立按钮]

[上一题]                         [下一题]
                              保存并退出
```

- 保留一屏一题和明确“下一题”动作，不默认自动跳题；不改键盘快捷键已有语义。
- 首次开始可用一句“按平时的自己回答”；后续题目不要反复展示“没有对错/不要选应该/都算处理过”等教导。
- 每题保留必要的评分含义和题面，删掉无关的量表介绍、开发解释、冗长答题状态句。
- 主测与补充题分别计进度，不在第一题伪装成固定 64 题；大五始终没有补充题。
- 桌面也先看到题目；题号导航和粗略倾向作为次级可达项。不要新增持续吸引注意的实时类型预测。
- 底部操作栏优先普通布局；只有实测需要时才 sticky，并给正文预留实际空间、处理安全区和键盘，不能挡住最后一档或错误反馈。

### 7.2 两类题型

十六型：左右陈述与五档必须一一对应。320px 下可让陈述上下排，但必须用固定“A/B”或两侧标签保持映射；不能把左右颠倒而不改标签，不能改极性。五档尽可能等宽，选中有文字/勾选/边框，不只靠颜色。

大五：五档符合程度按既有锚点呈现。不要画成五星好评或合并到双极题面。“说不好”独立于中间档；未选任何项也独立于“说不好”。

### 7.3 保存与异常状态

| 状态 | 首层呈现 | 操作 |
|---|---|---|
| 无待同步改动且服务端已确认 | 已保存 | 无需解释存在哪里 |
| 正在保存 | 保存中… | 不抖动布局，不阻塞无关阅读 |
| 有待同步改动/保存失败 | 有 N 题未保存 | 重试；需离开时说明会丢的范围 |
| 会话失效 | 登录后继续保存 | 重新登录，保留未同步答案 |
| 跨设备冲突 | 另一处的进度已更新 | 沿用当前查看/选择/重新载入机制，明确可能丢弃哪些改动 |
| 主测需补充 | 有些方面还不清楚 | 按契约给补充入口与允许的跳过动作 |
| 信息不足 | 暂时无法生成报告 | 返回需要补充的题目，不把它设计成低配报告 |
| 提交中/响应丢失 | 正在提交…/确认提交结果… | 沿用幂等与查找既有报告，不能重复创建 |

错误只用“一句发生什么 + 一个主要动作”；详细错误码可在诊断详情里，不作为正文。保留既有乐观锁、409、退出清理和待同步隔离。

## 8. 报告：减少包装文案，保留结果含义

### 8.1 双报告共同层级

1. **结果概览**：量表/日期，结果标题，必要状态说明，简短结果摘要。
2. **维度结果**：名称、倾向、图示或短解释；展开才看更多依据。
3. **可以观察的一件事**：来自现有有效报告内容，不新增测量结论。
4. **更多阅读**：类型文章/理论推导/方法说明按需要展开。
5. **工具与可选 AI**：操作位置一致，固定报告不依赖 AI。

复制、保存图片、比较入口放在概览之后的紧凑工具栏。正文不必讲“图片、文字、alt 来自同一快照”；这是实现纪律，自动测试保证即可。不要把复制/分享按钮重复放三处。

### 8.2 十六型

- 身份只表达一次：例如主标题“本次更接近 ENFP”，类型中文名作为次级信息。避免类型码、带类型码的标题、单独类型名三次重复。
- 保留现有四句摘要，优先缩减外围标题、重复状态和大图；不能为字数预算截掉“略偏/平分/说不好”的语义。
- `REFERENCE` 显示参考倾向；`TENTATIVE` 用短句“部分维度差距较小，另一侧也值得参考”；`TIED` 用“部分维度两侧得分相同，本次不指定唯一类型”。具体措辞由当前数据决定，不把它们统一成“你就是 XX”。
- 候选代价解释移到候选区域的“怎么算”中；只要数字 cost 可见，旁边必须有短标记“证据差异，非概率”，不能包装成匹配度。不得只剩类型徽章让用户误以为排序是概率。
- 推导内容的标题旁保留“类型推导，非额外测量”；理论解释可折叠，`TIED` 不推导。
- 历史快照的完整解释保持可访问；优先不变更 `domain/reportV3.ts` 的语义。若共享 view model 变动，须同时验证页面、复制、图片与 alt。

### 8.3 大五

- 保持五维并列、同等地位；不拼类型码、不求总分、不做排名。
- 每维第一层为日常名称、倾向、一句现有解释；分数范围和更多例子按需查看。
- 证据不足的维度直说“本项信息不足”，不填 0、不画成中等、不影响其他维度的有效解释。
- 不把每个维度都重复写成长篇“不是能力、人品、排名”的通用声明；通用边界集中写一次，特定维度易误读的短说明留在该维度。
- 不把 `ES` 擅自反转或改名为神经质，保持当前量表命名/方向。旧范围异常提示不得被样式合并隐藏，也不能在前端重算旧报告。

### 8.4 AI 面板

保留当前授权范围提示与主动生成动作，缩成“根据本报告生成补充解读，将发送页面列出的数据范围”。实际字段清单复用现有契约，不能用模糊文案扩大外发。

默认第一层只给“AI 解读 · 可选”、当前额度/状态、必要的数据发送说明、主动作。默认关闭、额度用尽、排队、运行、失败、结果未知、历史读取等状态需准确；真实 mock 仍明确标为演示数据。重复的“可选/不是诊断/不改分数”长段合并，固定报告保持完整可读。

### 8.5 尺寸目标

相同合成样例、390px 默认字体下，十六型首层概览目标比基线 1263px 缩短至少约 30%，建议不超过约 880px。优先删除重复包装、移走大图实现；不可裁断结论或缩小正文达标。320px、长结果和系统放大时不强制高度上限。

## 9. 历史、比较与账号

- 报告列表已有筛选和分页，保留并减短头部解释。“每次提交留一份快照，规则更新不重算”等技术说明移到方法页；列表展示量表、日期、简短状态、摘要和打开按钮即可。
- 比较入口使用明确量表名称；比较只说明观察到的变化，不标“进步/退步”。无可比数据时给原因和下一步，不展示空雷达图。
- 账号页将昵称、密码/恢复码、数据管理分组，默认少量简短说明；不要每个表单都放大插画。
- **优先修正 AccountView 的过时删除说明。**当前代码中 `ReportsListView.vue` 已调用 `v3Assessment.deleteReport`，后端 `JungController` 有 `DELETE /reports/{id}`。账号页应引导“删除单份报告，请前往我的报告”，同时另设“注销账号”及其实际后果。删除报告是否保留测评记录，沿用已确认的现有语义；本轮没有执行真实删除验证。
- 导出仅说导出什么和文件类型；成功或部分失败时说真实结果。删除前若刚发现导出不完整，保留当场提示，不能为简短而隐藏。
- 恢复码生成和注销的确认机制不删；只删旁边重复说理和服务器实现细节。

## 11. 完成标准

同时满足布局和文案目标，才算优化完成：

- 看得见双测评区别、当前状态与主要行动。
- 默认说明性文字显著减少；删去重复和内部实现说明，而不是迁到更多卡片/弹窗。
- 错误与不确定性保留最短必要提示；状态真实，不伪造保存或结果。
- 320 / 390 / 1440 的影响页面有实际截图与主要操作验证，不能只给一张桌面首页图。
- 类型检查、相关测试与构建按风险实际执行，命令输出与退出码一致。
- 不以测试通过宣称测量有效、转化率提高或生产数据库已验证。
