# 竞品调研与现状诊断

调研日期：2026-09-23。结论适用于本次观察到的公开页面；不同地区、账号和后续版本可能呈现不同界面。

## 1. 证据口径

本次实际通过浏览器打开并读取 6 个竞品的公开页面，观察信息顺序、主行动、视觉层级和公开说明；保留页面截图。网页搜索工具未返回可用正文，以下来源以官方网页的浏览器读取为准，不把搜索摘要或印象当作实测。

- **公开页面观察**能证明当时展示了什么，不能证明其转化率、测量准确性或后台行为。
- **本地源码**能证明字段、路由和状态处理的实现；注释与历史验收记录不能单独证明当前运行结果。
- **本地合成页面**能证明选定样例的布局与可见文字，不能证明真实账号权限、数据库保存和网络并发。
- **优化建议**是基于上述证据的设计判断，需要实施后比较，并通过真人任务观察补充验证。

[查看六站视觉对照](evidence/competitor-overview.jpg)。截图仅用于内部设计参考，不作为产品插画或可复用素材。

## 2. 竞品观察与迁移方式

| 来源 | 实际看到的模式 | 对 TypeMe 的借鉴 | 不带入本项目的部分 |
|---|---|---|---|
| S01 · 16Personalities | 中文首页有单一强主按钮；测试入口用三步图解说明过程；人物插画形成识别度 | 一个视区只突出一个主行动；预先说明“选择—作答—报告”；保留 TypeMe 原创人物资产 | 不照搬品牌配色、人物、题面、文案；不搬运准确率和用户规模宣传；不把其量表结构套给本项目 |
| S02 · Truity TypeFinder | 公开测试页有成对陈述与五档选择、分步提示；FAQ 提供投入说明和示例报告入口，说明先看概要再看更多内容 | 把题型、题数、投入与产出提前说清；两端选择建立清晰空间对应；报告分层展开 | 不引入付费解锁或大批问题同屏；不照搬它的题数、细分维度、题目与商业用途 |
| S03 · Dimensional | 官网用清楚的产品承诺、手机界面示例、不同人格维度入口展示产品；社交比较是其主要内容之一 | 用自家报告的静态、标明示例的预览解释“完成后看到什么”；给维度稳定的文字与视觉编码 | 不扩展为社交网络，不加入关系匹配；不把对方的维度数量或准确性说法带进本站 |
| S04 · PrinciplesYou | 首屏开始入口与保存进度的账号说明并置；往下展示类型、详细报告和生活情境，另有方法说明入口 | 在要求登录前解释保存价值；报告按概览、解释、生活观察组织；方法依据可达 | 不借用名人/专家背书；不新增团队评估、招聘判断和跨人比较 |
| S05 · BigFive 开源站 | 中文落地页直接给出题数、预计时长、开始入口与注册要求；结果、比较、关于分开导航 | 透明展示投入成本；报告回访入口清楚；将量表范围说明放在合适位置 | 该站公开页面显示 120 题且无需注册，均不适用于本站登录版 50 题大五；不继承其效度宣传 |
| S06 · 壹心理测评 | 中文目录按需求分组，有内容推荐、分类与多种测评入口 | 卡片标题说人话；优先回答“我想了解什么”，再讲量表名字 | TypeMe 仅两项主测，无需复制多层筛选、排行榜、轮播和商品货架；不引入诊断式标签或焦虑营销 |

这是设计取舍，不是竞品质量排名。尤其不能从“竞品这样设计”推导出“TypeMe 转化率一定提高”。

## 5. 真实浏览器基线

环境：当前源码经 Vite 启动，全部 `/api` 代理到只读合成服务；复用已有 `scripts/browser-verify-readable.py` 的目录与报告样例。没有启动 Spring Boot 或访问现有数据库。报告类型与内容使用合成夹具，目录里“10 分钟”是样例数据，不是产品时长证据。

页面 CSS 测量以 `getBoundingClientRect()` 加 `scrollY` 获取文档纵向位置，数值四舍五入。截图按浏览器实际内容区保存，可能小于配置视口；视口数据以 JSON 为准。

| 首页主按钮顶部 Y | 477 | 458 | 615 |
| 首页主视觉高度 | 886 | 933 | 848 |

## 6. 诊断与优先级

| 编号 | 事实 | 设计判断/待验证影响 | 对应措施 |
|---|---|---|---|
| F01 | 首页主按钮可见，但两项测评名称在较深处；Hero 主要为情绪化表述 | 初访者可能先理解氛围，后理解产品可选项；不能直接断言造成流失 | 保留一句品牌标题，增加“双测评区别”和靠前的轻量选择 |
| F02 | 十六型概览包含状态、类型码、完整标题、类型名、摘要和人物大图 | 相同身份信息和装饰占据较多高度 | 一个身份标题、状态解释和摘要为第一层；人物图后移 |
| F03 | 两报告的分享入口、概览结构与目录方式不同 | 跨量表回访要重新找操作 | 统一阅读骨架和工具栏位置，保持四维/五维内容独立 |
| F04 | 首页含人格图鉴、品牌宣言、阅读路径及十六型折叠示例 | 信息充足，但两条主测路径的内容比重不均 | 双量表报告示例前置，图鉴后置并明确只属于十六型 |
| F05 | 保存失败、冲突、会话失效与邀请注册已经实现 | 重新写页面时最容易遗漏这些状态 | 以状态矩阵约束重构，优先复用已有 store 和组件 |
| F06 | 样式既有 token，也有大量页面局部字号和颜色 | 跨页面调整可能产生密度漂移 | 在触及的组件内归并变量；不做全仓格式化或一次性 CSS 重写 |

F01—F04 是呈现优先级判断，不等同于用户测试结论。F05—F06 是实施风险与约束，不应被扩张为重写后端的理由。

用户补充要求后增加两项源码核对：

- **F07 · 过时能力说明。**`AccountView.vue` 仍说单份报告删除未完成、只能注销账号；但 `ReportsListView.vue` 已调用 `v3Assessment.deleteReport`，`JungController.java` 已有对应删除接口。应优先修正文案和入口，不能为删除个别报告误导用户注销账号。本轮未执行实际删除。
- **F08 · 隐私措辞过度。**`LoginView.vue` 写“答案与报告只属于你自己”，而 README 顶部说明管理员具有成员报告查看能力。该句话可能被理解为仅本人可见的绝对承诺；建议从登录引导删除，准确权限范围集中到隐私说明。此处只核对文案与已知能力，不推断存在未授权访问。

具体改写与删除方式见 [文案精简与逐页改写](03-文案精简与逐页改写.md)。

## 7. 证据限制

- 浏览器未走当前答题、注册、账号删除、导出与真实历史比较的完整路径；这些部分的当前判断来自源码。
- 只读夹具未覆盖首页的新版草稿列表接口，因此合成首页会在下方显示“未能确认上次进度”。这是夹具缺口，**不能上报为产品保存故障**；也不影响首屏到目录的测量。
- 没有转化率、流失率、真实用户访谈或性能基准，不给“预计提升 XX%”的承诺。
- 未做竞品移动端完整适配审查，不能推断其全部响应式行为。
- 图片证据可供内部评审，但竞品截图、图案与题面不进入 TypeMe 产品资源。
