# 本轮调研证据

日期：2026-09-23。源码基准：`96a7e67`，实际使用当前工作区源码。开始时没有受跟踪文件的改动，已有多份未跟踪日志；本轮保持不动。

## 实际做了什么

- 阅读 README 顶部、项目规则、相关产品/开发/报告契约片段；检查前端视图、路由、组件、样式与相应 store/API，针对单份删除说明核对后端 Controller。
- 浏览 6 个官方公开页面并保存截图，没有注册竞品账号、提交问卷、购买报告或发送用户资料。
- 运行本地 Vite 源码预览，`/api` 指向本轮启动的只读合成服务：复用现有 `scripts/browser-verify-readable.py` 的合成目录与报告；服务只响应读取，所有写请求拒绝，没有连接真实后端。
- 首页和两种报告各在 320×720、390×844、1440×900 观察，记录截图和 DOM 布局。只有指定样例的布局观察，不是整站功能回归。
- 建立方案、文案对照、AI 提示词与验收文档。没有改动产品前端、后端和配置；文档核验结果见 `documentation-check.json`。

## 已知局限

- 合成服务没有适配新版草稿列表接口，因此首页下方存在进度读取失败提示。这是夹具缺口，不能报告为真实产品故障；首屏和量表标题纵向测量位于其前方。
- 所有账号昵称、报告与 AI 展示均为示例。这里的模拟登录不证明真实认证、资源归属、并发或服务端写入行为。
- 部分底层资源采用当前项目既有插画策略；没有调用上传工具，没有修改资源服务。
- 没有把竞品的公开宣传当成准确性证据。没有阅读其私人/付费报告或验证其后台功能。
- 未执行本地答题、注册、真实删除/导出、数据库或 AI 生成流程。没有 frontend 单元测试/构建成绩，因为本轮交付为文档且产品代码未改。
- 没有性能测试、真人理解测试或转化数据。布局尺寸不代表业务收益。

## 基线复查入口

后来实施者应先检查当前源码、既有 fixture 和权限，不直接照抄历史测试结论。使用与当前 API 契约匹配的合成响应，将全部 `/api` 请求锁定到隔离服务/拦截器，再按 `layout-baseline.json` 的三档视口读取对应 DOM 位置。未覆盖接口不透传，不向现有数据库发写请求。

本轮临时服务仅用于取证，完成后停止。这里保留的是截图、原始尺寸和文档检查结果；没有新增长期运行服务或生产配置。
