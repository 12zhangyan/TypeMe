# 计分审计与验证记录

审计日期：2026-09-18；以当前工作区为准，包含用户已有未提交修改。本轮不改计分与内容包。

## 1. 结论

当前 Jung48 实现的基本计分方向、unknown/中立区分、平分保留和固定报告思路可保留；**不能宣称 MBTI 算法已全面验证正确**。本轮发现题意与极性错配、阈值规格不等价及尚未完成真人验证的问题。共享夹具通过证明特定实现行为一致，不证明题库有效。

## 2. 当前公式核对

来源：`backend/src/main/java/com/typeme/jung/scoring/JungScorer.java`、`jung/domain/JungScoringPolicy.java`、`frontend/src/domain/jung/scoring.ts` 和 `types.ts`。

```text
正极：EI→E，SN→N，TF→F，JP→P
direction = 右侧为正极 ? +1 : -1
单题贡献 = direction × (rating - 3)
S = 有效数字回答的贡献和
n = 有效数字回答数（rating=3 计入，unknown 不计入）
m = S/(2n)，无有效回答时为 null
p = (m+1)/2，仅为图示位置
方向取 S 符号，S=0 不判字母
T(n)=floor(2n/10)
B(n)=max(0,T(n)-1)
```

48 道主测全部处理且每维至少 9 个 rating 才能提交完整结果；主测不足不能靠补充题绕过。ReportService 在正式提交时检查安排的补充题全部已处理或显式跳过；纯函数单独调用不等于完整 API 合法状态。

## 3. F1：JP-02 题意和键值相反

源：`docs/2026-09-16/implementation/content/jung48-questions.yml:101` 及生成内容 `backend/src/main/resources/content/typeme-jung48-zh-v1.json`，题号 JP-02。现有 `jung48-item-review.md:21` 也重复了这一映射，说明已有审校表不能视作独立正确性证据。

| 项目 | 当前内容 |
|---|---|
| 场景 | 没有期限的任务 |
| 左端 | 先定下一套做法，往下推进 |
| 左端键 | P |
| 右端 | 同时留着几套做法，看情况再说 |
| 右端键 | J |

实际脚本调用 `contributionOf(item,1)` 返回 +2，贡献到 P。按照本项目产品方案对 J/P 的定义，先决定/推进对应 J，保留选项对应 P。这是高优先级内容键错配，不是浮点误差。

影响：强左与正确极性相比，该题贡献相差 4 分，可能改变边界附近 J/P 方向及类型衍生报告；不能据此声称所有历史报告都错，实际影响需在授权分析范围内逐份核对。

修复方向：新发布包修题面/极性并重新审校。单独翻转极性还会改变当前每维 6:6 的左右平衡，因此要审核整个 JP 题组的呈现安排，不能只改一个字段后绕过生成器检查。旧 packageId、已存报告、hash 均保留。

## 4. F2：触发阈值相差一倍，边界降级过窄

原产品/开发方案：`|m|≤0.20` 且 `m=S/(2n)`。

正确整数等价式：`5×|S|≤2n`，即 `|S|≤floor(0.4n)`。

当前冻结契约和两端实现：`|S|≤floor(0.2n)`，对应约 `|m|≤0.10`，不是原 0.20 的整数化。冻结契约是后来规则，不能简单称“代码没有遵守当前契约”；真正问题是规格发生实质变化，但说明错误地弱化了差异。

审计脚本令其他三维为明确正方向、JP 如表，跳过补充题，直接调用现 TS scorer：

| n | S | m | 原设计触发 | 当前触发 | 当前边界 | 当前总状态 |
|---:|---:|---:|---|---|---|---|
| 12 | 1 | 0.04167 | 是 | 是 | 是 | TENTATIVE |
| 12 | 2 | 0.08333 | 是 | 是 | 否 | REFERENCE |
| 12 | 3 | 0.12500 | 是 | 否 | 否 | REFERENCE |
| 12 | 4 | 0.16667 | 是 | 否 | 否 | REFERENCE |
| 9 | 1 | 0.05556 | 是 | 是 | 否 | REFERENCE |

当 n=9 时 B=0，非零方向永远不能因该维变为 TENTATIVE：该维只能平分或非边界。这是规则效果，不是实证结论。契约说“证据不足以支持较明显偏向，因此不给边界标记”，与 boundary 表示“倾向较轻”的语义相反。

此外原开发方案候选 cost 使用 `sum(abs(m))`，冻结契约/实现改为 `sum(abs(S))`。有效题数不等时排序含义不同；应明确 cost 是原始分距离还是归一化距离，不能继续把两个规格描述为同一算法。

建议：发布新 scoringVersion 前写 ADR，分别定义触发与最终解释阈值、跳过补充的表达、有效数量改变的影响。可将“保留原 0.20 产品区间”作为待试测基线，但不能把恢复该值叫作科学修复；没有数据就没有经验证的最佳阈值。

## 5. F3：内容构念混入风险，须真人复核

以下是审题判断，不是已完成心理测量验证：

- JP-04：“告一段落以后再改”与“继续修改”可能测量收尾/完美倾向，不一定区分保留选项与早决策。
- JP-10：完成后继续打磨同样可能更接近尽责性或完美倾向。
- TF-C3：“问谁方便”与“定死时间地点”混入协商、控制方式和 J/P，不宜直接当成 T/F 的纯证据。
- SN-C2：“看参数/评价”与“想是否需要”混合决策阶段和消费习惯，右端不天然等于 N。
- EI 若干条目可能同时受到社交紧张、熟悉程度和礼貌影响；需要认知访谈区分偏好与情境约束。

审核方法：让独立审题者先看题面、不看极性元数据，写出测量内容和两端含义，再对照键表；记录分歧。自动检查数量、左右平衡、facet 数、哈希均不能替代这一步。

## 6. F4：覆盖不足时的两端输出差异（源码发现）

TS `score()` 在全局 coverage 不足时把顶层 clarificationDimensions 置空。Java `score()` 在各维循环中先按局部 needsClarification 添加 scheduled，再进入 NEEDS_REVIEW 返回该列表。两端 `reviewClarification()` 均会在全局 coverage 不足时返回空。

本轮脚本构造 JP 缺一题、其他维接近中点，证实 TS 顶层为空；Java 的差异依据源码分支，未执行这个自定义样例的 Java 差分测试。正式提交服务还有全局覆盖守卫，因此不据此宣称当前 API 已经错误发题。

建议加入跨维缺答金样，明确 pure score 与 review 的顶层计划字段语义，避免平台提取时带入差异。

## 7. 官方算法与本项目的关系

官方 MBTI 有自己的题目和计分版本，公开产品资料说明 Form M/Q 使用 IRT 相关方法。当前等权双极求和是本项目自定义规则，不可因输出同样四字母就称为官方复刻。[官方说明](https://www.themyersbriggs.com/en-US/Support/Validity-of-the-Myers-Briggs-assessment)

McCrae/Costa 1989 的研究未支持其样本中的天然二分/定性离散类型解释，支持以连续维度理解的部分关联。这是一个独立研究结果，不等于穷尽该领域所有研究；但足以反对把本项目四字母当作确证分类。[论文](https://onlinelibrary.wiley.com/doi/10.1111/j.1467-6494.1989.tb00759.x)

当前包明确 `contentStatus=draft_review_pending`，题目来源标记尚未真人审读和试测。过程结构测试只证明字母到框架结构的映射实现，并没有测量认知功能强弱。
