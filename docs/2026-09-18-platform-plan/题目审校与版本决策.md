# 十六型题库逐题审校与版本决策（v1 → v2）

日期：2026-09-18。范围：`typeme-jung48` 的 64 道题（48 主测 + 16 补充）。
性质：**源码与内容审校记录**，不是心理测量学验证。本轮没有真人被试、没有认知访谈、
没有信度/效度/常模分析，因此任何"题目已被验证有效"的说法都不成立。

## 1. 为什么要出新版本而不是原地改

`typeme-jung48-zh-v1` 已经写进 `assessment_package` 表、绑定到已存在的草稿与已生成的报告
（报告里存了当时的 `content_sha256` 与 `scoringVersion`）。原地修改 v1 会让
"同一份 packageId 在不同时间算出不同结果"，历史报告无法解释，也无法追溯。
所以修正只能发布为新 `packageId`：

| | v1 | v2 |
|---|---|---|
| packageId | `typeme-jung48-zh-v1` | `typeme-jung48-zh-v2` |
| scoringVersion | `typeme-jung48-score-v1` | `typeme-jung48-score-v2` |
| reportContentVersion | `typeme-type-report-zh-v1` | `typeme-type-report-zh-v2` |
| 内容源 | `docs/2026-09-16/implementation/content/jung48-questions.yml` | v1 JSON + 本文件第 3 节的逐题修正 |
| 生成器 | `scripts/convert-jung-content.mjs` | `scripts/gen-platform-content.mjs` |
| 文件 | `content/typeme-jung48-zh-v1.json`（未改动） | `content/typeme-jung48-zh-v2.json` |

v1 的字节、`sha256`、已存报告与旧草稿全部保留。新草稿创建时绑定 v2；
旧草稿按它自己记录的 `package_id` 继续用 v1 加载（见 `ReleaseResolver`）。

## 2. 审校方法（以及它不能证明什么）

对 64 道题逐题做了四项检查：

1. **两端是否在比较同一件事、同一阶段**（"是否买" vs "买什么"这类混构念）。
2. **键值是否与题面语义一致**：左端描述的是哪一侧偏好、`leftPole/rightPole` 是否与之一致。
3. **是否混入其它维度或非人格评价**（尽责性、完美倾向、勤快/拖沓、社交能力）。
4. **重复与歧义**：是否与同维其它题问同一件事；是否需要很长 help 才能理解。

判定规则只有一条：**先只看 `textLeft`/`textRight` 与 `scenario`，写出这一题在比较什么、
哪一端对应哪一侧偏好，再去看 `leftPole/rightPole`。** 顺序反过来会被原有键值锚定，
`jung48-item-review.md` 就是这么把 JP-02 的错误映射抄下来的。

不能证明什么：上述检查全部由同一位执行者完成，**不构成独立盲审**，
也不构成题目可理解性的真人验证。`docs/2026-09-18-platform-plan/题目报告与AI易读性改造.md`
§5 要求的 5–8 人可用性访谈仍未进行，状态记为"待访谈"。

## 3. v2 的逐题修正（只列改动的题）

修正数据以代码为准：`scripts/gen-platform-content.mjs` 的 `JUNG_V2_ITEM_CORRECTIONS`。
未列出的 60 道题逐字沿用 v1。

### 3.1 JP-02（键值与题面相反，已修正）

| | v1 | v2 |
|---|---|---|
| 左端 | P · 先定下一套做法，往下推进 | P · 同时留着几套做法，看情况再说 |
| 右端 | J · 同时留着几套做法，看情况再说 | J · 先定下一套做法，往下推进 |

"先定下一套做法，往下推进"就是本项目对 J 的定义（提前定下来）；"同时留着几套做法"
是 P。v1 把两者标反了：选最左得到 +2 分，实际贡献给 P，与题面方向相反。

**为什么用"交换两端呈现"而不是"只交换键值"**：JP 组主测原有的"左端为负极 6 题"
正是靠这处错配凑出来的（见 §4）。只换键值会让该组变成 7:5，给"一直点左边"引入系统偏差；
交换呈现同时修正语义与左右平衡，且不需要为了凑平衡去重写任何一题的构念。

### 3.2 JP-04（键值与题面相反，已修正）

| | v1 | v2 |
|---|---|---|
| 左端 | P · 先告一段落，剩下的地方以后再改 | P · 再多留一点时间，接着改下去 |
| 右端 | J · 再多留一点时间，接着改下去 | J · 先告一段落，剩下的地方以后再改 |

"先告一段落、剩下的以后再改"是**尽快收掉、不再挂着**（J：尽早把状态定下来）；
"再多留一点时间，接着改下去"是**保留继续改的余地**（P）。v1 同样标反。
修正方式与 JP-02 相同：交换两端呈现。

### 3.3 JP-03（题面混构念，已重写；键值方向不变）

v1 左端"很快接受改动，重新安排就好"把两件事挤在一句里：接受变化像 P，
而"重新安排一遍"是典型的 J。两端不落在同一比较上，用户无法判断这题在问什么。
v2 只改文字：

- 左端：不重新排，顺着当时的情况走（不把安排提前定死 = P）
- 右端：马上重新排一遍，把后面的时间重新定下来（尽快把安排定下来 = J）

### 3.4 JP-10（题面混入"勤快/拖沓"，已重写；键值方向不变）

v1 左端"就让它这样，留些地方以后再看"容易被读成"做事不积极、拖着不改"，
而它要表达的是**不把结果定死**（P）。v2 只改文字：

- 左端：先不做最终决定，放一放再看看（P）
- 右端：尽快收个尾，把它定下来（J）

## 5. 本轮没有动的阈值问题（v2 轮次记录；v3 已按批准方案另行实施）

> **版本状态（2026-09-20 同步）**：本节以下记的是 **v2 发布当时**的决定与论证，保留原文以便追溯。
> 之后阈值政策已按批准方案落地为 **v3**：
>
> - **v1 / v2（历史行为，冻结）**：触发 `T(n)=floor(2n/10)`，最终边界 `B(n)=max(0,T(n)−1)`。
>   旧草稿与旧报告按各自绑定的版本继续这样计分，**不重算**。
> - **v3（当前默认，已实施）**：`T(n)=B(n)=floor(2n/10)=floor(n/5)`，最终边界另要求 `n>0`，
>   **等号包含在内**（`|S| ≤ B(n)` 即算"倾向较轻"）。触发条件与 v1/v2 相同，因此**没有任何人多答题**。
> - **按绑定版本计分**：新草稿绑 v3，已有草稿按其 `package_id` 绑定的版本计分；
>   未知 `scoringVersion` 在加载期报错，**不静默回落**。
> - **性质**：这是**已批准的产品政策调整**，**不宣称提高测量准确性**；
>   `0.10` 这个界限仍然没有信度/效度依据，用户可见差异只有 `|S| = T(n)` 那一格与 `n=9` 一档。
>
> 依据：批准与决策记录见 `docs/2026-09-16/implementation/_contracts/01-新测契约-v1.md` §4.1（v1.2）
> 与 `docs/handoffs/2026-09-18/open-decisions-decision-list.md` §1 / §4 决定一 / §6.2；
> 代码与隔离验证的最终复核见 `docs/optimization/verification/2026-09-20-score-v3-closeout/REPORT.md`。
> 交付状态：**代码与隔离验证完成；尚未登记数据库、尚未部署、尚未完成真实环境验收**。

`scripts/gen-platform-content.mjs` 生成 v2 时**沿用 v1 的阈值与政策**：
`boundaryNumerator=2`、`boundaryDenominator=10`、`minBaseRatingsPerDimension=9`、
`ratingNeutral=3`。

理由（**v1/v2 适用**）：`docs/2026-09-18-platform-plan/计分审计与验证记录.md` §4 记录了两个不等价的规格
（原产品/开发方案的 `|m|≤0.20`、边界口径 `|S|≤floor(0.4n)`；v1/v2 冻结契约与实现是**触发**
`T(n)=floor(0.2n)`，**最终边界** `B(n)=max(0,T(n)−1)`，即约 `|m|≤0.10` 再排除恰好落在 `T` 的一格）。
这是**业务决策**，不是实现缺陷：

- 选 `floor(0.2n)`：更多答卷被当作"方向明确"，`TENTATIVE` 更少，边界提示更少。
- 选 `floor(0.4n)`：更多答卷进入"只是略偏"，`TENTATIVE` 更多，报告更保守。

注意两者的差距不只是分子：原方案把 0.20 同时当作触发与边界，v1/v2 的边界比触发更严一格。
**只把分子改成 4、仍保留 `B=T−1`，不等于恢复原产品方案的边界口径**（`n=12, |S|=4` 仍是
`REFERENCE`，而原方案是 `TENTATIVE`）。详见修正后的
[阈值政策对比与决策请求](阈值政策对比与决策请求.md) §1–§3。

**（v2 当时）** v2 不擅自选一个值。差异、影响与建议见
[阈值政策对比与决策请求](阈值政策对比与决策请求.md)。在用户明确之前，
v2 与 v1 保持同一阈值，因此**没有通过调阈值制造更多"确定类型"**。

**后续（2026-09-18 晚，用户已明确）**：选择的不是本节列举的任何一档，而是**规则 D**——触发不动、
边界与触发合并（即 `T(n)=B(n)=floor(n/5)`，最终边界要求 `n>0`），随新包 `typeme-jung48-zh-v3`
实施。上述 v1/v2 结论继续**按其适用版本**成立；v3 的状态与依据见本节开头的版本状态块。

`assessment-packages/ipip50-zh1.yml` 生成：

- `contentStatus` 为 `draft_review_pending`：中文题面与解释尚未做真人试读。
