## 1. 两个规格分别是什么

计分口径（`docs/2026-09-16/implementation/_contracts/01-新测契约-v1.md` 与
`backend/.../JungScorer.java` 一致）：

```text
单题贡献 c = direction × (rating − 3)          rating ∈ 1..5，direction = ±1
S = Σc（整数）
n = 有效数字回答数（rating = 3 计入，unknown 与未作答都不计入）
m = S / (2n)
```

两处规格对"这一维够不够明确"给出的界不同。**先要把两个量分开**——冻结契约 §4.1 用两个不同的式子：
触发澄清的阈值 `T(n)`，与最终"倾向较轻"的边界标记 `B(n)`：

| 规格出处 | ① 澄清触发 `T` | ② 最终边界 `B` | 边界换算成 m | 语义 |
|---|---|---|---|---|
| 产品方案 §5.2 / 开发方案 §3.4 | `\|mBase\| ≤ 0.20`（开发方案 L64） | `5×\|S\| ≤ 2n`，即 `\|S\| ≤ floor(0.4n)`（开发方案 L68） | `\|m\| ≤ 0.20` | 边界更宽：更多答卷被判"只是略偏"（`TENTATIVE`） |
| 冻结契约 §4.1 / v1 与 v2 实现 | `\|S\| ≤ T(n) = floor(0.2n)` | `\|S\| ≤ B(n) = max(0, T(n) − 1)`（相对同政策的触发 `T` 只少一格） | 约 `\|m\| ≤ 0.10`；与开发方案相比的差异是**整段区间**，见下方勘误 | 边界更窄：更多答卷被判"方向明确"（`REFERENCE`） |

两条规则的差距不只是"分子 2 与 4"，而是**触发与边界的关系**：原方案把同一个 0.20 同时当作触发与边界；
冻结契约让边界比触发更严一格（`B = T − 1`）。

> **契约 §4.1 关于差异范围的说明有误（2026-09-18 勘误）。** 它写"差异只出现在 `T(n)` 那一格
> （`n=12` 时 `|S|=2`、`n=16` 时 `|S|=3`）"，这不成立：原方案边界 `5|S| ≤ 2n` 等价于
> `|S| ≤ floor(0.4n)`，现行边界是 `|S| ≤ B(n)`，两者相差的是**一整段区间**
> `B(n) < |S| ≤ floor(0.4n)`——`n=9` 时 `|S| ∈ {1,2,3}`、`n=12` 时 `|S| ∈ {2,3,4}`、
> `n=16` 时 `|S| ∈ {3,4,5,6}`。原文只举了区间下沿（恰好等于 `T(n)`），低估了差异范围。
> 出错的是**数学解释**，不是规则：`T(n)`/`B(n)` 的定义与"边界只在最终题集上判一次"都不变，
> 现行实现仍是契约符合的。**"实现以契约为准"只说明当前实现的依据，不能证明这段解释正确。**
> 勘误已同步写入 [契约 §4.1](../2026-09-16/implementation/_contracts/01-新测契约-v1.md)。

审计记录（`计分审计与验证记录.md` §4）已确认这不是浮点误差，
而是规格在演进中发生了实质变化，而当时的说明把它描述成了"整数化等价式"。

## 2. 实际影响（同一份答卷会得到不同结论）

取 JP 维、其他三维方向明确、跳过补充题，只看 JP 的 `n` 与 `S`。
下表为 **2026-09-18 复核实测**（内存调用当前 TS 计分器 + `typeme-jung48-zh-v2` 包，exit 0；
Java 侧按 `JungScoringPolicy` / `JungScorer` 源码交叉核对，未做 Java 差分执行）：

| n | S | m | 原开发方案边界 `5\|S\| ≤ 2n`？ | 当前触发 `T(n)`（要不要追问） | 当前边界 `B(n)`（该维是否"略偏"） | **当前实际状态** |
|---:|---:|---:|---|---|---|---|
| 12 | 1 | 0.042 | 是（边界） | `T=2` 是 | `B=1` 是 | `TENTATIVE` |
| 12 | 2 | 0.083 | 是（边界） | `T=2` 是 | `B=1` **否** | **`REFERENCE`** |
| 12 | 3 | 0.125 | 是（边界） | `T=2` 否 | `B=1` 否 | `REFERENCE` |
| 12 | 4 | 0.167 | 是（边界） | `T=2` 否 | `B=1` 否 | `REFERENCE` |
| 9 | 1 | 0.056 | 是（边界） | `T=1` 是 | `B=0` **否** | **`REFERENCE`** |
| 9 | 2 | 0.111 | 是（边界） | `T=1` 否 | `B=0` 否 | `REFERENCE` |

**"触发"不等于"结论不确定"**：`T(n)` 决定要不要追加澄清题，`B(n)` 才决定这一维算不算"只是略偏"。
`n=12, S=2` 与 `n=9, S=1` 都会被追问，但最终仍是 `REFERENCE`——所以"追问变多"不自动等于
"`TENTATIVE` 变多"：完成澄清题后 `S` 与 `n` 都会变，真实占比需要样本，不能靠这张表推断。

分界点：当 `n = 9` 时 `T(9) = floor(0.2×9) = 1`，所以 `B(9) = max(0, 1−1) = 0`，
**非零方向在该维永远不会被标记为"只是略偏"**——该维只能是平分（`TIED`）或非边界（`REFERENCE`）。
这是规则效果，不是关于用户分布的经验结论。

`TENTATIVE` 与 `REFERENCE` 对用户是两句不同的话：

- `REFERENCE`：四维方向都明确，给出四字母 + 完整解读。
- `TENTATIVE`：至少一维只是略偏，页面写"本次更接近 XXXX"并明确提示另一侧也值得读。

因此这个选择直接决定"有多大比例的用户会被告知自己的结果不那么确定"。

## 3. 三个候选方案

| 方案 | 触发 `T` | 最终边界 `B` | 优点 | 代价 |
|---|---|---|---|---|
| A：保持现状 | `floor(0.2n)`（不变） | `max(0, T−1)`（不变） | 与 v1 一致，历史报告无需区分；`REFERENCE` 更多，页面更"有结果" | `n=9` 时该维不可能出现"略偏"，与 `boundary` 想表达的"倾向较轻"语义相反；可能让边界附近的人拿到过度确定的表述 |
| B：回到原产品区间 | 待定（原方案是 `\|mBase\| ≤ 0.20`，即 `floor(0.4n)`） | `\|S\| ≤ floor(0.4n)`，**即边界等于 `T`、不再减一** | 与产品/开发方案的"边界"口径一致；"略偏"能真正出现在小 `n` 情形 | 与 v1 结论不一致，需要新 scoringVersion 并说明"同一份答卷为何换版本后更保守"；`TENTATIVE` 明显增多。**只把分子改成 4 而保留 `B = T−1` 不是这个方案**：`n=12, \|S\|=4` 仍会是 `REFERENCE`，而原方案的边界口径是 `TENTATIVE` |
| C：分层处理 | 触发澄清用 `floor(0.4n)` | 最终解释用 `floor(0.2n)`（或另定一条） | 把"要不要追问"和"结论有多确定"分开定义，两个目标各自有合适界 | 规格最复杂，需要同时解释两条界；实现与文案都要改，验证成本最高 |

## 4. 建议与理由

建议 **C**，但必须先写 ADR 并做独立样例评审再改；如果本轮必须快速收敛，则**保持 A**。

理由：

1. `T(n)` 的原始用途是"这一维证据是否足够，要不要追加补充题"，`B(n)` 的用途是
   "最终解释的语气"。让一个数同时承担两个目标，正是当前矛盾的来源。
2. 无论选哪个值，都**没有实证依据**说它更"准确"。本轮没有真人数据，
   无法用"哪个阈值预测得更准"来选。可行做法是先固定政策、收集真实答卷分布后再评估。
3. 不该为了"出更多确定类型"而调低标准（即选 A 而不是因为 A 更激进才选 A）。

无论选哪个方案，**ADR 必须同时填写 `T` 与 `B` 两条式子**（含等号边界）、跳过澄清与完成澄清各一个样例
（说明 `n` 与 `S` 都会变）、以及新旧版本报告如何并存；只写一条"阈值"不足以定案。

## 5. 需要用户确认的具体问题

1. 采用 A、B 还是 C？
2. 若采用 B 或 C：**最终边界 `B` 的语义是否一起改？** B 方案要求 `B(n) = floor(0.4n)`（边界等于触发、不减一）；
   若只把分子改成 4 而保留 `B = T−1`，`n=12, |S|=4` 这类答卷仍会是 `REFERENCE`，
   **不等于**恢复原产品方案的边界口径。
3. 如果采用 B 或 C，是否同意发布 **新的 scoringVersion**
   （例如 `typeme-jung48-score-v3`）并保留 v1/v2 报告的原始结论、不静默重算？
4. 部署到已有数据库的 `assessment_package` 表：
   新阈值包需要新增一行内容登记记录。**执行迁移/写入需要单独授权**，本轮未执行。复用旧 `packageId` 会 UPSERT 覆盖，必须用新 ID。

在得到答复之前，`typeme-jung48-zh-v2` 沿用 v1 的阈值，
因此本轮没有任何"通过调阈值改变用户结论"的改动。
