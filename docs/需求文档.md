## 0. 本版范围（先看这个）

**做给谁用**：我自己 + 我的朋友，预计 **10–100 人**。非商业。

**因此砍掉的东西**（相对商业化版）：

| 砍掉 | 原因 |
|---|---|
| ❌ 登录 / 账号体系 | 个人站不需要 |
| ❌ 支付 / 会员 / 广告 | **非商业是 OEJTS 许可的前提**（见第 3 章），一旦变现就违约 |
| ❌ 数据收集 / 后端 / 数据库 | 不收集数据 → **不触发《个人信息保护法》义务**，也就不用写复杂隐私政策 |
| ❌ 常模 / 人群百分位 | 没有样本量，做不了，也不该假装做得了 |
| ❌ AI 生成解读 | 没必要，且省掉备案问题 |
| ❌ ICP 备案 / 商标注册 | 个人自用 + 无经营行为，风险极低（部署方式见第 7 章） |
| ❌ 后台管理 / 看板 | 题库直接写成代码里的常量 |
| ❌ 微信小程序 | H5 网页足够 |

**保留的核心**：

| 保留 | 说明 |
|---|---|
| ✅ 32 题完整测评 | 用 OEJTS 官方题库（见第 3 章） |
| ✅ 四维倾向强度 + 类型推断 | 见第 4 章 |
| ✅ 结果页 + 分享图 | 朋友之间要能发出来 |
| ✅ 许可署名与免责声明 | **法律义务，不能省**（见第 8 章） |

> **一句话**：这是一个**纯前端、零后端、零成本、无数据收集**的静态站点。

## 1. 目标

1. 我和朋友能在手机上打开、**7 分钟内**做完、立刻看到结果。
2. 结果**比市面上的免费测试更可信**——不是"更准"，而是**更诚实**（明确告诉你哪个维度测不准）。
3. 结果能**分享**（生成图片卡片）。
4. **零运维、零成本**，我自己不需要维护服务器。

## 2. 非目标（明确不做）

- 不做诊断、不涉及心理疾病。
- 不用于招聘、晋升、筛选。
- 不做用户排名、不评优劣。
- 不做账号、不做社交、不做评论。
- **不收集任何个人信息**（这是设计原则，不是待办）。

## 3. 题库（已定）

### 3.1 决策：用 OEJTS 题库（32 题快速版 + 44 题标准版）

**关键变化**：项目从商业改为非商业后，**OEJTS 从"不能用"变成了"可以用"**。

OEJTS 许可是 **CC BY-NC-SA 4.0**——其中的 **NC（NonCommercial）正好允许非商业使用**。而它是目前**唯一有公开效度数据、且专为类型学设计**的免费题库。

**为什么不用 IPIP**：IPIP 虽是公有领域（可商用），但 **IPIP 里没有 MBTI / 荣格量表**（已通读其 274 个构念索引确认），只能做大五代理映射，而 S–N / T–F / J–P 三维与大五只是弱相关。**对个人站来说，OEJTS 的题更对路。**

#### 题量决策：32 题（快速版）+ 44 题（标准版）

官方印刷版 **32 题**（每维 8 题）确实偏短（竞品多为 60–93 题）。我们已把 OEJTS 开发文档**附录 A 的 298 道筛选题**全部提取并评估扩充可行性（详见 `research/05-长版题库选型.md`），结论如下。

合格标准：目标维度 `nmin ≥ 700` 且 `判别性 > 0`（判别性 = 目标维度值 − 其他三维度最大值）：

| 维度 | n≥700 候选 | 判别性>0 | ≥0.2 | ≥0.3 | ≥0.4 |
|---|---|---|---|---|---|
| I–E | 67 | 25 | 15 | 15 | 13 |
| **S–N** | **48** | **9** | **4** | **1** | **0** |
| F–T | 201 | 52 | 31 | 24 | 13 |
| J–P | 121 | 27 | 14 | 12 | 7 |

**→ S–N 维度素材枯竭**：判别性 ≥0.4 的题**一道都没有**；S 端候选的判别性**全为负**。这正是 OEJTS 的 S–N 效应量最低（0.93）在**题目层面**的根因——不是实现问题，是没题可用。

**因此定档**：

| 版本 | 题量 | 构成 | 用时 | 定位 |
|---|---|---|---|---|
| **快速版** | **32 题** | 官方原版 + 官方计分公式 | ~5 分钟 | **默认入口** |
| **标准版** | **44 题** | I–E / F–T / J–P 各 12 题，**S–N 保持 8 题** | ~7 分钟 | 可选 |

- **64 题版已否决**（S–N 缺 4 道合格题）
- **48 题版勉强可行但不推荐**（S–N 仅 4 道判别性 ≥0.2）

⚠️ **标准版的三项代价，必须在页面上如实标注**：

1. 附录 A 的值是**均值差**，**不是因子载荷或区分度参数**，用它选题只是**近似**。
2. **官方计分公式的常数项（30 / 12 / 30 / 18）与 ±1 符号只在那 32 题上标定过。** 扩充后**不存在任何经验证的权重**，24 分切分点随之失效，需自定权重（建议等权 ±1）。
3. 标准版**不是官方验证过的量表**，只能定位为「**探索性长版**」，信效度未知。

**另两条需留意的事实**（来自 `research/05`）：

- **官方 32 题的极向配平不均衡**（报告统计 J–P 为 J 0 : P 8、S–N 为 S 1 : N 7）。这是官方量表本身的结构特征，解读 J/P 与 S/N 结果时应留有余地。
- 附录 A 正文声称含「95% 置信区间」，但实际 HTML 中**并不存在 CI 数据**（`&#177;` 出现 0 次）——官方文档与内容不一致，因此选型改用样本量作稳定性门槛。

### 3.2 效度证据（为什么选它）

OEJTS 官方与三家在线 MBTI 替代品的区分效度对比（效应量）：

| 量表 | I–E | S–N | F–T | J–P |
|---|---|---|---|---|
| **OEJTS** | **2.06** | 0.93 | **1.63** | **1.30** |
| HumanMetrics | 1.51 | 0.94 | 1.18 | 1.07 |
| 16Personalities | 1.40 | 0.85 | 1.12 | 1.02 |
| SimilarMinds | 0.91 | 0.65 | 0.73 | 0.95 |

官方结论原文：*"the OEJTS is a clearly superior test... 25-40% more differentiating power than the next best scales on the IE, FT, and JP dichotomies."*

**→ 产品含义**：OEJTS 在 I–E、F–T、J–P 上明显优于竞品，但 **S–N 只有 0.93、与竞品持平**。所以 **S–N 维度必须给"倾向强度 + 临界提示"，不能给死标签**（见 4.4）。

### 3.3 题库内容与官方计分公式

**32 题、双极 5 点量表**（1 = 完全是左端，3 = 一半一半，5 = 完全是右端）。

计分公式（官方原文，**带符号 + 带常数**）：

```
IE = 30 - Q3 - Q7 - Q11 + Q15 - Q19 + Q23 + Q27 - Q31
SN = 12 + Q4 + Q8 + Q12 + Q16 + Q20 - Q24 - Q28 + Q32
FT = 30 - Q2 + Q6 + Q10 - Q14 - Q18 + Q22 - Q26 - Q30
JP = 18 + Q1 + Q5 - Q9 + Q13 - Q17 + Q21 - Q25 + Q29
```

转字母（注意是 `> 24`，**不是 `≥ 24`**）：

| 条件 | 结果 |
|---|---|
| `IE > 24` | **E**，否则 **I** |
| `SN > 24` | **N**，否则 **S** |
| `FT > 24` | **T**，否则 **F** |
| `JP > 24` | **P**，否则 **J** |

分数范围 8–40，中点 24。**中点 24 归到 I / S / F / J 一侧。**

> 32 题的逐题原文（左右端陈述 + 计分方向）已完整抄录在 `research/01-题库来源.md` §A1，可直接取用。

### 3.4 ⚠️ 不要用 openjung 的计分代码

GitHub 上的 `openjung/core` 是最接近的现成实现（含中文译文），但**它的计分逻辑是错的**：

> 它把 8 道题的 1–5 原值**直接相加再判断 `> 24`**，**丢掉了官方公式的正负号和常数**。
> 已验算反例：全选 3 时，**官方判 I，它判 E**；另一组答卷**官方判 E、它判 I**——同一份答卷给出不同字母。

**结论**：可以参考它的**中文译文**和 `ConfidenceLevel / clarityIndex` 的数据结构思路，但**计分必须照 3.3 的官方公式重新实现**，并写单元测试用"全选 1 / 全选 3 / 全选 5"三组极端输入验证。

### 3.5 中文翻译

- 需要把 32 题译成自然中文（左右两端 + 选项文案）。
- 参考 `openjung` 的 zh / zh-tw 译文作为起点，但**必须逐题校对**（该仓库质量未经验证）。
- **翻译规范**：
  - 两端必须**语义对等、无褒贬**（❌「有条理 vs 邋遢」，✅「喜欢列清单 vs 凭记忆」）
  - 避免翻译腔，**读出来要像人话**
  - 例：`energetic / mellow` → 「精力充沛 / 平和沉静」，不要译成「精力旺盛的 / 圆润的」

### 3.6 许可红线（必须写进 README）

OEJTS 的 CC BY-NC-SA 4.0 有三个条件，**违反任何一个都是侵权**：

| 条件 | 我们的义务 |
|---|---|
| **BY（署名）** | 必须在页面上标注 Eric Jorgenson / Open-Source Psychometrics Project 及许可名称与链接（见第 8 章） |
| **NC（非商业）** | **一旦站上出现广告、付费、赞助、或任何引流变现，此许可立即失效。** 届时必须换成 IPIP 公有领域题库（即商业化的做法，见存档）。 |

## 4. 计分与结果

### 4.1 输出三样东西

1. **四字母类型**（如 INFP）——作为叙事入口，不是结论
2. **四维倾向强度**——主结果
3. **每个维度的清晰度等级**——本产品的差异化

### 4.2 倾向强度换算

每条公式得分 `s ∈ [8, 40]`，中点 24：

```
偏向强度 = (s - 24) / 16        // 取值范围 [-1, +1]
显示强度 = |偏向强度| × 100     // 0-100 的"倾向强度"
偏向方向 = 偏向强度 > 0 ? 正极 : 负极
```

**必须注意的表述问题**（否则误导用户）：

- ❌ 不要写「你是 68% 的外向者」——暗示存在绝对的"外向度"
- ✅ 写「**你在 I–E 维度上的外向倾向强度为 68**（0–100）」
- ⚠️ **绝对不要给"人群百分位"**——我们没有样本量，给了就是编造。

### 4.3 清晰度分级

按得分与中点的距离 `d = |s - 24|`：

| 等级 | 条件 | 标签 | 界面处理 |
|---|---|---|---|
| A | d ≥ 9 | **明显倾向** | 正常展示，作为强结论 |
| B | 5 ≤ d < 9 | 中等倾向 | 正常展示 |
| C | 2 ≤ d < 5 | 轻微倾向 | 附「倾向不强，另一侧特质你同样具备」 |
| D | d ≤ 1 | **压线** | **同时显示两个字母**，并说明「这类结果在不同时间作答可能变化，这是正常的」 |

> 【待决策】上述阈值是我给的初始建议值，上线后可根据自己和朋友的实测感受调整。

### 4.4 维度差异化提示（核心设计）

因为是给自己和朋友用，**诚实比好看重要**。四个维度必须给不同的提示语：

| 维度 | 区分效度 | 结果页提示 |
|---|---|---|
| E / I | 高（2.06） | 常规展示 |
| S / N | **低（0.93）** | **必须提示**：「这个维度在心理学测量上是出了名的难测准（各平台效应量都只有 0.9 左右），如果你的结果压线，别太当真。」 |
| F / T | 高（1.63） | 常规展示 |
| J / P | 中（1.30） | 常规展示 |

> **设计理由**：OEJTS 官方开发文档自己承认 S/N 和 J/P 是最难出题的两个维度。**主动说出这一点，比假装 32 题能精准定位你更让人信服。**

### 4.5 一致性校验（P1，可选）

参考 openjung 的 `ConfidenceLevel / clarityIndex` 思路：对每个维度的 8 道题，检查作答方向是否自洽（例如同向题是否一致偏向同一极）。不自洽时提示「你在这个维度上的回答有些矛盾，结果可能不太稳定」。

## 5. 功能需求

### F-01 落地页（P0）

- 标题 + 一句话说明
- `约 5 分钟 · 32 题 · 无需登录 · 不收集任何数据`
- **许可声明**（署名 OEJTS，见第 8 章）——放在落地页，不能只藏在页脚
- 开始按钮

### F-02 答题页（P0）

- **手机：一屏一题**，选中即自动跳下一题
- **PC：必须有独立的桌面布局**（一屏一题在宽屏上会非常空）。建议**居中卡片式**（内容限宽 ~640px 居中），或一屏 2–3 题【待决策】
- **响应式是硬要求**：PC 与手机都要能正常作答，不能只做手机版
- 双极 5 点：`完全是左边 ● ○ ○ ○ ○ 完全是右边`（两端显示端点陈述短标签）
- 进度显示「第 12 / 32 题」
- 可返回上一题修改
- **进度存 localStorage**，误关不丢
- **纯本地状态，答题过程不需要网络**
- 每 8 题插一句轻量文案，降低中段放弃率

### F-03 结果页（P0）

模块顺序（**响应式**：手机单列优先，PC 居中限宽或分栏）：

| # | 模块 | 内容 |
|---|---|---|
| 1 | 类型卡 | 四字母 + 中文类型名 + 一句核心描述 |
| 2 | 四维倾向条 | 4 条横向条：方向 + 强度 + 清晰度标签（A/B/C/D） |
| 3 | **压线提示** | 若有 C/D 级维度，**紧邻倾向条**解释（不要藏页脚） |
| 4 | S–N 特别说明 | 见 4.4 |
| 5 | 你的特质解读 | 分维度展开，每维 2–3 段 |
| 6 | 3–5 条「这说的就是我」 | **具体、可证伪**，见 6.3 |
| 7 | 优势与盲区 | 各 3 条，盲区要具体且不冒犯 |
| 8 | 成长建议 | 2–3 条可执行建议 |
| 9 | 分享按钮 | 生成图片卡片 |
| 10 | 重测入口 | 提示「建议间隔 4 周以上重测」 |
| 11 | 免责声明 + 许可署名 | 见第 8 章 |

**文案红线**：
- ❌ 「你就是……的人」「注定」「天生」
- ❌ **巴纳姆式万能描述**（这是人格测评最被诟病的点）
- ✅ 用「倾向于」「在多数情况下」「你可能更常……」
- ✅ 写「人格是连续的，类型是人为的切分」

### F-04 分享图（P0）

**目标环境：普通网页访问（PC 浏览器 + 手机浏览器）。不针对微信内置浏览器做适配。**（范围变更）

- ✅ **一键保存 / 下载人格卡片**——主要分享路径，需分环境实现：
  - **PC 浏览器**：`<a download>` 直接下载图片
  - **手机浏览器**：优先 `navigator.share`（Web Share API，唤起系统分享面板）；不可用时**降级为打开图片让用户长按保存**
  - ⚠️ **Web Share API 需要 secure context**——当前 IP + HTTP 部署下**不可用**，所以降级路径是**必须实现**的，不是可选
- ⚠️ **下载必须有用户可见的成功/失败反馈**——失败时静默无反应会被当成"坏了"（见审查 IM-2）
- 竖版卡片（1080×1920），内容：类型名 + 四维简化条 + 一句金句 + 站点二维码（可选）
- 用 **canvas 纯前端生成**，无服务器
- 卡片**不含任何个人信息**

内容：题库来源与许可、计分方法、**为什么 S–N 测不准**、致谢与参考文献。

## 6. 内容资产（**真正的工作量在这里**）

### 6.1 32 道中文题（约 0.5–1 天）

见 3.5 翻译规范。

### 6.2 16 个类型的中文文案（**最大工作量，约 2–4 天**）

每个类型需要：中文类型名、一句 tagline、分维度解读、优势 3 条、盲区 3 条、成长建议 2–3 条。

**【裁决已定】类型名：采用中文互联网通行的译名**（如 INFP=调停者、INTJ=建筑师、ENFP=竞选者）。
理由：① 短名称通常不构成著作权保护的客体；② 用户认知成本最低——这些译名已是中国用户的共同语汇。
⚠️ 同时必须保留「与任何第三方测评平台无关联」的免责表述（见第 8 章）。

**【硬要求】正文必须原创撰写**：tagline / 分维度解读 / 优势 / 盲区 / 共鸣条目 / 成长建议 —— **不得复制** 16Personalities、才储 APESK、知己MBTI 或任何平台的报告原文。

> 这才是真正的法律风险所在：**著作权保护的是表达，不是思想**。名称是短词、是共同语汇；而整段的人格描述文本属于受保护的表达。
> 因此「名称可以用通行的，正文必须自己写」是本项目在合规与用户体验之间的定线。
>
> ⚠️ **待验证**：`types.yml` 的正文原创性是 T-C 的自述，R5 明确声明**未做**与外部平台的全文雷同检测。**在以此内容定稿前必须补做**（见审查聚合）。

### 6.3 「这说的就是我」的反巴纳姆要求

这是**整个产品可信度的关键**。区别：

| ❌ 巴纳姆式（谁看了都觉得像自己） | ✅ 反巴纳姆（具体、可证伪、有人会觉得"不像"） |
|---|---|
| 「你有时会怀疑自己的决定」 | 「你在给别人建议时条理清晰，轮到自己做决定却反复推翻」 |
| 「你渴望被理解，也享受独处」 | 「群聊里你经常打完一段话又删掉，最后什么都没发」 |

**验收标准（【裁决】不做上线前试读）**：

- **上线前不组织朋友试读**，改为**上线后由真实使用自然验证**——朋友做完测评看到自己的结果页，那就是最真实、也最省事的试读。
- **保留的机器可验标准**（这类检查仍然要做）：
  1. 16 型之间的 `resonance` 不得互相复用（跨类型字符集 Jaccard 相似度 < 0.7）
  2. 同一个具体物象/场景不得出现在 ≥3 个类型（如"喉糖"只属 ISFJ）
  3. 同一模板句式不得跨 3 个以上类型复用
- ⚠️ **残留风险（需明确知晓）**：机器检查只能证明「**类型之间有区分度**」，**不能证明「读起来真的像一个人」**。后者只有真实用户能判断。
- **处理方式**：若上线后发现某个类型的描述被普遍认为"不像"，**只重写该型**，不做全量返工。

## 7. 技术方案

### 7.1 技术栈（建议）

| 层 | 选择 | 理由 |
|---|---|---|
| 框架 | **Vite + React + TypeScript** | 轻、构建快、纯静态输出 |
| 样式 | **Tailwind CSS** | 移动端快速适配 |
| 状态 | React state + localStorage | 不需要状态管理库 |
| 题库 | **TypeScript 常量文件** | 无数据库，无接口 |
| 计分 | 纯前端函数 | 零依赖，可写单元测试 |
| 分享图 | Canvas API | 无服务器 |
| 后端 | **无** | 这是核心设计 |
| 成本 | **¥0** | 静态托管免费额度 |

### 7.2 ⚠️ 不要收集数据（重要设计原则）

**不收集任何作答数据。** 理由：

1. 不收集 → **不触发《个人信息保护法》的任何义务**（无告知同意、无删除权、无出境问题、无未成年人门槛）
2. 我**没有能力和精力**去维护数据库与合规
3. 代价：永远无法做常模。**对个人站，这个代价可以接受**——我们本来就只给"倾向强度"，不给百分位。

**唯一例外（P1，可选）**：如果以后想给朋友做"对比"功能，可以做一个**纯前端的分享码**（把结果编码进 URL 参数），数据仍然不落库。

### 7.3 部署

| 方案 | 说明 | 推荐度 |
|---|---|---|
| **Cloudflare Pages** | 免费、静态、国内多数地区可访问 | ⭐ 首选 |
| Vercel | 免费，但**国内访问常不稳定** | 备选 |
| 国内轻量服务器 + 域名 | 需 ICP 备案，个人站没必要 | 不推荐 |
| **单文件 HTML** | 构建成一个自包含 HTML，微信直接传文件、双击就能用，**零托管、零备案** | ⭐ 很适合"给朋友用"的备份方案 |

**建议**：主路径用 Cloudflare Pages 发链接；同时保留单文件 HTML 构建产物，朋友访问不顺时直接发文件。

## 11. 如果将来要商业化，需要补什么

现在的**非商业**定位是 OEJTS 许可的前提。**未来一旦想加广告或收费，必须先做以下替换**（完整清单见 `docs/商业化构想-v0.1-备查.md`）：

1. **换题库**：OEJTS → IPIP 公有领域题项（IPIP 无类型学量表，需自建映射与自研题）。
2. **重写结果表述**：加上人群百分位需要**真实常模**，须先积累样本（竞品的"350 万样本"是多年积累）。
3. **补合规**：ICP 备案、公安备案、隐私政策、对齐 GB/T 45253-2025、数据出境评估。
4. **重建免责与商标策略**（商业化后商标风险显著上升）。
5. **AI 解读需备案**（《生成式人工智能服务管理暂行办法》）。

**结论**：先做个人站，验证"结果页是否真的有用、朋友是否愿意分享"。**这一步的反馈，比先做合规更有价值。**
