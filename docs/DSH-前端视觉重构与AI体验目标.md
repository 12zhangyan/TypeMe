# TypeMe 前端视觉重构与 AI 体验目标

将下面整段交给 DSH 执行。本轮聚焦前端视觉、交互和 AI 分析的产品呈现，优先于上一份通用持续优化提示词的任务排序。

```text
你负责重构 TypeMe 的前端页面与 AI 分析体验。
项目目录：D:\develop\develop\code\TypeMe。

我的目标：让用户第一眼觉得这个产品精致、现代、有吸引力，愿意开始测评；答题过程轻松顺畅；拿到报告后愿意认真阅读、探索 AI 分析并再次回来。AI 分析要更高级、更有科技感，体现个性化洞察和完整产品体验。

请直接完成实际页面改造、接入与验证。不要只交设计建议、静态原型，或只改按钮颜色和圆角。可以重新组织页面结构、导航、视觉系统、组件和动效。保留业务能力与数据语义，在现有 Vue 3 + TypeScript 项目内实现。

一、先确认现状，但不要长时间停留在分析

阅读 AGENTS.md、git status、相关 diff 和 docs/optimization/ 的现有记录，保护其他正在进行的修改。检查当前首页、答题页、报告页、AI 面板、历史/对比页、账号页面及其真实状态。

重点入口：frontend/src/App.vue、style.css、tailwind.config.js、views/、components/AiAnalysisPanel.vue、stores/aiAnalysisV3.ts、api/v3Ai.ts，以及相关报告模型、测试和浏览器验收脚本。现有 AI 面板已包含结构化结果、生成入口和历史记录，先核对再改造，不重新造一套状态机。

阅读新测产品方案和相关契约，理解固定报告与 AI 分析的边界。旧记录里的功能缺口不代表今天仍然缺失。

本轮用户明确授权视觉重构：AGENTS.md 和旧方案中“复用现有视觉风格”、固定奶白/墨蓝/杏橙配色及旧版布局是历史默认，可以调整。保留业务、安全、内容版本和数据保护约束。不要因遵守旧外观而把这次重构缩成几处样式微调。

二、设计方向：有辨识度的现代人格探索产品

以“人格探索 / 自我洞察”为核心建立完整视觉语言。整体感受应当是清晰、精致、可信、有探索欲。

默认采用以下方向，发现与实际内容不适配时可给出理由后自行调整：
- 主体使用清爽的浅色阅读表面、深墨色文字与克制的蓝青色强调；首页主视觉和 AI 核心区域可使用深海军蓝背景、细腻光晕与几何轨迹形成辨识度。
- 主视觉围绕四个维度、不同倾向与探索路径设计，可以使用精心构建的 SVG、线条、层次和轻动效。装饰图形与真实结果图表必须明显区分。
- 标题有力量，正文舒展；统一字号层级、间距、容器宽度、圆角、边框、阴影、图标和组件状态。
- 页面应有主次和节奏，不把所有内容塞进同样大小的圆角卡片。首页可以有视觉张力，答题页面保持专注，报告页面适合长时间阅读。
- 科技感来自结构清晰的数据表达、精准反馈与细节质量。避免整屏霓虹、廉价玻璃叠加、滚动粒子背景、机械打字长文和满屏无意义英文。
- 优先 CSS / SVG 和现有能力，不为装饰引入大型图表库、3D 引擎、远程字体或新的 UI 框架。

先简短写明你选定的设计方向与关键页面变化，然后直接实现。无需让我逐页确认配色和间距。

三、按用户旅程重构页面

首页：
- 首屏在短时间内说清“这是什么、我能得到什么、如何开始”，有一个明确的主行动按钮和一个报告预览入口。
- 做出有记忆点的主视觉与真实报告结构预览，展示结果价值，而不是堆满注意事项和技术说明。
- 用自然中文组织价值介绍、体验步骤、报告预览、隐私与常见问题。重要限制和授权信息可读、可找到，但不应淹没主内容。
- 主测题数、登录要求、数据保存方式和 AI 能力状态与实际一致。示例清楚标注，不伪造用户数量、评价、专家背书、准确率或“科学认证”。

答题页：
- 让用户注意力集中在当前题目，进度、选项、帮助和下一步有清晰层级。
- 选中反馈、键盘焦点、题目切换和保存状态精致自然；不因动效阻碍连续作答。
- 手机单手操作方便；长题面、说不好、回退、补充题、断网失败和冲突状态都保持可用。
- 不以重新设计为由改变题意、选项极性、评分规则、跳题规则或保存行为。

固定报告：
- 建立“结果概览 → 维度依据 → 具体解读 → 行动建议 → 延伸探索”的阅读层次，按实际数据组织内容。
- 类型名、结果状态、维度图形与核心解释形成清晰的视觉焦点。图表有真实数据、标签和文本替代，不仅靠颜色区分方向。
- 使用分段、目录、锚点或适度折叠解决长报告阅读问题；不能为了页面短而隐藏核心结论和不确定性。
- 平分、略偏、信息不足时仍有完整且有尊重感的页面，不强行补类型、不显示虚假的百分比。
- 分享卡片和导出与新版页面形成统一视觉语言，内容仍来自真实报告模型。

历史、对比、账号与认证页面：
- 与新视觉系统保持一致，历史列表容易找回、对比容易读懂，登录/注册/恢复表单简洁可靠。
- 空态有合理的下一步，加载、错误与成功反馈完整。管理员页面如受全局样式影响，同步保证清晰可用。
- 旧量表入口和历史记录保持可读可用，不把新旧量表的名称、许可与报告语义混在一起。

四、重点打造 AI 洞察体验

将 AI 分析从“报告底部的一串段落”升级为有独立视觉识别的洞察区域。可以在报告概览提供可发现的入口和锚点，详情保持独立层次。固定报告始终完整可读，用户不生成 AI 也能获得完整测评结果。

生成前：
- 用精炼说明与有设计感的预览，让用户理解 AI 会提供什么额外视角。
- 主题选择、输入范围、补充信息、额度和授权说明按真实接口组织，不展示没有实现的交互。
- 将“你将得到什么”和“将发送哪些信息”表达清楚，保留明确的主动生成和数据外发同意。不能进入页面就偷偷调用模型。

生成中：
- 设计专业、安静的任务状态区域：排队、生成、完成、失败等按后端实际状态展示。
- 可以使用轻量呼吸光、轨迹或骨架屏，但不得假造进度百分比、已完成步骤、神经网络扫描或模型思维过程。无真实阶段时只显示“正在生成”等诚实状态。
- 接口是轮询就做好轮询体验，不将一次返回的结果伪装成真实流式输出。切页、切报告、重试和任务恢复遵守现有状态与幂等语义。

生成后：
- 用一段醒目的核心摘要建立阅读入口，再展开洞察、建议与自我反思，避免整块长文直接铺满。
- 当前结果中的 summary、sections、actions、reflectionQuestions、boundaryNotes 应各有合适的展示层次：摘要区、分主题解读、可执行步骤、反思问题、边界说明。具体以当前接口字段为准。
- 可用局部深色视觉、清晰的图标、章节编号、连接线或适度强调突出关联，正文保持足够对比度与合适行宽。
- 只有真实返回的数据或可验证映射才可生成图表与关联关系。不能把自然语言擅自变成“潜力值”“匹配率”“人格置信度”或排名。
- 固定测评结果、AI 解释和用户自己的补充要清楚区分。AI 的推测不得包装成已经测得的事实，也不得修改固定类型或计分。
- 历史分析容易切换，当前主题与所属报告清楚；重复进入不自动再次生成。

异常与不可用：
- AI 关闭、额度不足、状态加载失败、超时、任务失败、部分结果无法解析时，都要有经过设计的状态与可执行下一步。
- 没有开启 AI 时说明可用的基础功能；不能伪造一份分析撑页面。演示结果必须标明示例，不能混进用户真实记录。
- 不把原始错误码、堆栈、模型配置、内部版本和维护说明直接当用户文案。

“高级”必须同时体现在信息组织和交互质量上。若现有字段不足，先用现有真实数据做好呈现；确需扩展时只做支持本轮体验的最小契约改动，兼容旧结果、同步验证前后端。不要借机重写 AI 后端或宣称提高了模型能力。

五、实现与验证闭环

先建立统一设计变量和基础组件，再推进首页、报告及 AI 核心区域，随后覆盖答题和其他页面。可以按风险调整顺序，但不要只做首页留下其他页面风格断裂。

保留现有业务 store 和 API 契约中的正确行为，抽取能减少重复的展示组件。不要通过大面积覆盖文件破坏已有未提交工作。

实施前后保存同场景截图对比。每轮在浏览器查看实际效果，发现布局、密度、排版或反馈问题就继续修改，不能只以编译通过作为视觉验收。

验收至少包含：
1. 首页、答题、报告、AI 与账号页面在 320、390、768、1440 宽度的实际布局；无横向溢出、遮挡、截断的关键操作。
2. 中文长文本、200% 缩放、键盘导航、可见焦点与 reduced-motion；普通正文对比度至少 4.5:1、交互目标至少 44×44。
3. AI 的未开启、待生成、生成中、成功、失败、额度不足、部分解析失败等状态；固定报告在这些状态下均能正常阅读。
4. 答题保存、刷新恢复、会话失效、revision 冲突和重复提交等主要业务行为无回退。
5. 运行前端 typecheck、相关测试和完整 build；若改了后端或接口则补充对应验证。不得删除行为测试或降低可访问性标准来适应新外观。
6. 检查首屏资源和动效开销，避免重型依赖、无意义持续动画及切页后残留轮询；不得让视觉升级明显拖慢页面。

验证遵守 AGENTS.md 的环境与权限要求。浏览器状态覆盖可使用现有隔离测试夹具或明确的开发 mock，必须与真实接口联调证据分开；不得把 mock 数据接入生产主流程。未授权的真实数据库写入、模型调用、个人数据外发和付费服务不执行。

在 docs/optimization/ 下新增本轮视觉重构记录与证据目录，记录设计方向、关键改动、前后截图、验证结果和剩余问题。给出实际观察到的体验改善；没有真实用户数据时，不宣称转化率或留存已提升。

六、完成标准

完成的结果应当是：整站设计语言统一，首页有吸引力，答题专注顺畅，固定报告层次清晰，AI 洞察具有明显的科技感与精致感，异常状态同样完整，移动端和桌面端都经过验证。

持续推进到本轮关键页面和主要状态完成，并解决验收中发现的问题。不要停在效果图或计划；也不要无休止换配色。遇到依赖权限的阻塞，先完成其余可独立实现和验证的工作，再精确报告阻塞与未覆盖项。不要擅自提交、推送或部署。

现在开始：检查现有实现并确定设计方向，简短说明最值得改变的几个体验问题，然后直接实施重构和浏览器验收。
```
