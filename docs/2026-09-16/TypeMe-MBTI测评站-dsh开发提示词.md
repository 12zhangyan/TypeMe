# 交给 dsh 的开发提示词

将下面代码块完整复制给 dsh，在 `D:\develop\develop\code\TypeMe` 项目中执行。文档路径相对仓库根目录。此提示词用于后续开发，本次尚未启动 dsh 或修改应用代码。

```text
你现在负责把现有 TypeMe 项目实现为“登录版十六型人格测评站”。工作目录：D:\develop\develop\code\TypeMe。

这是一项实际开发任务，请阅读下列两份方案后持续实现、验证和交付可运行结果，不要只回答架构建议或重复写计划：
1. docs/2026-09-16/TypeMe-MBTI测评站-产品方案.md
2. docs/2026-09-16/TypeMe-MBTI测评站-开发方案.md

先读项目/父目录 AGENTS.md、README.md、LICENSE 和上述两份方案，检查 git status，保护所有已有修改。存在用户新指示时以新指示为准。方案中明确变更的新测产品规则优先于旧 README/旧设计文档中的默认大五、纯本地存储、只读后端、保守阈值不输出类型等旧产品决定；权限、保密和用户数据保护规则仍适用。

目标：
- 用户希望测出 ENFP、INFJ 等四字母参考类型，阅读详细中文性格解释；首版只开放这一种测评。
- 注册登录、跨设备草稿、历史报告、账号恢复、数据导出/删除/注销完整可用。
- 题目自然、易懂，有具体生活场景，消除“机翻感”。
- DeepSeek 是用户主动选择的分析能力，基础报告和固定计分独立工作。

产品与技术决策已经给出，常规实现细节请自行落实，不要逐项征询。遇到有实质影响的新业务歧义，先继续独立部分，再集中说明选择与影响。

一、首先做出可审阅的内容和规则
1. 新建独立中文原创题库 typeme-jung48-zh-v1：48 道主测（每维 12）+16 道澄清（每维 4）。四维是 EI/SN/TF/JP。
2. 不把 IPIP 大五映射成 MBTI，不仅仅切回旧 OEJTS，不照抄官方 MBTI、16Personalities 或 OEJTS 原题后换词。逐题记录来源/创作说明、场景、两端含义、方向、帮助、审校风险。
3. 按产品方案的语言和场景规范编题。两端等值、无道德高低暗示、没有双重否定，不能把 J/P 写成勤奋/拖延，也不能把 T/F 写成理性/愚蠢或冷漠/善良。
4. 生成全部 16 型基础报告内容，每型建议 1200–1800 汉字，覆盖日常表现、可能优势、盲点、沟通关系、学习工作方式、压力观察、成长行动和相邻类型区别。避免16篇换名套同一模板。
5. 所有内容先标内测待审校。你可以做内容检查，不能伪造真人访谈或信效度验证。留下完整题目审校表供真人复核。

二、严格实现方案中的新评分契约
1. 新规则独立于旧 IPIP/OEJTS，旧包和公式保持版本隔离。
2. 统一负/正极 I/E、S/N、T/F、J/P；c=direction*(rating-3)，m=sum(c)/(2*n)。unknown 不计入 n，中立3计入 n。
3. 每维至少9/12主测数字回答，且48主测题全部被处理，才能提交；缺答与unknown分开，不能自动补3。澄清题不替代主测覆盖条件。
4. 主测 abs(m)<=0.20 的维度各追加4题，只追加一轮，最多16题，可明确跳过。最终按实际数字回答等权合并；触发题目集合由服务端确定。
5. 四维贡献和都不为0则输出规范四字母；方向较轻时状态TENTATIVE并说明，不能继续用旧门槛把整个类型隐藏。全非边界为REFERENCE，含平分为TIED。
6. 真平分不给随机类型或默认ISFJ；展示并列候选及四维解释。个人认同的类型独立存储，不覆盖问卷结果。
7. 类型校验 ^[EI][SN][TF][JP]$；例如IMFJ无效。边界判断不依赖四舍五入后的图示百分比，不宣传准确率或概率。
8. 提交后报告不可变；修改答案派生新attempt。Java后端是正式计分来源，客户端结果不可信，前后端用共用fixtures交叉验证。

三、实现登录站与存储
1. 保留 Vue3/TypeScript/Pinia/Vite + Java21/Spring Boot 单体，增补必要认证/数据库依赖；不重写为另一套框架，不引入微服务、Redis/MQ或向量库。
2. 首版用户名密码登录、可选昵称、一次性恢复码找回。恢复码只存hash、一次展示、原子消费，改密/恢复要撤销旧会话。成熟PasswordEncoder，禁止手写加密。
3. HttpOnly同源Cookie，生产Secure/SameSite，CSRF保护，登录轮换会话，限流和统一错误。不要把token放localStorage。
4. 按开发方案的表和API实现草稿、答案、不可变报告、历史与个人选择、AI任务和数据管理。MySQL迁移文件独立且有序；不能自行连接已有业务/生产库运行DDL/DML。
5. 所有资源按服务端登录用户过滤；验证账号A不能获取、覆盖、导出、删除账号B的数据或触发B的AI任务。
6. 自动保存使用revision并发控制；断网/401/409提示真实。会话到期保留本人待同步草稿，退出/换账号隔离并清理缓存；不能把未同步说成已保存。
7. 首页只保留新十六型入口；旧本地记录不删、不自动上传、不重算成新类型，提供只读兼容入口。

四、完成报告体验
1. 首屏直接看到参考类型或真实并列候选、自然中文摘要和边界提醒。中间是四维解释与详细内容，末尾是成长建议、AI入口和分享。
2. 基础报告必须足够有用，不能把所有详细内容都交给AI或要求AI成功才看得到。
3. 页面/复制文字/分享图/alt都用同一报告模型。所有维度写完整名称；暂定分享保留边界说明，平分分享不得突出一个伪造主类型。
4. 手机一屏一题，清晰的两端文字与五档选择，帮助和无法判断独立，主测与追加进度分开；覆盖320/390与1440视口。
5. 删去当前入口中失效的大五文案、机翻题面和“没有形成完整结论”的通用失败式表达，更新方法与隐私说明为真实云端存储行为。

五、接入DeepSeek
1. 只在后端调用；配置开关、base URL、key、model、超时、限额、并发与promptVersion。key来自服务端环境，不能进前端、仓库、截图或日志。
2. 先核对官方文档与当前模型。方案核验日官方示例为deepseek-flash，但模型必须可配置，不盲目使用过时别名。
3. 用 /chat/completions 的非流式JSON输出。固定系统提示词，用户近况当数据而非指令；AI解释后端结果，不判型、不改分数、不杜撰准确率、诊断或未经测量能力。
4. 用户确认发送范围后创建job，默认只发四维摘要、候选/边界、最多8个必要证据片段、主题和主动填写文字，不发账号和完整历史/原始答卷。
5. 创建接口快速返回202；后台worker+数据库任务状态/lease执行，前端轮询且可离开后返回。实现幂等、重复点击去重、每日次数、全局预算和真实usage记录。
6. 处理未配置、401/402/429/5xx、超时、空内容、非法JSON、截断、错误类型、进程重启以及报告删除后结果晚到。上游执行状态未知不盲目自动重试。基础报告始终可读。
7. 同一个输入缓存仅归当前用户。mock必须明确标识；没有真实key时仍完成适配、mock故障测试和非AI全流程，如实写明真实联调未完成。

六、验证与交付
1. 实际实现后执行与风险相称的typecheck、前后端测试、完整构建。现有前端pretest/prebuild会生成内容，检查diff并保护用户改动。
2. 覆盖16型映射、正反向、中立、unknown、有效覆盖、边界、澄清反转、真正平分；账号隔离、CSRF、会话和恢复码；草稿冲突/幂等提交；AI故障/幂等/预算/未知状态。
3. 使用隔离测试账号进行真实浏览器验收和分享导出，不访问用户个人浏览器存储，不自动填真实用户答案。记录手机与桌面证据。
4. 数据库和DeepSeek的真实集成需要明确目标与已有授权；缺少条件时继续mock/构建/内容/UI等独立任务，单独列明未完成的真实联调，不能用mock冒充生产验证。
5. 更新README、数据流和隐私说明、环境变量示例（不含秘密）、迁移/部署/回退步骤。不要未经来源核验宣布全站可商用。
6. 交付代码、完整题库与16型报告、迁移文件、AI适配与提示词、测试结果、浏览器截图、已知限制及运行命令。工作记录放docs/2026-09-16/implementation/，验收证据放docs/2026-09-16/verification/。
7. 工程完成、真人题目试测、真实MySQL验证、真实DeepSeek联调、上线部署分别报告，不能混写为“全部完成”。

当前允许在本项目内实施文件修改和本地非破坏性验证；不得擅自提交、推送、发布、操作生产数据、清除旧答卷或向外发送真实个人测评数据。需要新权限时，先完成不依赖该权限的可审阅工作，再准确说明所需操作和目标。

现在开始：简要说明将如何复用现有代码，检查工作区并读完方案，然后推进实际实现。无需先重复向我确认本提示词已经明确的产品选择。
```
