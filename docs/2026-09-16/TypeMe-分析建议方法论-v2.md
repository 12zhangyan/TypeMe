## 0. 一句话结论

v1 只会告诉你"你是 ISTJ"；v2 还能告诉你**"ISTJ 是内倾感觉主导、外倾思考辅助，
所以你和 INTJ 差在第一步，你最该补的是第四位的外倾直觉，而你觉得最难的那两步决策法步骤
正是用不上你偏好功能的那两步"** —— 并且这些都能追到《天资差异》的具体章节。

## 1. v1 的方法论是什么，它缺什么

### 1.1 v1 的现状（未改动，仍然有效）

| 层 | v1 做法 | 位置 |
|---|---|---|
| 作答 | 主测 48 题（每维 12）+ 最多 16 题补充；5 档 + 「这题我说不好」 | `jung48-questions.yml` |
| 计分 | 单题 `c = direction × (rating − 3)`；每维 `S = Σc`、`m = S / 2n` | `JungScorer.java` |
| 状态 | `REFERENCE` / `TENTATIVE` / `TIED` / `NEEDS_REVIEW` 四态；平分**不给字母** | `JungScorer.java` |
| 候选 | 按 `cost`（规则距离，**不是概率**）列出"另外也值得一起看的类型" | `JungScorer.java` |
| 解读 | 只按**四字母**取：8 段通用文案 + 3 条 `nextActions` | `type-reports-zh-v1.yml` |

v1 的两条纪律是好的，v2 全部继承：**平分不制造确定性**；**不给任何概率/准确率/百分位**。

### 1.2 三个具体缺口

v1 的四维是**互相独立**的四个开关。但《天资差异》全书的立场恰恰相反：**类型是一个动态结构**，
四个字母只是这个结构的投影。三个缺口由此而来：

**缺口一：说不出"为什么"，也说不出"你和相邻类型的差别从哪来"。**
v1 的 `neighbors` 段只能罗列"ISFJ 更先想到人，ISTJ 更先看规则"——现象清单，
没有机制。书里的机制是**主导过程 + 辅助过程**（第 1 章 1.9–1.11，印刷 p.13–17；
第 9 章逐型描述，印刷 p.78–107）。
ISTJ = 内倾感觉主导 / 外倾思考辅助；INTJ = 内倾直觉主导 / 外倾思考辅助。
两者**共用同一个辅助过程**，差别全在主导——这一句话 v1 说不出来。
（**本条已闭环**：`neighbors` 段 16 型已按机制重写，见 §6.1 与
`docs/2026-09-16/implementation/README.md` §2.4。）

**缺口二：给不出有依据的成长建议。**
v1 的 3 条 `nextActions` 是"这周就能试一次的小动作"，好用但**与你的类型结构无关**：
换个类型看，动作的针对性一样、依据一样薄。书里恰好有一整套可操作的方法：
**19.2 的三层发展要求**（印刷 p.179）、**19.3 的四步决策法**（印刷 p.182 起）、
**第 10 章 + 图表 32 的对立面互补**（印刷 p.108–114、p.111）、
**19.5–19.6 的沟通规则**（印刷 p.186）。

**缺口三：把"略偏"讲得太轻。**
v1 对 `TENTATIVE` 的表述是"这一侧只是略偏，另一侧也值得一起读"。这在四维独立的模型里没问题，
但在结构模型里**严重低估了后果**：E/I 换边会让**主导与辅助互换**（四个过程还是那四个）；
J/P 换边会让**每个位置上的过程都换成另一类**（判断↔感知，四个方向全不变）；
S/N 或 T/F 换边会让该类的两个过程互换功能。
"另一侧也值得读"和"你的主导过程会换成另一个"，不是同一件事。

## 2. v2 的分层

```
L0  作答        48 + 16 题                              （未改）
L1  四维计分     S / m / n                              （未改）
L2  四态判定     REFERENCE/TENTATIVE/TIED/NEEDS_REVIEW   （未改）
L3  过程结构     由四字母按框架规则推导主导/辅助/两个尚未偏好的过程   ★新
L4  派生建议     发展三任务 / 四步决策法 / 对立面互补 / 沟通规则      ★新
L5  呈现纪律     推导必须与免责说明同现；TIED 不推导；过程无高下      ★新
```

**L3 不引入任何新的测量**。它是四字母的函数——同一份作答换个实现跑，字母一样，结构就一样。
这一点必须在产品里说清楚，否则用户会把"推导"读成"另一个测试结果"（见 §5.1）。

## 3. L3：过程结构与推导规则

### 3.1 推导规则只有两条，都出自原书

1. **J/P 描述的是「对外部世界使用哪一种过程」**（第 1 章 1.10–1.11
   「识别具有内倾偏好的人的主要精神活动过程」「识别主要精神活动过程」，印刷 p.14–17）。
   以 J 结尾 → 对外用判断过程（T 或 F）；以 P 结尾 → 对外用感知过程（S 或 N）。
2. **主导过程的方向与类型码首字母一致**：外倾者的主导过程朝外，内倾者的主导过程朝里。
   于是**内倾者对外露出的其实是他的辅助过程**。

第 1 章的 1.9 已经先把辅助过程的两项职责讲清了（印刷 p.13）：
"辅助精神活动过程不是主要精神活动过程的对手，而是对其有用的辅助手段"，
它要为感知/判断提供平衡，也要为内倾/外倾提供平衡——这正是本文 §3.2 里
"辅助与主导一个判断一个感知、一个朝外一个朝里"那条不变量的出处。

第 2 章对此有直接例证（印刷 p.21）：

- 「内倾感觉思考判断型（ISTJ）（内倾感觉型，**偏好将思考而非情感作为辅助精神活动过程**）
  ……通常会将思考作为辅助精神活动过程来处理外部世界，所以，其方式会带有非个人的体系和秩序。」
- 「内倾直觉情感感知型（INFP）（**内倾情感型**，偏好直觉而不是将感觉作为辅助精神活动过程）
  ……其外部世界充满了冲动、项目和激情。」

作者用"将军与助手"作喻（第 1 章，印刷 p.15）：外倾者的将军出头露面，
内倾者的将军待在帐篷里决策、由助手在外挡驾；"如果人们没有意识到呆在帐篷中，
且职务远远超过助手的将军，他们会误认为助手就是掌管一切的。这是一个遗憾的错误。"

### 3.2 四个过程的形式化

> **用词约定（这里踩过坑，先立规矩）**：**「类」= 判断类 / 感知类**（T/F 是判断类，S/N 是感知类）；
> **「功能」= S / N / T / F**。下面两句一旦把「类」写成「族」，就会被读成
> "辅助 `Te` 的同族另一个功能是 `Ti`"——而正确答案是"判断类的另一个功能 `Fi`"。
> 代码里 `JungProcess.sameFamily` 的 "family" 指的是**类**。

```
outer = (J ? 判断类(T/F) : 感知类(S/N)) + e      // 对外使用的那个
inner = (J ? 感知类(S/N) : 判断类(T/F)) + i      // 朝里使用的那个
外倾者：主导 = outer，辅助 = inner
内倾者：主导 = inner，辅助 = outer
第三位 = 辅助那一**类**的「另一个功能」、方向取反     // Te 辅助 → Fi 第三
第四位 = 主导那一**类**的「另一个功能」、方向取反     // Si 主导 → Ne 第四
```

**不变量**（构造期逐个校验，写错就抛）：
主导与辅助类不同、方向相反；四个过程恰好各占 S/N/T/F 之一
（这条保证了四步决策法里"功能 → 过程"只有一个答案）。

16 型的结果表（Java 权威实现、Node 参考实现与前端 TypeScript 镜像由同一份夹具钉住）：

| 类型 | 主导 | 辅助 | 第三位 | 第四位 |
|---|---|---|---|---|
| ISTJ | Si | Te | Fi | Ne |
| ISFJ | Si | Fe | Ti | Ne |
| INFJ | Ni | Fe | Ti | Se |
| INTJ | Ni | Te | Fi | Se |
| ISTP | Ti | Se | Ni | Fe |
| ISFP | Fi | Se | Ni | Te |
| INFP | Fi | Ne | Si | Te |
| INTP | Ti | Ne | Si | Fe |
| ESTP | Se | Ti | Fe | Ni |
| ESFP | Se | Fi | Te | Ni |
| ENFP | Ne | Fi | Te | Si |
| ENTP | Ne | Ti | Fe | Si |
| ESTJ | Te | Si | Ne | Fi |
| ESFJ | Fe | Si | Ne | Ti |
| ENFJ | Fe | Ni | Se | Ti |
| ENTJ | Te | Ni | Se | Fi |

**独立旁证**（这四条不是本项目的发明，是原书自己的说法）：
第 9 章把 16 型按**主导过程**分组（9.1–9.5 的小节标题就是"内倾思考型""内倾情感型"…）；
第 2 章把 ISTP/INTP 描述为"两个内倾思考型的共同点和差异"；
第 9 章论内倾思考型时写明**第四位**（外倾情感）是它"发展最不充分的精神活动过程"
（印刷 p.84）——与"第四位 = 主导的同族另一个功能、方向取反"一致。

> **本文档同时更正一处此前的转写错误**：`output/天资差异-解读.md` 第 3 节的 16 型速览表里，
> **ISFP 与 INFP 两行的"主导/辅助"次序曾写反**（写成"内倾感觉/情感""内倾直觉/情感"）。
> 依据是第 2 章的两条例证（印刷 p.21）与第 9 章 9.5 节标题（"内倾情感型"下同时列 ISFP 与 INFP）。
> 已更正为 **ISFP = 内倾情感主导 / 外倾感觉辅助**、**INFP = 内倾情感主导 / 外倾直觉辅助**。
> 原书写得是对的，错在转写。

### 3.3 换边后果（回答缺口三）

四种换法**互不相同**，而且极易互相说反（本项目就把前两行写反过一次，见下）。

| 维度换边 | 例子 | 结构后果 | 报告怎么写 |
|---|---|---|---|
| **E/I** | ISTJ → ESTJ | **四个过程还是那四个**，但主导与辅助互换、第三位与第四位也互换 | "过程还是这四个，但主导与辅助会互换 —— 原来是内倾感觉主导，换过去就是外倾思考主导" |
| **J/P** | ISTJ → ISTP | 每个位置**方向都不变**，但**每个位置上的过程都换成另一类**（判断↔感知） | "主导仍是朝里用的，只是从内倾感觉变成内倾思考" |
| **S/N** | ISTJ → INTJ | 只有 S 与 N 那**两个位置**换功能、方向不变（主导↔第四位） | 点名哪两个位置、从什么变成什么 |
| **T/F** | ISTJ → ISFJ | 只有 T 与 F 那两个位置换功能、方向不变（辅助↔第三位） | 同上 |

**为什么必须点名换完之后的过程，而不是只说"方向整体对调"**：抽象措辞正是上一次把
E/I 与 J/P 说反、却没有任何人察觉的原因 —— 当时的测试甚至拿 `ESTJ`（那是 **E/I** 换边的结果）
去印证 J/P，断言照样全绿。现在的实现与测试都改成**先真的把那个字母换掉、重新推导一遍**，
再逐槽位比对（16 型 × 4 维 = 64 组），并且报告文案里直接写出换过去的类型码与过程名，
用户拿自己的类型一对就能自己核对。

于是 `TENTATIVE` 的表达从"另一侧也值得一起读"升级为**后果说明**——这才是用户真正需要知道的。

## 4. L4：由结构派生的建议

四块建议，每块都标出**依据**与**哪些是书里直接说的、哪些是机械推论**。

### 4.1 发展的三段任务（书里直接说的）

19.2 的三层要求（印刷 p.179），顺序**不可改**：

1. 熟练使用**主导过程**——"主宰其他 3 个过程，并且确定生活的主要目标"；
2. 熟练使用**辅助过程**——为感知型主导提供判断，或反之；
3. **学会使用两种没有得到偏好的、发展不充分的过程。**

作者用"一个屋檐下住着感觉、直觉、思考、情感 4 个人"作喻（印刷 p.179）：
主导过程"如同家庭的主人"，辅助权利仅次于他，两个发展不充分的过程会有不同意见；
**拒绝倾听不能解决问题**，应当把它们"像家庭年幼的成员那样接纳"（印刷 p.180）。

**第 3 层里的两个过程并列，报告不替它们排先后。** 理由不是我们的克制，而是原书自己撤回了时间表：
作者明确说，她早年以为"人格类型的发展是按照时间表进行的，必须在特定时期完成"，
并声明**这是不正确的**——"任何年龄的任何人都可以获得人格类型的良好发展"（印刷 p.177）。
所以报告里只保留"第四位发展得最不充分"这一条**过程之间的**次序说明，
并紧跟一句"这不是年龄表"。

### 4.2 四步决策法（书里直接说的；裁剪是本项目的推论）

19.3（印刷 p.182 起）给了一个固定顺序的四步法：**先用感觉处理事实 → 再用直觉列可能性 →
用思考算清后果 → 用情感称一称分量**。原书给每一步配了可以直接问自己的一句话，
例如第一步："在一个聪明的和无偏见的局外人看来，环境究竟是什么状况？"
作者的判语是：这样得到的决定"建立在比以前更完美的基础上"。

**本项目的加工只有一处，且是机械的**：把四步按"这一步的功能族落在你结构里的第几位"
标成 `preferred` / `unpreferred`（各两步），并把 `unpreferred` 的两步单独提出来
（`hardestSteps`）。依据是作者自己的提醒："涉及与自己完全不同类型的长处"的步骤最初是困难的，
问题重要时"可以咨询其他具有这些长处的人"。这一步之所以有价值，是因为**最难的两步恰好因人而异**：
对 ISTJ 是"列可能性 / 称分量"，对 ENFP 是"处理事实 / 算清后果"。

### 4.3 对立面的互补（书里直接说的；只覆盖 SN/TF 是原书的口径）

图表 32（印刷 p.111，第 10 章）用两份清单说明对立类型如何互相补足。本项目把它压成**一条**口径：
每个极点只写"**这一侧能提供给对面那一侧的东西**"，报告里按方向拼前缀——

- 我需要的 = 对面那一侧的 `offers` → "**你需要**偏直觉的一侧提供：……"
- 我能给的 = 我这一侧的 `offers` → "**你能提供给**偏直觉的一侧：……"

只写一份的好处是两侧口径不可能打架（早期版本两侧各写一遍，正是"你需要 X"与"你能给 X"
用了不同措辞）。**只取 SN 与 TF 两轴**，因为原书图表 32 的清单本来就只覆盖这两轴——
不替它扩展到 EI/JP。

### 4.4 沟通规则（书里直接说的；按"你自己那一侧"取一条）

第 10 章与 19.5–19.6（印刷 p.108–114、p.186）给的是**成对**的规则，本项目按用户在该维的字母
取对应那一条，四维各一条：

| 维度 | 你在负极侧（I/S/T/J） | 你在正极侧（E/N/F/P） |
|---|---|---|
| EI | 把"我需要安静一会儿"直接说出口 | 给"我还在想"加个标记，别让半成品被当成结论 |
| SN | 用你知道的事实**补充**对方的想法，而不是推翻它 | 对偏感觉的人说话的四条规矩（先讲结论、把话说完、换话题要提醒、别来回跳） |
| TF | 要提不同意见时，先把同意的部分说出来；能不说就别批评 | 尽量有条理；并且**直接说出你的感受**——对方不会自己看出来 |
| JP | 先定方向、细节留活口，并说明哪些之后还能改 | 给出时间点或阶段性结论，比"到时候再看"更让对方安心 |

## 5. L5：新增的呈现纪律

### 5.1 推导必须与免责说明同现

`dynamics.notes.frameworkCaveat` 与 `dynamics.basis` **不是装饰**：
没有它们，"按规则推的"会被读成"测出来的"。两条都要在页面上可见，且 `basis` 必须写明
「内倾/外倾在这里指这个过程主要朝里用还是朝外使用，不是性格内向或外向」——
这是对 v1 那个决定（极点标签用"偏内/偏外"而不用"内倾/外倾"）的延续与补充。

### 5.2 平分不推导

`TIED` 时 `dynamics` 与 `processPlan` **都是 `null`**。字母都没定，再推一个过程结构
就是在制造确定性——与 v1"平分不给字母"是同一条纪律的延伸。

### 5.3 四个过程没有高下

主导过程只是"用起来最省力"的那个；两个尚未偏好的过程只是"还没练过"。
**均衡不等于两边一样多，而是各有各的位置**。用户的 `unpreferred` 两步在页面上要与
`preferred` 两步同等呈现，不许写成"短板"。
尚未发展的过程也不会消失：第 9 章 9.1 把它们在压力下的表现称为**灰色区域**
（印刷 p.79），"低于该人通常的标准"即可判定——报告里用这一点解释"为什么我会突然不像自己"，
而不是据此给人下结论。

### 5.4 新增的禁用词

原有禁用词表（`准确率 / 概率 / 百分位 / 置信 / 确诊 / 命中注定 / 科学证明 / MBTI 官方 /
16Personalities / OEJTS`）不变，**追加**：`匹配率 / 适配度 / 适合度 / 职业匹配 / 恋爱配对`。
理由：这一层比四字母更容易被读成"你就适合干这个"——把推导变成判决的说法不许出现。

这五个词进的是**全局**表（`scripts/convert-jung-content.mjs` 的 `BANNED_WORDS`），
而不是只加在过程层的 `PROCESS_EXTRA_BANNED` 上，并且 `JungReportBuilder.BANNED_WORDS`
（运行期那份）用同一张表。两边不一致就会变成"构建期通过、线上运行期抛异常"——
构建期的报错会指出具体文件与字段，是更该失败的那一侧。

### 5.5 本版不引入任何群体分布数据

**v2 刻意不引入任何人群比例、职业分布或统计表。** 数据层的引用政策已经裁定，留给 v3：

- **允许**引用书中样本的构成，且**只能**作为"书中某样本的事实"陈述；
- 引用时必须**同时**标注样本、年代、以及"这是自我选择造成的分布，不是因果、不是对个人的预测"；
- **禁止**把它变成指向用户个人的比例、概率、适配度、匹配率；
- 现有禁用词护栏继续生效。

这条政策是为 v3 的统计表数据层（如图表 33 的职业类型分布、自我选择比率 SSR）准备的，本版不实现。

必须成立的具体断言（都有测试钉住）：

1. `JungTypeDynamicsTest`：16 型的过程结构逐个对上表；内倾者主导朝里；
   J 型对外用判断过程；四个过程各占 S/N/T/F 之一；手工拼的错结构当场抛异常。
2. `JungTypeDynamicsTest.agreesWithSharedFixture`：Java 推导 = 硬编码表 = 共享夹具，三者一致。
3. `frontend/src/domain/jung/dynamics.ts` 的 TS 镜像与同一份夹具的 16 行逐行一致。
4. `JungReportSchemaTest`：`report_json` 顶层字段集合与顺序含 `dynamics`、`processPlan`；
   `methodology` 含三个新键；`TIED` 时两块都是 `null`；`TENTATIVE` 的 `boundaryNotes` 非空，
   且 EI 换边的说明必须**点名换过去的类型码与主导过程**（不再断言"功能族不变"这种抽象说法，
   原因见 §3.3）。
5. `JungTypeDynamicsTest.flipEffectsMatchTheFlippedType`：16 型 × 4 维 = 64 组，
   每组都把那个字母真的换掉、重新推导，再逐槽位与 `FlipConsequence` 对拍
   （E/I 同集合且主辅互换；J/P 每槽方向不变、类全换；S/N、T/F 只动两个槽位且方向不变）。
   **这条就是为拦住"把 E/I 与 J/P 说反"而写的**——抽象断言拦不住，逐槽位对拍才拦得住。
6. `processPlan` 结构：发展序**恰好 3 段**且第 3 段并列两个过程；决策步**恰好 4 步**且
   function 顺序为 S,N,T,F；恰好两步 `preferred`；`opposites` 恰好 2 条；
   `communicationRules` 恰好 4 条；三段说明都非空。
7. 禁用词扫描：过程层文案与生成物里零命中（含 5.4 的追加词）。
8. `neighbors` 文案的机制核对（一次性脚本，在 `work/` 下，不进仓库校验链）：
   `node work/verify_neighbors.mjs` —— 16 型各四个邻居，逐段核对
   "提到的类型码正好是四个只差一个字母的邻居"、"该维度的说法与真实变化一致"、
   "段里出现的过程名不越界"。**它抓到过真问题**：初稿有 9 段的 E/I 说法里
   一个过程名都没点出来（只剩"同一套过程、主辅换了位置"这类抽象话；
   另有 3 段连"主辅换了位置"这层意思都没说清），与当年那条错误说法是同一种毛病。
