# TypeMe 登录版十六型测评站：产品方案

日期：2026-09-16。状态：供开发实施的方案；本次只编写方案，没有改造应用或上线。

配套：[开发方案](TypeMe-MBTI测评站-开发方案.md) · [交给 dsh 的开发提示词](TypeMe-MBTI测评站-dsh开发提示词.md)。

## 1. 产品目标与决定

用户希望回答容易理解的问题，得到 ENFP、INFJ 等四字母参考类型，读懂自己的性格特点，并登录保存记录、选择 DeepSeek 深度分析。用户举例中的 `imfj` 不是有效类型码；系统合法类型遵循 E/I、S/N、T/F、J/P 四个位置，输入提示应帮助纠正，但不能自行猜成某一个类型。

一句话定位：**TypeMe 是一个用中文日常情境认识自己的十六型人格测评站，完成测评后得到参考类型、详细性格报告与可选 AI 分析。**

| 决策 | 首版方案 |
|---|---|
| 测评范围 | 只开放 E/I、S/N、T/F、J/P 四维十六型测评；撤下大五新测入口 |
| 对外定位 | 十六型人格自测，说明采用 MBTI 四维偏好语言，非官方 MBTI 测验 |
| 账号 | 用户名、密码、可选昵称；登录后答题，跨设备续答及查看历史；提供一次性恢复码找回账号 |
| 题库 | 中文原创情境题初稿 48 题，每维 12 题；边界维度可追加每维 4 题，总计最多 64 题 |
| 时长 | 初步估计主测 8–12 分钟，需用真人试测数据调整，不以题量证明准确性 |
| 判型 | 固定规则计分，方向轻微时也给暂定参考类型并标注；平分时进入澄清/候选类型流程 |
| 报告 | 16 型完整基础解读 + 本次四维结果 + 边界解释 + 具体行动建议 |
| AI | 用户主动选择；服务端调用 DeepSeek，根据本次结果解释，不负责决定或改写类型 |
| 商业化 | 本轮不做付费、广告、会员、订单；新题库独立编写并记录来源，避免继续绑定旧题库 |

这里的 48 题、9/12 有效回答门槛与边界阈值都是首版设计参数，需要试测迭代；没有已验证的准确率、常模或信效度承诺。

## 2. 当前问题及改造方向

当前默认包 `ipip50-zh1` 是大五量表，`hasTypeCode=false`。它不会生成四字母类型；一个维度未达到展示门槛时，分享文案会写“没有形成完整结论”。用户发来的“高、高、低、高，低/高待观察”还丢掉了维度名。仅凭这段分享文字不能确定究竟哪一维待观察，也不能还原每一维分数。

当前 OEJTS 32 题旧版本支持四字母，但四维全部达到产品展示门槛才输出，且部分题面涉及“机器人式思考”“大声喊话”等难以直观映射到日常偏好的内容。只切换默认包，仍不能满足此次目标。

本方案改变的是测评入口、中文题库、参考类型展示、账号存储和报告体验。现有移动端答题、进度恢复、解释展开、题目回看、结果页和分享图片等交互基础可以复用。

本方案明确取代新测流程里的旧决定：默认大五、答案只存在本地、后端仅只读、四维都越过旧门槛才能给类型。旧答案、旧报告仍按旧版本解释，不能拿新规则覆盖旧记录。

## 3. 首版用户流程与页面

### 3.1 主流程

首页了解结果示例 → 注册/登录 → 测前说明与一个练习题 → 48 道主测题 → 必要时少量澄清题 → 四字母参考结果及详细报告 → 可选 DeepSeek 分析 → 我的测评中查看、复测与比较。

首页允许未登录阅读，开始测试前登录。不能等用户做完 48 题后才突然要求注册。登录成功返回原先要去的站内页面。

### 3.2 页面清单

| 页面 | 核心内容与动作 |
|---|---|
| 首页 | “了解你的性格偏好，找到更接近你的十六型人格”；说明题量、预计时长、结果示例；开始/继续测评 |
| 注册/登录/恢复 | 用户名密码；注册后展示恢复码保存提醒；登录、退出、恢复账号、修改密码 |
| 我的测评 | 继续草稿、开始新测、历史卡片、查看报告、同版本两次对比 |
| 测前说明 | 平常状态、个人偏好与工作要求的区别；一题操作演示；保存与隐私说明 |
| 答题页 | 一屏一题、两侧生活化选项、五档选择、暂不适用、短释义、上一题/下一题、答题卡 |
| 澄清页 | “这几个方面你两边都有一点，我们再看几个具体场景”；展示实际追加题数 |
| 结果页 | 四字母与中文标题、个人摘要、四维倾向、详细解读、相邻类型比较、成长建议、AI 入口 |
| AI 分析区 | 数据范围确认、选择关注主题、生成进度、失败重试、完整分析；基础报告一直可读 |
| 账号与数据 | 改昵称/密码、重新生成恢复码、导出本人数据、删除报告、注销账号 |
| 方法与隐私 | 四维含义、题库来源和版本、解释规则、数据保存范围、AI 第三方处理说明 |

不制作“即将开放”的其他测评列表、复杂管理后台、聊天大厅、交友或情侣配对。

### 3.3 答题体验

- 两侧文字与五档按钮同屏，按钮为“很像左边 / 更像左边 / 两边差不多 / 更像右边 / 很像右边”。另有“暂不适用/无法判断”，不混入中间档。
- 选后保持本题，点击下一题继续；键盘方向键选择，Enter 下一题。返回修改时可看清旧选项。
- 顶部显示主测进度，例如“18 / 48”；澄清题进入后另列“补充 1 / 4”，进度不倒退或突然改分母。
- 题目帮助只解释场景，不暴露测哪个字母，也不暗示哪侧更好。
- 保存提示区分“正在保存 / 已保存 / 未同步”。离线可继续已加载的题目；正式提交需要联网，失败保留本地待同步进度。
- 完成检查准确区分数字作答、明确无法判断、未处理。每维数字主测题不足 9 道时，引导回看；允许保存现状和退出，不强迫猜答案。
- 澄清不是无穷追问：只追加一次，每个触发维度 4 题，最多 16 题；可跳过，报告反映实际证据。

## 4. 中文题库设计

### 4.1 选择中文原创题库的理由

产品目标是自然、易懂的四维偏好探索。首版新建独立题库 `typeme-jung48-zh-v1`，不把大五答案映射为 MBTI，也不对 OEJTS 题目逐句换词后称为原创。旧 OEJTS 内容在仓库 LICENSE 中标注 CC BY-NC-SA 4.0；新题库和解释内容记录创作、来源及审校情况，避免把旧内容不明不白带入新站。

这是重新设计的非官方问卷，不能借用旧量表的验证结论。若将来要提供正式 MBTI 服务，应另行选择获得相应授权的产品路线。官方资料也将测验后的解释和个人核对视为重要过程。[官方 best-fit 说明](https://www.myersbriggs.org/unique-features-of-myers-briggs/best-fit-type/)

### 4.2 内容覆盖

| 维度 | 要观察的偏好 | 避免偷换成 |
|---|---|---|
| E / I | 互动与独处后的精力变化；边讨论边想或先想后说 | 社交能力、胆量、是否喜欢出门 |
| S / N | 先关注具体信息与经验，或联系、模式和可能性 | 智商、文化程度、有无创造力 |
| T / F | 权衡时优先分析原则一致性，或个人价值与人的处境 | 冷漠与善良、理性与不理性 |
| J / P | 提前确定安排，或保留选择与适应变化 | 勤奋与懒惰、守约与失信 |

每维至少覆盖 3 种生活场景，每类约 4 题。避免 12 题只是同一句话反复问。每维 6 题左侧对应第一极、6 题右侧对应第一极；澄清题各 2 题，减少一直点同一边造成的偏差。

### 4.3 写作规范

- 一题只有一个场景、一种主要比较。两侧都应是正常、可接受的选择。
- 题干建议 15–45 个汉字，两侧各 8–24 字，帮助 25–60 字；以可理解为先，不机械凑字数。
- 使用常见生活语言，避免双重否定、抽象人格标签、翻译腔和“总是/从不”。
- 不依赖必须上班、恋爱、养宠物、海外旅行等经历；需要特殊经历的场景必须改成多数人能理解的等价场景。
- 把“通常怎样更自然”作为问题，不问“你认为怎样才正确”。不能将现实限制当成偏好。
- 测评期间题目和帮助固定，不由 DeepSeek 现场改写或生成；修改题面必须形成新版本。

### 4.4 题面风格示例（原创草案，待试测）

以下是写作方向，不是已验证题目，也不构成完整 48 题题库。

| 维度 | 场景 | 左侧 | 右侧 |
|---|---|---|---|
| E/I | 和熟悉的人一起活动了一下午，回到家后你通常更想？ | 再找个人聊聊今天的事 | 留点时间自己安静待着 |
| E/I | 有个想法还没理清，身边有人愿意和你讨论。你更自然的做法是？ | 边说边整理思路 | 先自己想一会儿再说 |
| S/N | 开始学一种不熟悉的东西时，你通常更想先了解？ | 一个能照着做的具体例子 | 它整体如何运作、各部分有什么联系 |
| S/N | 听别人介绍一个新点子时，你最先想追问的是？ | 具体会怎么做、有哪些已有例子 | 还能延伸出哪些用途和可能 |
| T/F | 两种安排都能完成任务，但会影响不同的人。你做取舍时通常先考虑？ | 用什么标准比较，前后是否一致 | 谁会受什么影响，哪些价值需要照顾 |
| T/F | 与朋友对同一件事有分歧，准备表达自己的看法时，你通常先想清楚？ | 双方理由分别成立在哪里 | 双方各自重视什么、为什么在意 |
| J/P | 周末有几件想做的事，时间由你自己安排。你通常更舒服的状态是？ | 提前决定大致顺序和时间 | 先保留选项，到时再决定 |
| J/P | 准备做一件没有紧迫期限的事，几个方案看起来都可行。你更倾向？ | 先确定一个方案，往下推进 | 再保留几个选项，看看有没有新信息 |

T/F 等难写的比较必须重点试测，不能把两侧兼顾误当作不能回答，也不能让措辞使一侧明显更讨喜。

### 4.5 上线前审校

开发先交付完整 48 主测 + 16 澄清题草案及逐题审校表：题号、维度、两端含义、方向、场景、来源、歧义风险、修改原因。至少安排 5–8 名目标用户试做并用自己的话复述题意；这是首轮可用性访谈建议，不是统计验证。

同一题被两人独立误解其核心意思，列入必改；目标为首轮至少 90% 题目能被多数参与者正确复述。记录真实结果，不允许开发代理代填“真人审校通过”。未试测时可作为内测预览交付，内容状态写明待验证。

## 5. 结果怎么给，避免再次“白做了”

### 5.1 常见正常路径

四维主测均有至少 9 个数字回答且最终方向不为零时，直接输出四字母参考类型。**轻微偏向不再把整个类型隐藏。**

例如：“本次更接近 ENFP。你在信息获取、决策和安排方式上分别更偏 N、F、P；E/I 两边比较接近，目前略偏 E，可以一起看看 INFP 的差异。”这是报告展示示例，不是对提出需求者的实际判型。

不显示“ENFP 准确率 92%”“你有 70% 概率是 ENFP”。条形图展示本问卷相对位置或偏向程度，不能称人群百分位、心理强度或置信度。

### 5.2 澄清与边界

- 主测每维归一化偏移在 -0.20 到 +0.20 之间，触发该维固定 4 道澄清题；阈值解释见开发方案。
- 完成后若四维仍有明确正负方向，给“本次参考类型”，接近中点的字母带“倾向较轻”说明。跳过澄清也可基于主测非零方向得到暂定结果。
- 若某维真正平分，列出相邻候选及区别，例如 ENFP / INFP；不随机取一边、不用最后一题强制破平。
- 用户可以阅读后选择“目前更认同 ENFP”，显示为“我的自我选择”，与问卷结果并列保存；不能伪装成算法已经测出 ENFP。
- 多维平分时不展示毫无根据的唯一第一名；优先呈现四维解释及待核对维度，候选按规则折叠，最多可能有 16 个。
- 所有答案都中立或大量无法判断时，仍提供可阅读的四维报告、题目回看和观察建议。产品不承诺任何回答模式都必然得到唯一类型。

这个设计把“给出有用结果”和“保留真实不确定性”同时落实，不用旧版“一个维度偏弱就整份结果为空”的展示方式。

## 6. 详细报告规格

基础报告无需 AI 就必须完整。16 种类型均有独立、自然中文内容，建议每型 1,200–1,800 汉字作为首轮内容预算，分节折叠，避免一屏长文压迫。

| 模块 | 用户能获得什么 |
|---|---|
| 结果摘要 | 四字母、中文描述标题、100–180 字摘要；暂定原因就近可见 |
| 四维解释 | 每个字母是什么意思，本次偏向如何，接近中点意味着什么 |
| 日常表现 | 熟人互动、独处、学习、协作、做选择时的常见倾向，作为类型参考 |
| 可能的优势 | 3–5 个可能用得顺手的方式，给具体场景，不称实测能力 |
| 容易卡住的地方 | 3–5 个可能的盲点及提醒，不贴负面标签 |
| 沟通与关系 | 如何表达需要、理解差异与处理分歧；不做“最佳配对” |
| 学习与工作方式 | 环境和方法偏好建议，不输出必选职业、录用或晋升判断 |
| 压力下的观察 | 可能需要留意的行为和休息策略，不诊断疾病 |
| 成长行动 | 3 个一周内可尝试的小行动，可记录“适合/不适合我” |
| 相邻类型对照 | 对倾向较轻的维度，说明例如 ENFP 与 INFP 在哪一点不同 |
| 结果依据 | 回看本次答案、算法版本、测评日期；版本详细信息放展开区 |

首屏用本次真实方向和边界组成摘要；通用类型介绍明确是参考阅读。不要把同一篇人物介绍装扮成 AI 对用户逐题分析的结果。暂定类型有边界时，不能在后文又写“你一定是典型的……”。

“详细”首先体现为解释清楚、有例子、可行动。首版不生成八维功能排名、A/T 后缀、类型稀有度、恋爱匹配率或收入预测。

## 7. DeepSeek 深度分析

### 7.1 产品功能

基础报告末尾提供“结合这次回答，进一步分析”。用户选择关注主题：全面认识自己、沟通相处、学习工作方式、成长建议，可补充最多 300 字近况，也可以不填。

第一次生成时说明将把类型、四维倾向、必要的答题摘要和主动填写的文字发送给 DeepSeek。用户确认后发送；拒绝不会影响基础报告。每次补充文字都在提交前可见，不自动上传昵称、用户名、联系方式、IP、整个历史记录或原始完整答卷。

AI 输出包括：对当前倾向的解释、边界维度提醒、围绕所选主题的分析、3 条行动建议、2 个自我观察问题。建议 800–1,200 汉字。AI 不改分数、不重新判型、不自行追加量表题。

### 7.2 体验与成本

- 点击后立即显示排队/生成中，离开页面后可以从历史报告返回查看。
- 超时、服务不可用、余额不足、格式错误时明确提示，基础报告始终保留。无密钥环境禁用真实 AI 入口并说明暂不可用。
- 同一报告与同一输入重复点击只生成一份任务，不重复扣额度；刷新读取已有任务。
- 建议起始限制：每账号每日最多 2 次新的分析，失败后的主动重试额外限制每小时 3 次；站点有全局预算和紧急关闭开关。实际数值可配置。
- 不承诺费用金额或响应秒数；联调记录真实模型、输入输出用量、耗时后再调整。

DeepSeek 目前提供 Chat Completions 与 JSON 输出，可用结构化结果渲染报告；需要处理空内容和截断，不能只判断 HTTP 200。[官方 JSON 输出说明](https://api-docs.deepseek.com/guides/json_mode/)

## 8. 登录、历史与数据管理

首版采用用户名密码，减少短信、微信和邮件服务前置依赖。昵称非必填。注册完成提供一组仅展示一次的恢复码，提醒下载或抄存；恢复流程要兼顾限流、一次性使用与旧会话失效。后续若增加邮箱验证或微信登录，单独设计账号绑定，首版不假装已支持。

登录的价值是跨设备继续、保存报告和对比历史。会话到期时保留当前待同步答案，重新登录同一账号后继续。换账号时不能将上一账号的答案带给新账号。

报告提交后不可变；想修改答案时从旧报告派生一份新测评。复测比较优先支持同版本，显示哪些维度变化，并说明环境与理解差异可能影响作答；不同题库版本只并列阅读，不直接计算成长幅度。

用户可导出本人记录、删除单份报告和注销账号。首次登录不得静默上传旧浏览器记录；旧大五记录保留本地只读入口，不能转换成十六型历史报告。

## 9. 首版边界、阶段与验收

### 9.1 实施阶段

1. **内容与规则定稿**：题库草案、澄清规则、16 型报告结构、核心页面信息结构、计分样例；完成后即可审阅。
2. **账号与测评闭环**：登录、草稿保存、主测/澄清、后端计分、基础报告和历史记录。
3. **AI 与数据管理**：真实 DeepSeek 适配、任务状态、额度、同意记录、恢复/导出/删除闭环。
4. **验证与内测**：关键异常与跨账号安全验证、移动端验收、真人题目试测、部署候选包。

阶段用于控制交付顺序，不要求所有事项串行；可以独立推进的内容工作与工程工作按实际依赖安排。不以固定天数承诺整个工程，开发前根据现有基础和外部环境估算。

### 9.2 关键验收

- 首页只开放四维十六型测试，登录后能完成全流程；旧大五记录不会被抹除。
- 48 主测题与 16 澄清题无缺项，题目对普通中文用户可理解；真人试测结果如实记录。
- 完整、非平分的回答得到合法四字母参考类型及完整报告；轻微方向被标注，不隐藏整份结果。
- 平分、缺答、无法判断均有明确体验；没有默认 ENFP/ISFJ，没有伪造准确率。
- 16 型报告内容齐备，基础报告不依赖 DeepSeek，AI 故障不会变成空白结果页。
- 新设备登录可恢复已同步草稿；用户 A 无法读取或修改用户 B 的草稿、报告、AI 任务和导出。
- AI 只有确认发送后才调用；同一次生成幂等、可恢复、有限额，输出与原始类型一致。
- 注册、登录、恢复、退出、改密码、数据导出/删除/注销可用，反馈真实。
- 手机 320/390 像素与桌面 1440 像素布局可用，长题干、错误提示和分享图片不溢出。

### 9.3 上线后的观察指标

统计开始到完成的流失位置、各题“看不懂/不适用”比例、平均时长、追加题比例、平分比例、报告阅读反馈和 AI 失败率。首版从服务器业务记录得到必要汇总，不另加第三方跟踪脚本。任何“准确性提升”结论需另有研究证据，不能用用户满意或生成类型比例替代。
